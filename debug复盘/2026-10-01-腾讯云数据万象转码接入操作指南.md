# 腾讯云数据万象视频转码接入操作指南

> 日期：2026-10-01  
> 项目：能学慧吉他课堂笔记整理工具 / 播放器项目  
> 目标：把上传到 COS 的原视频自动转成 1080p / 720p，并让网站播放器可以选择清晰度。

---

## 0. 先说明：数据万象是什么

腾讯云数据万象，简称 CI，是腾讯云 COS 上的视频、图片、文档处理服务。

你现在的视频文件放在 COS 里。数据万象可以在视频上传后自动做这些事：

1. 发现有新视频上传；
2. 自动转码成 1080p；
3. 自动转码成 720p；
4. 把转码后的视频保存回 COS；
5. 调用我们后端的回调接口，告诉系统：“这个视频的 1080p / 720p 已经好了”。

网站后端收到回调后，会把数据库里的 `video_renditions` 表更新成：

```txt
source  ready       原画地址
1080p   ready       1080p 地址
720p    ready       720p 地址
```

然后播放器里就可以切换清晰度。

## 1. 当前项目已有的基础能力

项目现在已经有这些基础表和接口：

### 1.1 数据库清晰度表

表：

```txt
video_renditions
```

字段大概是：

```txt
video_id
quality
video_url
file_size
status
```

其中：

```txt
source = 原画
1080p  = 1080p 转码结果
720p   = 720p 转码结果
```

### 1.2 上传视频后会预留转码状态

上传视频后，系统会先创建：

```txt
source = ready
1080p  = processing
720p   = processing
```

也就是说，网站已经预留好了清晰度位置。

### 1.3 后端已有回调接口

接口：

```txt
POST /api/videos/transcode/callback
```

完整线上地址应该是：

```txt
https://api.nxhguitar.com/api/videos/transcode/callback
```

但是这个接口目前还需要加强安全校验和适配腾讯云 CI 的真实回调格式。

## 2. 最终要实现的流程

最终目标流程是：

```txt
管理员上传视频
↓
原视频进入 COS
↓
后端记录 source / 1080p / 720p 三档清晰度
↓
腾讯云数据万象检测到 COS 新视频
↓

↓
自动生成 720p 文件
↓

↓

↓

↓

```

## 4. 第一步：进入腾讯云数据万象

1. 打开腾讯云控制台；
2. 进入 **对象存储 COS**；
3. 找到项目正在使用的 Bucket；
4. 进入 Bucket 后，找到 **数据处理 / 数据万象 / 媒体处理** 相关入口；
5. 如果提示开通数据万象，先按提示开通。

注意：

- 数据万象通常是按量计费；
- 视频转码会产生费用；
- 建议先用一个小视频测试。

---

## 5. 第二步：创建 720p 转码模板

在数据万象媒体处理里找到 **转码模板** 或 **模板管理**。

创建一个 720p 模板。

建议参数：

```txt
模板名称：nxh-720p
封装格式：mp4
视频编码：H.264 / AVC
分辨率：1280x720
码率：建议 1500 - 2500 kbps
帧率：跟随原视频，或 25 / 30 fps
音频编码：AAC
音频码率：128 kbps
```

创建完成后，记录：

```txt
720p 模板 ID：
720p 模板名称：nxh-720p
```

## 7. 第四步：规划输出目录

建议转码输出放到单独目录，避免和原视频混在一起。

推荐目录：

```txt
transcoded/
```

推荐输出规则：

```txt
transcoded/{原视频文件名或任务ID}/720p.mp4
transcoded/{原视频文件名或任务ID}/1080p.mp4
```

更理想的是输出路径里能包含数据库的 `video_id`，例如：

```txt
transcoded/video-123/720p.mp4
transcoded/video-123/1080p.mp4
```

但数据万象能否直接拿到 `video_id`，取决于当前上传路径和工作流变量支持。

所以你配置时先记录它支持哪些变量，例如：

```txt
${InputName}
${InputPath}
${JobId}
${RunId}
```

把截图或变量列表发给我，我再帮你决定最稳的输出路径。

---

## 8. 第五步：创建工作流

进入数据万象的 **工作流** / **媒体工作流**。

创建一个工作流。

建议配置：

```txt
工作流名称：nxh-video-transcode
触发 Bucket：当前视频 Bucket
触发目录：原视频上传目录
触发文件类型：mp4 / mov / m4v，至少先选 mp4
处理动作：转码
转码模板：nxh-720p + nxh-1080p
输出 Bucket：同一个 Bucket
输出目录：transcoded/
```

注意：

- 如果触发目录配置太宽，可能历史视频或转码后视频也再次触发转码；
- 触发目录不要包含转码输出目录；
- 例如原视频在 `videos/source/`，输出放 `videos/renditions/`。

推荐最终目录结构：

```txt
videos/source/       原视频
videos/renditions/   转码后视频
covers/              封面
attachments/         附件
```

如果当前项目不是这个目录，先不要大改，先记录当前实际目录。

## 9. 第六步：配置回调地址

工作流里如果有“回调地址 / 通知地址 / 回调 URL”，填写：

```txt
https://api.nxhguitar.com/api/videos/transcode/callback
```

但是这里有一个安全问题：

当前正确的安全流程应该是：

```txt
腾讯云 CI 发回调
↓
回调里带签名或密钥
↓
后端验证签名或密钥
↓
验证通过才更新数据库
```

不能让任何人直接伪造回调。

---

## 10. 第七步：确认数据万象是否支持自定义 Header

你需要在腾讯云数据万象控制台里看：

> 回调配置是否支持自定义 Header？

如果支持，最好配置：

```txt
Header 名称：x-ci-signature
Header 值：HMAC_SHA256(rawBody, CI_CALLBACK_SECRET)
```

但大多数云产品控制台未必支持动态 HMAC Header。

所以你需要确认，并把截图发给我。

---

## 11. 如果不支持自定义 Header 怎么办

如果数据万象只能填一个回调 URL，不能自定义 Header，那么我们采用兼容方案。

回调 URL 改成：

```txt
https://api.nxhguitar.com/api/videos/transcode/callback?token=一串随机密钥
```

例如：

```txt
https://api.nxhguitar.com/api/videos/transcode/callback?token=xxxxxxxxxxxxxxxx
```

后端会改成：

```txt
没有 CI_CALLBACK_SECRET → 拒绝
有 x-ci-signature → 验 HMAC
没有 x-ci-signature，但有 token → 校验 token
都没有或错误 → 401
```

这个方案比 HMAC 弱一点，因为 token 会出现在 URL 和日志里，但比“无密钥直接通过”安全很多，也更容易和腾讯云控制台对接。

---

## 12. 第八步：生成回调密钥

在服务器上执行：

```bash
openssl rand -hex 32
```

会得到类似：

```txt
9f0e2f...一长串...
```

把它保存为：

```txt
CI_CALLBACK_SECRET
```

服务器 `.env` 里最终需要加：

```env
CI_CALLBACK_SECRET=你生成的那串密钥
```

如果有 `backend/.env`，也要同步。

### 15.3 建立 videoId 和 COS 对象的映射

如果数据万象回调里没有直接带 `videoId`，我需要用以下方式之一映射：

#### 方案 A：上传路径里包含 videoId

例如：

```txt
videos/source/video-123/original.mp4
```

回调里看到这个路径，就能知道：

```txt
videoId = 123
```

#### 方案 B：数据库记录 sourceUrl，回调用 InputObject 匹配

回调里有原视频路径：

```txt
InputObject = videos/source/xxx.mp4
```

后端查数据库：

```sql
SELECT video_id FROM video_renditions WHERE quality = 'source' AND video_url LIKE '%xxx.mp4%'
```

#### 方案 C：额外建任务映射表

如果数据万象回调只有任务 ID，那需要新增表：

```txt
transcode_jobs
```

记录：

```txt
job_id
video_id
quality
```

这个方案更规范，但需要改动更多。
