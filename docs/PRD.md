## 1. 产品定位与范围

面向吉他教室的**内部教学视频平台**。三类使用者：

- **教导主任**：上传与维护全部教学内容（曲目、知识点、资料），管理账号与班级
- **老师**：管理本班学生，查看学习记录，推送作业并填写练习要求与提交要求
- **学员 / 游客**：看视频、下载资料，学员额外能看到老师布置的作业

范围边界：

- 账号由教导主任统一创建，无公众注册或自助找回密码；Web/小程序支持本人凭旧密码改密，管理重置见 §2.7。
- 不收费、不做评论弹幕或数据看板；已支持 CI 自动生成 720p/1080p 与手动清晰度切换。
- Web 桌面优先，学生移动端由独立微信小程序承载；小程序不提供管理后台。

## 2. 角色、权限与账号

### 2.1 角色定义

| 角色   | 说明       | 存储位置                              |
| ---- | -------- | --------------------------------- |
| 游客   | 未登录访问者   | 无账号（前端 `guest.js` 控制）             |
| 学员   | 付费/在册学生  | `users` 表                         |
| 老师   | 带班教师     | `admins` 表，`role = 'teacher'`     |
| 教导主任 | 内容与账号管理者 | `admins` 表，`role = 'super_admin'` |

> 实现提示：老师与教导主任**同表不同 role**，登录后由 `role` 字段决定前端口径；学员独立在 `users` 表，登录走 `/api/user/login`。

### 2.2 权限矩阵

| 能力 / 板块                        |  游客 |  学员 |     老师    | 教导主任 |

| 曲目区 / 知识点区 / 图书馆 浏览            |  ✅  |  ✅  |     ✅     |   ✅  |
| 内容上传 / 编辑 / 删除（曲目、知识点、合集、P、资料） |  ❌  |  ❌  |     ❌     |   ✅  |
| 首页（作业 + 练习要求 + 提交要求）      |  ❌  |  ✅  |     ❌     |   ❌  |
| 我的历史作业                         |  ❌  |  ✅  |     ❌     |   ❌  |
| 学生管理                           |  ❌  |  ❌  |  ✅ 限本人班级  | ✅ 全部 |
| 布置作业 / 练习要求 / 提交要求        |  ❌  |  ❌  | ✅ 限本人班级学生 | ✅ 全部 |

前端**不渲染越权入口**，后端**每个接口独立鉴权**（前端隐藏不算安全措施）。

### 2.3 核心规则

1. **内容权与管理权分离**：老师**零内容权限**，一切内容增删改仅教导主任。
2. **老师与教导主任没有首页**：老师登录后默认进入「学生管理」；教导主任登录后默认进入「曲目区」。
3. **游客没有首页**：游客入口进入后默认落在「曲目区」，只能播放与下载。
4. **学生管理是同一个页面**：顶部两个筛选条件——**班级 + 学生**（学生可搜索）。老师进入时班级筛选**锁死为本人所带班级**（一师多班时可多选）；教导主任两个筛选均自由。选定学生后的**作业历史记录与布置作业**为同一页面内的组件；作业历史记录与学员「我的历史作业」共用同一份数据模型和记录组装规则。**历史条目对所有角色一律只读、不可点击、无跳转**（见 §4.8 / §5.10）。
5. **分班结构**：一个老师可对应多个班级（`teacher_classes` 多对多）；一个学生只属于一个班级（`users.class_id`）。
6. **内容按业务可见性共享**：游客/学员仅可访问公开内容，有效老师/教导主任按后端权限可读私密；附件独立私密，图书馆无私密（§4.10）。
7. **停用 ≠ 删除**：被停用账号仍可正常登录，只是进入受限状态（见 §2.6）。
8. **详情页不做学习进度**：无「已看 ✓」、无进度条/百分比；前置知识点也不做「未学习」标记（**此项与 design-spec v2.0 §2.4 的绿色未学习圆点冲突，以用户要求为准：本轮不实现该状态标记**）。

### 2.4 账号模型

四要素，`users` 与 `admins` 两张表字段口径一致：

| 字段              | 类型               | 说明                                       |
| --------------- | ---------------- | ---------------------------------------- |
| `username`      | text, 全局唯一       | **登录账号**（真实凭据；学员即数字账号，管理员为字母/数字/下划线） |
| `account`       | text, 全局唯一       | 兼容字段，创建/迁移时回填 `username`，不是昵称、不再作为权威登录字段 |
| `nickname`      | varchar          | 昵称，**仅界面展示**（学生列表等）                  |
| `password_hash` | text             | 密码（bcrypt）                              |
| `role`          | varchar（仅 `admins`） | 老师 / 教导主任；学员由 `users` 表隐含           |
| `status`        | varchar          | `active` / `disabled`；`users` 另有 `is_active` |
| `auth_version`  | integer          | 改密 / 重置时原子递增，旧会话随即失效                 |

规则：

- 登录方式为账号 + 密码，nickname 仅展示；当前实现 username 是登录账号，account 为兼容字段，不能把 username 当昵称重新解释。
- 表字段以 db.js 和对应路由为准，表中 account/status 为业务口径，不表示两类账号的存储与验证完全相同；users 同时有 is_active，账号均有 auth_version。
- 生产保留存量数据，字段变更先备份、隔离副本演练、人工批准再显式迁移，禁止按历史 M0 清空重建。
- **账号字段边界校验**（新建与重置密码同规则，详见 §4.9）：
  - `nickname`：必填，≤ 10 字，仅允许中文 / 英文字母 / 数字 / 下划线（禁空格与其他符号）
  - 学员账号：必填纯数字，当前服务端最多 50 位；老师/主任账号兼容字母、数字、下划线，不能按旧“全角色纯数字不限长”重构。唯一 admin 为受保护账号。
  - 新建学员密码固定 `Nxh123456`，前端只读无随机生成，后端忽略客户端 password；不追溯修改已有密码，不改变老师/主任创建密码规则。
  - 学员创建可选“暂不分班”，class_id=null，后续再分配；普通老师原有班级权限不扩大。
  - 自助新密码按服务端规则校验（当前 5~30 位）；管理重置不提供自选新密码。

### 2.5 登录与会话

- 三类身份**共用登录入口**语义：学员走 `/api/user/login`，老师/教导主任走 `/api/admin/login`；登录页按同一界面呈现，提交后由后端返回的角色决定跳转
- Web 使用 Cookie/JWT（当前 7 天），小程序使用独立 Bearer（15 天）；每次鉴权回查账号状态和 auth_version，密码变更使旧版本/缺版本会话失效。
- 登录成功后跳转规则：学员 → 首页 `/`；老师 → `/admin/users`；教导主任 → `/tracks`
- 游客入口：登录页提供「游客浏览」入口，进入后落 `/tracks`

### 2.6 停用机制

`status = 'disabled'` 的账号**仍可登录**，行为如下：

| 角色   | 表现                                                                 |
| ---- | ------------------------------------------------------------------ |
| 学员   | 仍可浏览视频、下载资料；**首页**显示提示条；**我的历史作业**页显示提示条（文案见 §8）                   |
| 老师   | 仍可登录，`/admin/users` 内容区替换为停用提示（标题 + 正文见 §8），**不可执行任何管理操作**，接口层同样拒绝 |
| 教导主任 | 可正常登录；默认收起内容管理入口（保留只读浏览），是否保留管理权由站长决定                              |

操作权限与入口：

- 停用 / 恢复**学员**：本班老师 或 教导主任
- 停用 / 删除**老师、其他教导主任**：仅教导主任
- 恢复与停用**同入口，一键切换**（`PATCH /api/admin/users/:id/status`）；账号操作统一在班级管理（§5.7）
- 停用老师后，其带班关系保留（`teacher_classes` 不清空），恢复后原样生效

> **未决差异（本轮不替产品决定）**：Web 端保留上表原只读产品需求（停用学员可登录、可浏览下载，仅显示引导文案）。小程序端已发现 `/login` 未查 `status` 即签发 token，但受保护的 `requireMiniStudent` 会回查账号状态并拒绝停用账号（403 `ACCOUNT_DISABLED`）——即小程序停用学员可登录拿 token、但在使用学生端功能时被拒。两端口径不一致，记录为**未决项**，不在本轮 PRD 同步中替产品裁决。

### 2.7 本人改密与管理重置

- Web 头像菜单、小程序“我的”提供本人改密，提交 oldPassword/newPassword；输入框各有独立显示密码按钮。
- 旧密码错误返回 400 并行内提示，不误清会话；成功后提示、清理身份/业务缓存并退出，重新登录。
- 改密与管理重置原子递增 auth_version，所有旧 Cookie/Bearer 在后续鉴权时拒绝；唯一 admin 禁止本人修改和管理重置。
- 管理重置仅 root/教导主任在班级管理中对权限范围内的其他账号操作，固定重置为 `Nxh123456`；普通老师不能替他人重置，不能把重置做成任意密码输入。
- 接口：POST `/api/user/change-password`、`/api/admin/change-password`、`/api/miniprogram/change-password`；管理重置使用 §5.7 的 reset-password 端点。
- 首次部署前显式执行 migrate-auth-version.js；不能靠启动自动改生产库，不能为升级注入账号/覆盖存量密码。

要求：

### 3.2 列表页通用规范（曲目区首页 / 知识点区首页 / 图书馆共用）

以下能力三页**共用同一套组件**，只换数据源与文案：

| 组件    | 要求                                                                                             |
| ----- | ---------------------------------------------------------------------------------------------- |
| 搜索条   | 页级唯一搜索入口，位于导航下方工具行左侧；白底 + coffee 描边 + 放大镜 icon + 输入时的「清除」按钮；**一条搜索框同时过滤本页两个区**；搜索变化时分页重置回第 1 页 |
| 排序下拉  | 选项：按更新时间倒序（默认）/ 更新时间正序 / 按首字母（zh-CN 拼音序）；**每个区独立排序**，切换后该区回到第 1 页                              |
| 卡片网格  | 每行 8 张，卡片等高；卡片内容 = 封面（1:1）+ 名称 + 更新时间；**不带任何状态角标**                                             |
| 悬停操作层 | **仅教导主任**：卡片 hover 居中显示 编辑 / 删除 / 下载 / 查看详情；删除**必须二次确认**                                       |
| 翻页器   | 「上一页 / 第 X 页 · 共 Y 页 / 下一页 / 跳转到 X 页」；**单页也常驻显示**（共 1 页时上下页禁用）                                 |

### 3.5 合集详情页 · 收录网格的教导主任操作层（2026-09-15 定稿）

**适用范围**：`/tracks/collections/[id]`（曲谱集详情）与 `/knowledge/collections/[id]`（知识点集详情）的「收录单课」网格。**仅教导主任（`super_admin`）**可见；老师/学员/游客不渲染。

**实现机制（全站唯一口径，新增页面不得另写一套）**

1. 页面调用 `fetchCurrentViewer()` 取当前身份 → `isSuperAdmin = viewer?.role === 'super_admin'`
2. `document.body.classList.toggle('dean', isSuperAdmin)`
3. 收录网格的 `ContentCard` 传 `actions`：`查看详情` / `编辑` / `删除`
4. 显隐完全交给全局 CSS：`.card .ops { display:none }` + `body.dean .card:hover .ops { display:flex }`；`ContentCard` 内部固定渲染 `<div className="ops">{actions}</div>`

| 按钮  | 跳转 / 行为                                                       |
| --- | ------------------------------------------------------------- |
| 查看详情 | 曲目 → `/tracks/[id]`；知识点 → `/knowledge/[id]`                   |
| 编辑  | 曲目 → `/admin/tracks?id=[id]`；知识点 → `/admin/knowledge?id=[id]` |
| 删除  | 打开第一层确认弹层（见下）                                                  |

**删除 = 两段确认**

- 第一层「删除确认」：正文说明**「移出本合集只解除收录关系，单课与其视频保留；彻底删除会连同全部分段与视频一并删除」**；按钮 = 取消 / **移出本合集** / **彻底删除**
- 选「彻底删除」→ 第二层「彻底删除确认」：按钮 = 取消 / **确认删除**
- 反馈用全局 toast（1.6s 自动消失）：移出成功 → 「移出成功」；彻底删除成功 → 「删除成功」
- 移出调 `PATCH /api/{tracks|knowledge}/collections/:id/{tracks|points}`（传入剩余 id 数组）；彻底删除调 `DELETE /api/{tracks|knowledge}/:id`
- 任一动作完成后重新拉取合集详情并重置到第 1 页

> ⚠️ **历史 bug（已修，勿复发）**：两个合集详情页原先**从未调用 `fetchCurrentViewer()`**，`viewer` 恒为 guest，导致 `body.dean` 不会打上、也不会传 `actions`，设计稿的悬停操作层完全不出现。任何带卡片操作层的页面都必须走上面 4 步。

## 4. 内容模型

### 4.1 三段式对象层级

```
单课（track_point / knowledge_point）   例：卡农 / 1645 和弦进行
 ├─ 封面（1:1，必填）
 ├─ 简介
 ├─ P1 ── video（复用 videos 表）
 ├─ P2 ── video
 └─ P3 ── video
合集（track_collection / knowledge_collection）  例：周杰伦专辑 / 指弹入门
 ├─ 封面（1:1，必填）
 ├─ 简介
 └─ 收录多个单课（多对多：track_collection_items / knowledge_collection_items）
```

要点：

- **P 不是独立内容**：P 依附单课存在（`track_parts` / `knowledge_parts`），本身**没有封面、没有简介页**
- **单课可同时属于多个合集**，互不影响；删除合集只删关联，不删单课
- **删除单课时**：同步删除其 P 关联的 `video` 与 COS 对象（沿用现有删除一致性链路）

### 4.2 封面规则

| 对象             |          封面          |
| -------------- | :------------------: |
| 单课（单曲目 / 单知识点） |        需要，1:1        |
| 合集（曲谱集 / 知识点集） |        需要，1:1        |
| P 分段           | **不需要**（展示时用所属单课的封面） |

- 上传单课/合集时封面**必填**（沿用现有封面必填校验）
- 推送单个 P 时，卡片展示**所属单课的封面**
- 因此 `track_parts` / `knowledge_parts` **不设 cover 字段**

### 4.3 前置关系

- 详情页「前置知识点」可选**四种对象**：单曲目、曲谱集、单知识点、知识点集
- 点击前置项跳转到对应详情页（合集类前置跳到合集详情页）
- **不做环判定**：老师在后端手动维护，出现环时按实际跳转链浏览，不做检测与提示
- 存储统一走 `prerequisites` 通用表（`object_type + object_id → prerequisite_type + prerequisite_id`），两种内容区共用
- 唯一的自校验：不允许自己指向自己（表级 CHECK 已存在）

### 4.4 object_type 枚举（**全站统一，以此表为准**）

| 值                      | 含义              | 对应表                 |
| ---------------------- | --------------- | ------------------- |
| `video`                | 旧单视频（兼容历史，不再新建） | `videos`            |
| `track_point`          | 单曲目             | `track_points`      |
| `track_collection`     | 曲谱集             | `track_collections` |
| `track_part`           | 曲目分 P           | `track_parts`       |
| `knowledge_point`      | 单知识点            | `knowledge_points`  |
| `knowledge_collection` | 知识点集            | `knowledge_collections`    |
| `knowledge_part`       | 知识点分 P          | `knowledge_parts`          |
| `library_resource`     | 图书馆资料           | `library_resources` |

> ⚠️ 命名定稿（2026-09-11 晚）：**两区命名完全对称**——曲目区 `track_point` / `track_collection`，知识点区 `knowledge_point` / `knowledge_collection`；**数据库表名同步重命名，禁止一切简写**（`kp_*` 前缀已废除，表已改名为 `knowledge_*` / `track_*` 全称）。早期用过的 `track` / `collection` / `kp_collection` / `kp_part` 全部作废。前后端代码已按本表完成重命名。新增接口前先核对此表。**存量生产库不再清空重建**（见 §2.4 / §9 / 根 README）；历史文档中的「清空重建」仅指早期 M0 测试环境初始化，不可对生产重做。

### 4.5 附件与资料

两类不同的东西，不要混：

| 类型    | 归属              | 表                                                                         | 说明                            |
| ----- | --------------- | ------------------------------------------------------------------------- | ----------------------------- |
| 内容附件  | 挂在单课/合集下，随详情页展示 | `content_attachments`（object_type + object_id）；旧 `video_attachments` 保留兼容 | PDF / GP / MP3 / PNG 等，逐个下载   |
| 图书馆资料 | 独立资料库，可被内容关联    | `library_resources` + `library_resource_links`                            | 有独立浏览页与上传页；详情页右下「关联图书馆」展示关联状态 |

**合集关联图书馆资料（新增规则）：**

- 合集支持关联一个或多个图书馆资料；曲目集使用 `object_type = track_collection`，知识点集使用 `object_type = knowledge_collection`。
- **不在 `track_collections` / `knowledge_collections` 表中新增单个 `library_id` 字段**；合集关联记录统一写入已有的 `library_resource_links` 多对多表。
- 合集关联属于合集自身的直接关联。合集内单课/单知识点通过所属合集获得**继承关联**，不复制单课关联记录。
- 单课/单知识点详情页及编辑页的图书馆资料区域必须**置顶展示**，展示结果为：自身直接关联资料 + 所属合集继承资料，按资料 ID 去重。
- 继承资料在单课/单知识点编辑页中以灰显状态展示，禁止删除；需要修改时必须进入对应合集编辑。
- 同一资料既被单课/单知识点直接关联、又被所属合集关联时只展示一份，并标注来源为「直接关联 + 来自合集」。
- 单课/单知识点移出合集后，仅解除该合集带来的继承关联；其自身直接关联继续保留。

### 4.6 P 命名与展示规范（布置作业搜索依赖）

**背景**：布置作业要能搜到并精准选中某个 P（如卡农里的「基本功练习」）。P 名单独看（「基本功练习」）无法知道属于哪首曲子，因此**所有跨上下文的 P 展示与搜索场景，一律拼接父级名**：

```
显示名 = 单课名-P名        例：卡农-基本功练习
                            1645 和弦进行-击弦练习
```

- **存储**：`track_parts` / `knowledge_parts` 的 `name` 只存 P 名本身（如「基本功练习」），**不存拼接结果**；拼接在展示层做
- **必须拼接的场景**（否则 P 名有歧义）：
  1. 布置作业的推送对象搜索结果（§5.8）
  2. 学员首页 / 历史作业的**单 P 作业卡片标题**
  3. 老师删除/取消作业时的确认提示
- **不拼接的场景**（上下文已有父级）：
  1. 单课详情页右侧 P 播放列表（已在卡农页面内，只写「基本功练习」）
  2. 新建/编辑单课时的 P 管理行
- 分隔符固定半角 `-`；P 名与单课名之间不再加空格
- 搜索匹配规则：搜「卡农」能命中其所有 P；搜「基本功练习」也能命中，结果里显示「卡农-基本功练习」

### 4.7 视频清晰度（自动转码 + 多档播放）

**方案定稿：教导主任只上传原画文件，服务端自动转码出 1080p / 720p，播放器手动切换档位。**

- **档位枚举（固定三种，全站统一）**：

| quality 值 | 含义       | 来源                                   |
| ---------- | ---------- | ------------------------------------ |
| `source`   | 原画         | 上传时的原始文件，**必传，上传完成即可播**    |
| `1080p`    | 高清 1080p | **服务端自动转码生成**，默认播放档        |
| `720p`     | 流畅 720p  | **服务端自动转码生成**                  |

- **数据模型**：表 `video_renditions`（`video_id → videos.id` ON DELETE CASCADE、`quality`、`video_url`、`file_size`、`status`，`UNIQUE(video_id, quality)`）；`status ∈ ready / processing / failed`；`videos.video_url` 保留为原画档，上传完成即写入 `source` 档，`ready`
- **转码实现（定稿：用腾讯云数据万象 CI，不自建转码）**：
  - COS 本身不带转码；**开通数据万象（Cloud Infinite）并绑定存储桶**后即可用其媒体处理能力（付费服务，有少量免费额度，超出按转码时长计费）
  - 在 CI 控制台建 **两条数据工作流，分别绑定 `tracks/`（曲目区 P 视频）与 `knowledge/`（知识点区 P 视频）输入路径**。两区 P 视频共用同一回调入口，靠回调里的源文件 key 前缀（`tracks/...` / `knowledge/...`）区分归属
  - **产物与源同目录**：转码输出落在源文件所在目录，文件名为 `${InputName}-720p.mp4` / `${InputName}-1080p.mp4`（即 `${InputPath}` 同目录下的 `${InputName}-720p/-1080p.mp4`）。**不是**旧稿写的 `videos/{id}/{quality}/`；旧 `transcoded/` 仅作历史兼容
  - 后端只做**胶水**：接收 CI 工作流完成回调 `POST /api/videos/transcode/callback`，一次性聚合同一工作流实例里的 720p / 1080p 结果，把对应 rendition 置 `ready` / `failed`，**无需自写 ffmpeg**
  - **回调鉴权与登录无关**：回调 URL 必须带 `?token=`，服务端用 `CI_CALLBACK_SECRET` 校验（也接受 CI 签名头）。**未配置 `CI_CALLBACK_SECRET` 时回调一律返回 503**；校验失败返回 401；这是回调专用密钥校验，**不是登录鉴权、不看用户会话**
  - **服务状态与转码解耦**：CI 不可用 / 未开通 / 回调拒绝时，系统照常工作，只是没有转码档（原画仍可播，前提见下）
- **播放器交互**（详情页通用模板 §3.3）：
  - **Web 默认播放 1080p，档位菜单只列 `ready` 的档位**，当前档高亮；1080p 未就绪（processing/failed）时回退到已就绪档，再退原画
  - **小程序默认优先 `720p`，其次 `source`，再取其他可用档**；`1080p` 若在后端返回的就绪档位中，也可显示与选择，不额外限制为仅两档
  - 切换档位**保留 currentTime 与播放状态**，不重新加载页面
- **播放地址与回退**：
  - 各档播放地址**优先用普通 CDN 域名**，取不到时**回退到同档 COS 原始外网地址**（同一档位，不跨档）
  - **原画可播的前提**：有可用的源地址且对象实际存在、可读。仅媒体网络错误或源对象不可读不等于作业目标 private/missing，不能据此把作业卡改成权限失效灰框；作业状态以目标查询/导航复核为准（§4.8）
- **规则与边界**：
  - 转码产物为渐进式 MP4，**不做 HLS/DASH 码率自适应**，切换即换文件地址
  - 删除 video 时 renditions 级联删除，COS 对象（含各档产物）沿用现有删除一致性链路逐一清理
  - 转码是尽力而为的增强功能：**转码失败或 CI 未开通不阻塞上传与播放**（原画存在且可读即可播）
  - 附件、封面与清晰度无关
  - **运维前置（控制台操作，非代码）**：① 开通数据万象并绑定存储桶；② 建 1080p/720p 转码模板；③ 分别建绑定 `tracks/`、`knowledge/` 的两条工作流，产物按 `${InputName}-720p/-1080p.mp4` 落到源目录；④ 配置业务回调 URL（带 token），并在服务端配置 `CI_CALLBACK_SECRET`

### 4.8 内容删除、作业稳定关联与历史快照（现行规则）

- 内容本体删除沿用现有一致性链路及二次确认，无内容回收站；普通内容列表移除对象及失效关联。**作业记录例外**：保留稳定目标 ID 和布置时快照，不能级联删掉作业历史或今日占位。
- 作业身份为 object_type + object_id；分 P 使用真实 part_id，兼容旧记录 COALESCE(part_id, object_id)。P 序号、名称和 URL 均不是身份，禁止按标题匹配回填。
- 今日作业显示当前目标标题、封面、P 序号：P2 移到 P3 后应显示/定位当前 P3；课程/合集改名或换封面不破坏关联。
- private/missing 在今日原位保留灰框，标题精确“此资料已经被老师更改”，不下发封面或导航；点击无响应，无 Toast/弹窗/跳转。全部失效仍保留占位与该批练习/提交要求，不当作从未布置。
- 原可用项点击实时复核 navigation 端点，仅 available 可跳转；失败资格静默转灰。Web focus/visibilitychange、小程序 onShow 重新查询，恢复公开后自动恢复。
- 老师回填使用最新未删除批次接口 `/api/admin/users/:userId/assignments/latest`，过滤当前私密/删除目标，按稳定 ID 勾选；全失效仍回填该批要求，不退回旧批次。切换学员/乱序响应须防竞态。
- 历史只读布置时标题快照，优先 assigned_object_title，再 assigned_video_title，均无时“已删除内容”；目标私密/删除/改名不改历史标题，所有角色历史条目均不可跳转、无私密 Toast。
- 同一次推送按 operation_id 聚合，历史时间倒序，不按日期覆盖；要求原文与换行保留，长文在栏目内滚动。
- 删除操作保留追溯日志；不新增观看时长、学习进度统计。

### 4.9 表单与文件边界校验（2026-09-13 定稿，**所有写接口必须落地**）

**执行原则（适用于全站所有校验）：**

1. **后端为权威**：每条规则在对应接口独立校验；前端 `maxlength` + 提交前校验只做体验层，**不能相信前端上报的任何数据**
2. **文件大小必须后端复核**：直传场景前端选择即拦，后端在 `upload-url` 签发与 complete 登记两处再次校验；complete 时以存储侧 **HeadObject 拿到的实际大小为准**（`storage.js` 已有该能力），超限拒绝并清理已传对象
3. 字数按**字符数**计（中英文均计 1），trim 后判空；大小单位 1MB = 1024×1024 字节
4. 错误提示逐字友好：「请填写 XX」「XX 不能超过 N 字」「XX 不能超过 N MB」

**单课（单曲目 `track_point` / 单知识点 `knowledge_point`）：**

| 字段 | 规则 |
| ---- | ---- |
| 标题 | 必填，≤ 80 字 |
| 简介 | 选填，≤ 800 字 |
| 封面 | 必填，1:1，≤ 10MB，仅 jpg / png / webp |
| 分 P | **新建时至少 1 个 P**；编辑/删 P 不允许删到最后 0 个 |
| P 名 | **必填**，≤ 50 字 |
| P 视频 | 每个 ≤ **2GB**，仅 mp4 / mov |
| 附件 | 每个 ≤ 100MB；**格式与数量不设限** |

**合集（曲谱集 / 知识点集）：**

| 字段 | 规则 |
| ---- | ---- |
| 标题 | 必填，≤ 80 字 |
| 简介 | 选填，≤ 800 字 |
| 封面 | 必填，1:1，≤ 10MB，仅 jpg / png / webp |
| 收录内容 | **允许为空**（0 个单课也可保存） |

**图书馆资料（`library_resource`）：**

| 字段 | 规则 |
| ---- | ---- |
| 标题 | 必填，≤ 80 字 |
| 简介 | 选填，≤ 800 字（与单课统一口径） |
| 封面 | 必填，≤ 10MB，仅 jpg / png / webp |
| 文件 | ≤ 500MB，格式不设限 |

**账号（学员 / 老师 / 教导主任）：** 见 §2.4——`username` 为登录账号、`nickname` 仅展示、`account` 兼容；昵称 ≤ 10 字且仅中文/字母/数字/下划线。学员登录账号必填纯数字、服务端最多 50 位；老师/主任账号允许字母、数字、下划线。密码 5~30 位。唯一 admin 为受保护账号。

**已有规则保持不动：** 班级名 ≤ 100 字、练习要求 ≤ 1000 字、提交要求 ≤ 1000 字、删除原因 ≤ 200 字、单次推送 ≤ 5 个对象（见 §5.8）。旧「留言」字段及兼容接口仅保留历史数据读取，不作为新页面输入。

**写接口校验现状**：以上规则为全站统一口径，后端在对应写接口独立校验、前端只做体验层。账号边界（学员账号纯数字 ≤50 位、管理账号字母数字下划线、昵称规则、密码 5~30、新建学员固定 `Nxh123456`）见 §2.4 / §4.9；新建学员前端只读密码、后端忽略客户端 `password`、可 `class_id=null`，不追溯已有密码、不改变老师/主任创建规则。

### 4.10 业务可见性（public / private，2026-11-18 定稿）

**含义**：公开 `public` = 学生与游客可访问；私密 `private` = 仅有效老师/教导主任可读。**这是业务可见性，不是文件加密**——私密只挡未授权接口与前端入口，不加密 COS 文件。

**派生规则（自下而上）**：
- P（`track_parts` / `knowledge_parts`）自身带 `visibility`，是可见性的最小单位
- 单课（track_point / knowledge_point）的可见性由其 P 派生：**只要有 1 个公开 P 即为 public**，全部 P 私密才是 private
- 合集（track_collection / knowledge_collection）再由其收录单课派生：**只要有 1 个公开课即为 public**，全部私密才是 private
- 合集的派生 visibility 是迁移时按成员计算、落库存储的列（见 §6 八表），不是每次请求现算

**八表 visibility（以 `visibility-schema.js` 为准，含两个合集表）**：
- 带 `visibility` 列的 8 张表：`track_points`、`knowledge_points`、`track_parts`、`knowledge_parts`、`content_attachments`、`video_attachments`、`track_collections`、`knowledge_collections`
- **附件独立可见性**：`content_attachments` / `video_attachments` 各自带 `visibility`，可单独设为私密，不随父内容联动
- **图书馆无私密**：`library_resources` 没有 `visibility` 列，全部资料对所有角色公开
- 启动只做存在性门禁；存量库升级须在**离线副本上演练**后显式执行 `migrate-content-visibility.js --apply`（见 §2.4 / 根 README），不得靠启动自动回填生产库

**读取权限**：
- 学生 / 游客：只能读 `public`；私密目标一律按不存在处理（列表过滤、详情拒绝）
- 有效老师 / 教导主任（`status = active`）：可按权限读 `private`；账号被停用后其私密读取资格随之失效
- **学生侧前置隐藏**：详情页「前置知识点」中的私密对象对学生/游客不可见（隐藏该项），不对未授权者泄露标题；老师/主任可见

**作业与可见性的交互**:
- **私密内容不能作为新作业布置**：布置接口过滤掉当前 private / 已删除目标，禁止新引用
- **已布置作业的前置可改私密**：内容后来被改为 private 时，**不撤销已有作业记录、不返回 409 引用冲突**（作业按稳定 ID + 布置时快照保留，见 §4.8）；只是今日作业该条转灰、学生侧不可点击
- 恢复公开后，下一次查询自动恢复可点（§4.8 navigation 复核）

**已知限制（不再承诺）**:
- **非文件加密**：Type A（文件级加密方案）**已移除**，私密无法通过加密文件本身实现
- **已知直链不可追回**：一旦内容曾公开，其 CDN / COS 直链可能已被转发或缓存；改私密只能撤销后续授权与新增访问，**无法追回已扩散的直链**，也不承诺让旧直链立即全网失效。改私密/删最后公开 P 时记录待撤销 key（`visibility_revocations`），由账号所有者在控制台处理 CDN 刷新与 COS 匿名读回收，代码不自动改写桶策略

#### 5.1.5 规则与边界

- 一个曲目可进入多个曲谱集；删除曲谱集**不得**删除曲目本身
- 删除曲目必须走现有删除一致性链路（**先删 COS 对象再删库记录**），禁止只删库
- P 的序号 `part_no` 在同一曲目内唯一（表级 UNIQUE），调整顺序时需避免中间态冲突
- 合集关联图书馆资料后，所有收录曲目详情页的「关联图书馆」区域置顶展示该资料；单曲不需要重复关联
- 单曲编辑页的关联资料区域置顶展示：单曲直接关联可编辑；来自合集的继承关联必须灰显并禁止删除，提示前往对应合集编辑
- 单曲后来加入已关联资料的合集时自动继承；从合集移除时仅解除该合集继承，单曲自身直接关联继续保留；仍属于其他已关联合集时继续继承
- 单曲详情页展示单曲直接关联与所属合集继承关联的并集，按资料 ID 去重并标注来源；同一资料两种来源同时存在时显示「直接关联 + 来自合集」
- 详情页不记录任何播放状态，**不新增进度表**

#### 5.1.6 验收标准

1. 首页上下两区正确显示；一条搜索框同时命中曲目名与曲谱集名；两区可独立排序，默认更新时间倒序
2. 点曲目进详情页，P 列表可切换播放；从曲谱集内点曲目同样进入
3. 同一曲目出现在多个曲谱集中互不影响；删除曲谱集后曲目仍在
4. 详情页右列三盒齐备；P 列表无进度条、无已看标记
5. 封面 1:1；P 无封面上传入口
6. 老师看不到任何新建/编辑/删除按钮；直接调写接口返回无权限
7. 视觉与 `tracks-home.html` / `track-point-detail.html` 逐块一致
8. **点曲谱集卡片进的是曲谱集详情页**（不是直接进某首曲目）；集内卡片点击才进单曲目详情
9. 教导主任在曲谱集详情悬停集内曲目卡片可见 查看详情/编辑/删除；删除两段确认，选「移出本合集」后卡片消失且曲目仍能单独搜到，选「彻底删除」后曲目连同视频一并清除
