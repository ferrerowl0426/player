# 2026-09-20 服务器部署问题复盘

## 背景

本次是在服务器 `/root/player` 目录部署播放器项目，使用 Docker Compose + 腾讯云 COS：

- 前端：Next.js，容器服务端口后续确认监听 `3001`
- 后端：Node/Express，容器服务端口 `3000`
- 数据库：PostgreSQL，宿主机映射 `15432`
- 对象存储：腾讯云 COS，不使用本地 MinIO
- 域名：
  - 主站：`nxhguitar.com`
  - www：`www.nxhguitar.com`，最终配置为 301 跳转主站
  - API：`api.nxhguitar.com`
- 服务器公网 IP：`150.158.122.193`

部署目标是从停止旧容器、清数据库、清 COS、释放端口开始，重新建表、导入数据并通过域名访问。

## 最终推荐架构

### DNS

三条 A 记录都指向服务器公网 IP：

| 主机记录 | 类型 | 记录值 |
|---|---|---|
| `@` | A | `150.158.122.193` |
| `www` | A | `150.158.122.193` |
| `api` | A | `150.158.122.193` |

### Nginx 反向代理

推荐统一主域名，避免 `www` 和非 `www` 同时承载业务导致 CORS、登录态、localStorage 混乱：

```nginx
server {
    listen 80;
    server_name www.nxhguitar.com;
    return 301 http://nxhguitar.com$request_uri;
}

server {
    listen 80;
    server_name nxhguitar.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

server {
    listen 80;
    server_name api.nxhguitar.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### `.env` 域名配置

```env
FRONTEND_URL=http://nxhguitar.com
NEXT_PUBLIC_API_BASE_URL=http://api.nxhguitar.com/api
```

注意：`NEXT_PUBLIC_API_BASE_URL` 是前端构建时写入的，修改后必须重建 frontend。

## 问题 1：`seed.mjs` 缺少 `PUBLIC_BUCKET_BASE_URL`

### 现象

执行：

```bash
cd /root/player/test-data
node seed.mjs
```

报错提示缺少：

```txt
PUBLIC_BUCKET_BASE_URL
```

### 原因

`test-data/seed.mjs` 并不是读取 `/root/player/test-data/.env`，而是通过：

```js
import { config } from '../backend/src/config.js';
```

间接读取后端配置。后端 `config.js` 固定读取的是：

```txt
/root/player/backend/.env
```

所以只把根目录 `.env` 复制到 `test-data/.env` 不生效。

### 处理方式

把根目录配置同步到后端目录：

```bash
cp /root/player/.env /root/player/backend/.env
```

确认：

```bash
grep -i PUBLIC_BUCKET_BASE_URL /root/player/backend/.env
```

并确保宿主机运行 seed 时数据库地址为：

```env
DATABASE_URL=postgresql://postgres:postgres@localhost:15432/video_player
```

不要写成容器网络地址：

```env
DATABASE_URL=postgresql://postgres:postgres@postgres:5432/video_player
```

## 问题 3：后端健康检查打到 Next.js 前端 404

### 现象

执行：

```bash
curl http://localhost:3000/api/health
```

返回 Next.js 404 HTML，页面里有 `__next_static__`。

### 原因

Docker 端口映射写反/写错，前端占用了宿主机 3000，后端没有暴露到 3000。

错误配置曾类似：

```yaml
backend:
  ports:
    - "3001:3001"

frontend:
  ports:
    - "3000:3000"
```

### 处理方式

后端应映射：

```yaml
backend:
  ports:
    - "3000:3000"
```

前端端口需要结合容器实际监听端口，最终发现当前前端容器监听 `3001`，所以应映射：

```yaml
frontend:
  ports:
    - "3001:3001"
```

修改后重建：

```bash
cd /root/player
docker compose -p video_player -f docker-compose.yml up -d --build --force-recreate backend frontend
```

## 问题 4：3000 / 3001 端口反复占用

### 现象

启动容器时报：

```txt
failed to bind host port 0.0.0.0:3000/tcp: address already in use
```

或：

```txt
Bind for 0.0.0.0:3001 failed: port is already allocated
```

### 排查命令

查 Docker 端口占用：

```bash
docker ps --filter publish=3000 --format "table {{.ID}}\t{{.Names}}\t{{.Ports}}"
docker ps --filter publish=3001 --format "table {{.ID}}\t{{.Names}}\t{{.Ports}}"
```

查系统监听：

```bash
sudo lsof -i :3000
sudo lsof -i :3001
sudo ss -tnlp | grep ':3000'
sudo ss -tnlp | grep ':3001'
```

### 具体原因

1. 旧的 `video_player_backend` 曾以旧映射占用 `3001->3000`。
2. 宿主机上有一个 `next-server` 进程占用 3000，且被进程管理器反复拉起。
3. Docker 可能存在 `docker-proxy` 残留。

### 处理方式

删除旧容器：

```bash
docker rm -f video_player_backend video_player_frontend
```

如果是 Docker 网络/代理残留，先不要删数据库卷，执行：

```bash
cd /root/player
docker compose -p video_player -f docker-compose.yml down --remove-orphans
docker network prune -f
```

如果是宿主机 `next-server` 占用 3000，先找到 PID：

```bash
sudo ss -tnlp | grep ':3000'
```

再停止背后的守护方式，优先查：

```bash
pm2 list
systemctl list-units --type=service --state=running | grep -Ei "node|next|player|frontend"
ps -fp <PID>
```

不要只反复 kill 子进程，否则会被自动拉起。

### 现象

```bash

```

返回：

```txt

```

### 原因

前端容器日志显示 Next 监听：

### 处理方式

修改为：

```yaml
frontend:
  ports:
    - "3001:3001"
```

然后：

```bash
docker compose -p video_player -f docker-compose.yml up -d --build --force-recreate frontend
```

验证：

```bash
docker ps --format "table {{.Names}}\t{{.Ports}}"
curl -I http://localhost:3001
```

## 问题 6：域名解析后仍不能无端口访问

### 现象

DNS 已经解析到服务器 IP，但直接访问 `http://nxhguitar.com` 还不能进入项目。

### 原因

DNS 只负责把域名解析到 IP，不能指定端口。项目实际运行在：

- 前端：`3001`
- 后端：`3000`

要无端口访问，需要 Nginx 反代 80 到对应端口。

### 处理方式

创建 Nginx 配置：

```bash
sudo nano /etc/nginx/sites-available/nxhguitar.com
```

启用：

```bash
sudo ln -s /etc/nginx/sites-available/nxhguitar.com /etc/nginx/sites-enabled/nxhguitar.com
sudo nginx -t
sudo systemctl reload nginx
```

如果 Nginx 未启动：

```bash
sudo systemctl start nginx
sudo systemctl enable nginx
```

## 问题 7：Nginx 配置正确但无法启动，80 被占用

### 现象

```bash
sudo systemctl start nginx
```

失败，日志：

```txt
bind() to 0.0.0.0:80 failed (98: Address already in use)
```

### 原因

80 端口已有 nginx 进程占用，但不受当前 systemd nginx.service 正常管理，导致 reload/start 失败。

### 排查

```bash
sudo ss -tnlp | grep ':80'
```

看到已有：

```txt
users:(("nginx",pid=...))
```

### 处理方式

`nginx -s quit` 因缺少 `/run/nginx.pid` 失败后，用端口方式杀掉旧 nginx：

```bash
sudo fuser -k 80/tcp
sudo ss -tnlp | grep ':80'
sudo systemctl start nginx
sudo systemctl status nginx --no-pager
```

确认：

```txt
Active: active (running)
```

## 问题 8：`www` 加上后后端访问失败

### 现象

`nxhguitar.com` 正常，`www.nxhguitar.com` 访问业务时后端失败。

### 原因

`nxhguitar.com` 和 `www.nxhguitar.com` 是两个不同 Origin。后端 CORS / 前端环境变量通常只配置了：

```txt
http://nxhguitar.com
```

如果 `www` 也直接承载业务，会导致：

- CORS 来源不一致
- 登录态 / localStorage 分裂
- API 回跳地址混乱

### 处理方式

不要让 `www` 直接跑业务，统一跳转到主域名：

```nginx
server {
    listen 80;
    server_name www.nxhguitar.com;
    return 301 http://nxhguitar.com$request_uri;
}
```

验证：

```bash
curl -I http://www.nxhguitar.com
```

应返回：

```txt
HTTP/1.1 301 Moved Permanently
Location: http://nxhguitar.com/
```

## 复盘结论

1. 部署前必须先明确容器内部监听端口，不要只凭常规 Next.js 默认端口判断。
2. DNS 只解析 IP，不处理端口；正式域名访问必须配反向代理。
3. `NEXT_PUBLIC_API_BASE_URL` 是构建时变量，改 `.env` 后必须重建前端。
4. `www` 和非 `www` 是不同 Origin，建议统一主域名，`www` 只做 301 跳转。
5. COS CORS 需要随着前端 Origin 变化同步更新；从 IP/端口切到域名后必须放行新域名。
6. seed 脚本读取后端配置，排查 `.env` 时不能只看根目录，还要关注 `/root/player/backend/.env`。
7. 端口冲突要区分 Docker 容器、docker-proxy 残留、宿主机 Node/Next 进程、systemd/pm2 自动拉起。
8. Nginx 启动失败时先看 `nginx -t` 和 `systemctl status`，语法正确但启动失败通常是 80 端口被占。

# 2026-09-29 补充：HTTP/HTTPS 域名部署标准流程与排障手册

## 一、最终生产访问口径

本项目最终推荐只保留一个业务主入口：

```txt
https://nxhguitar.com
```

API 入口：

```txt
https://api.nxhguitar.com/api
```

其余入口只做跳转，不直接承载业务：

```txt
http://nxhguitar.com        -> https://nxhguitar.com
http://www.nxhguitar.com    -> https://nxhguitar.com
https://www.nxhguitar.com   -> https://nxhguitar.com
```

原因：`http` / `https` / `www` / 非 `www` 对浏览器来说是不同 Origin。如果多个入口同时直接跑业务，会造成登录态、Cookie、CORS、localStorage、前端 API 地址混乱。

## 三、完整部署流程

### Step 1：安装 Nginx 与 Certbot

```bash
sudo apt update
sudo apt install -y nginx certbot python3-certbot-nginx
sudo systemctl enable nginx
sudo systemctl start nginx
sudo nginx -t
```

如果默认站点冲突，可禁用：

```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

### Step 2：先配置 HTTP 反向代理

先保证 HTTP 能访问，再申请 HTTPS 证书。

```bash
sudo tee /etc/nginx/sites-available/nxhguitar.com >/dev/null <<'EOF'
server {
    listen 80;
    server_name www.nxhguitar.com;
    return 301 http://nxhguitar.com$request_uri;
}

server {
    listen 80;
    server_name nxhguitar.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

server {
    listen 80;
    server_name api.nxhguitar.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF

sudo ln -sf /etc/nginx/sites-available/nxhguitar.com /etc/nginx/sites-enabled/nxhguitar.com
sudo nginx -t
sudo systemctl reload nginx
```

验证 HTTP：

```bash
curl -I http://nxhguitar.com
curl -I http://www.nxhguitar.com
curl http://api.nxhguitar.com/api/health
```

预期：

```txt
http://nxhguitar.com                 200 或可正常响应前端
http://www.nxhguitar.com             301 跳转主站
http://api.nxhguitar.com/api/health  返回 {"message":"后端服务运行正常"}
```

### Step 3：申请 HTTPS 证书

```bash
sudo certbot --nginx \
  -d nxhguitar.com \
  -d www.nxhguitar.com \
  -d api.nxhguitar.com
```

交互选择：

```txt
邮箱：填写可用邮箱
是否同意协议：A
是否接收 EFF 邮件：N
是否将 HTTP 重定向到 HTTPS：2
```

成功标志：

```txt
Successfully received certificate
Congratulations
```

验证证书续期：

```bash
sudo certbot renew --dry-run
```

### Step 4：修正 www 跳转到 HTTPS 主站

Certbot 自动改配置后，需要特别检查 `www` 是否跳到了 `http://nxhguitar.com`。如果是，必须改成 `https://nxhguitar.com`，避免 HTTPS 访问被降级为 HTTP。

检查：

```bash
curl -I https://www.nxhguitar.com
```

如果看到：

```txt
Location: http://nxhguitar.com/
```

执行修复：

```bash
sudo sed -i 's#return 301 http://nxhguitar.com$request_uri;#return 301 https://nxhguitar.com$request_uri;#g' /etc/nginx/sites-available/nxhguitar.com
sudo nginx -t
sudo systemctl reload nginx
```

最终验证：

```bash
curl -I http://nxhguitar.com
curl -I http://www.nxhguitar.com
curl -I https://www.nxhguitar.com
curl -I https://nxhguitar.com
curl https://api.nxhguitar.com/api/health
```

理想结果：

```txt
http://nxhguitar.com          -> 301 到 https://nxhguitar.com
http://www.nxhguitar.com      -> 301 到 https://nxhguitar.com
https://www.nxhguitar.com     -> 301 到 https://nxhguitar.com
https://nxhguitar.com         -> 200 OK
https://api.nxhguitar.com/api/health -> {"message":"后端服务运行正常"}
```

## 四、项目环境变量配置流程

HTTPS 证书成功后，项目环境变量必须从 HTTP 切到 HTTPS。

### 1. 修改根目录 `.env`

```bash
cd /root/player
cp .env .env.bak.$(date +%F-%H%M%S)

python3 - <<'PY'
from pathlib import Path

p = Path(".env")
text = p.read_text(encoding="utf-8")

updates = {
    "FRONTEND_URL": "https://nxhguitar.com",
    "NEXT_PUBLIC_API_BASE_URL": "https://api.nxhguitar.com/api",
}

lines = text.splitlines()
out = []
seen = set()

for line in lines:
    stripped = line.strip()
    if not stripped or stripped.startswith("#") or "=" not in line:
        out.append(line)
        continue

    key = line.split("=", 1)[0].strip()
    if key in updates:
        out.append(f"{key}={updates[key]}")
        seen.add(key)
    else:
        out.append(line)

for key, value in updates.items():
    if key not in seen:
        out.append(f"{key}={value}")

p.write_text("\n".join(out) + "\n", encoding="utf-8")
PY

grep -E '^(FRONTEND_URL|NEXT_PUBLIC_API_BASE_URL)=' .env
```


## 五、腾讯云 COS CORS 同步

HTTPS 启用后，COS 跨域 Origin 也要补 HTTPS 域名。

腾讯云 COS 控制台路径：

```txt
对象存储 COS -> 对应存储桶 -> 安全管理 -> 跨域访问 CORS
```

建议 Origin 至少包含：

```txt
https://nxhguitar.com
https://www.nxhguitar.com
http://nxhguitar.com
http://www.nxhguitar.com
```

如果仍需要 IP/端口临时访问，可暂时保留：

```txt
http://150.158.122.193:3001
```

Methods：

```txt
GET
PUT
POST
DELETE
HEAD
OPTIONS
```

Allowed Headers：

```txt
*
```

Expose Headers：

```txt
ETag
x-cos-request-id
x-cos-hash-crc64ecma
```

## 六、常见故障与处理

### 故障 1：Certbot 申请证书失败，提示 DNS problem

原因：域名未解析到当前服务器，或 DNS 尚未生效。

排查：

```bash
ping nxhguitar.com
ping www.nxhguitar.com
ping api.nxhguitar.com
```

处理：确认 A 记录均指向 `150.158.122.193`，等待 DNS 生效后重试。

### 故障 2：Certbot 申请证书失败，提示 Timeout during connect

原因：80 端口无法从公网访问。

排查：

```bash
sudo ss -tnlp | grep ':80'
sudo nginx -t
sudo systemctl status nginx --no-pager
```

处理：

1. 云服务器安全组放行 `80/tcp`。
2. 确保 Nginx 正常监听 80。
3. 确保没有其他服务占用 80。

如果 80 被旧进程占用：

```bash
sudo ss -tnlp | grep ':80'
sudo fuser -k 80/tcp
sudo systemctl start nginx
sudo systemctl status nginx --no-pager
```

### 故障 3：`https://www.nxhguitar.com` 跳到 HTTP

现象：

```bash
curl -I https://www.nxhguitar.com
```

返回：

```txt
Location: http://nxhguitar.com/
```

处理：

```bash
sudo sed -i 's#return 301 http://nxhguitar.com$request_uri;#return 301 https://nxhguitar.com$request_uri;#g' /etc/nginx/sites-available/nxhguitar.com
sudo nginx -t
sudo systemctl reload nginx
```

### 故障 4：主站 HTTPS 正常，但登录失败 / Failed to fetch

原因通常是前端构建时仍写入旧 API 地址，或 API HTTPS 反代未通。

排查：

```bash
curl https://api.nxhguitar.com/api/health
grep -E '^(FRONTEND_URL|NEXT_PUBLIC_API_BASE_URL)=' /root/player/.env
```

处理：

1. `.env` 中确认：

```env
FRONTEND_URL=https://nxhguitar.com
NEXT_PUBLIC_API_BASE_URL=https://api.nxhguitar.com/api
```

2. 重建前端：

```bash
cd /root/player
docker compose -p video_player -f docker-compose.yml -f docker-compose.local.yml build frontend
docker compose -p video_player -f docker-compose.yml -f docker-compose.local.yml up -d --force-recreate frontend
```

3. 浏览器强刷：`Ctrl + F5`。

### 故障 5：HTTPS 页面上传 COS 失败，CORS 报错

原因：COS CORS 只放行了 HTTP 或 IP/端口，未放行 `https://nxhguitar.com`。

处理：在 COS CORS 中补充：

```txt
https://nxhguitar.com
https://www.nxhguitar.com
```

保存后浏览器强刷再上传。

### 故障 6：浏览器显示不安全或没有小锁

原因可能是：

1. 访问的是 `http://` 而不是 `https://`。
2. 页面内加载了 HTTP 资源，出现 mixed content。
3. 证书没有覆盖当前访问域名。

排查：

```bash
curl -I https://nxhguitar.com
curl -I https://www.nxhguitar.com
curl -I https://api.nxhguitar.com/api/health
```

浏览器开发者工具 Console 查看是否有 `Mixed Content`。

## 七、上线后标准验证清单

每次改域名、证书、Nginx、`.env` 后都执行：

```bash
# Nginx 配置
sudo nginx -t
sudo systemctl status nginx --no-pager

# 容器状态

# 本机端口

# 域名跳转
curl -I http://nxhguitar.com
curl -I http://www.nxhguitar.com
curl -I https://www.nxhguitar.com

# 正式入口

```

合格标准：

```txt
http://nxhguitar.com          -> 301 到 https://nxhguitar.com

https://www.nxhguitar.com     -> 301 到 https://nxhguitar.com
https://nxhguitar.com         -> 200 OK
https://api.nxhguitar.com/api/health -> {"message":"后端服务运行正常"}
FRONTEND_URL=https://nxhguitar.com

```

## 八、2026-09-29 结论

1. HTTP、HTTPS、www、非 www 都可以让用户输入，但不应全部独立跑业务。
2. 生产环境唯一主站应统一为 `https://nxhguitar.com`。
3. `www` 只做 301 跳转到主站。
4. HTTP 只做 301 跳转到 HTTPS。
5. API 独立使用 `https://api.nxhguitar.com/api`。
6. `NEXT_PUBLIC_API_BASE_URL` 改动后必须重建前端镜像。
7. 证书申请前必须先保证 HTTP 可访问，因为 Let's Encrypt 需要通过 80 端口验证域名归属。
8. HTTPS 启用后，COS CORS、后端 CORS、前端构建变量必须同步切换到 HTTPS Origin。
