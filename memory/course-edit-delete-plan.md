# 教导主任课程编辑删除与历史记录稳定性方案

> 本文件是实际实施方案，不是已完成代码说明。后续按阶段实施时，应先做阶段 1，保证删除课程不会破坏历史作业记录和前置知识关系，再做课程编辑能力。

## 背景

当前项目已经有三角色：学员、老师、教导主任。老师可以上传课程视频并为本班学员编辑主页置顶课程视频和作业备注；教导主任拥有更高权限。

本方案解决以下问题：

1. 教导主任不仅可以删除课程，也应该可以编辑所有课程内容。
2. 删除课程时，如果课程被其他课程作为前置知识点，不能让前置知识列表、详情页或上传/编辑表单报错。
3. 删除课程时，如果课程出现在学生主页课程设置或历史作业操作记录里，历史记录不能因为原视频被删而坏掉。
4. 教导主任编辑课程时，应该明确是更新旧课程记录，还是重新上传成一门新课。
5. 前端入口应该让教导主任知道如何编辑或删除课程。

## 当前代码现状

### 课程表与附件

- `videos` 保存课程视频标题、简介、视频 URL、封面 URL、创建时间。
- `video_attachments` 通过 `video_id` 关联课程，当前是 `ON DELETE CASCADE`。
- 删除课程时，附件数据库记录会跟着删除。

### 前置知识关系

当前 `video_prerequisites` 表结构是：

```sql
video_id INTEGER NOT NULL REFERENCES videos(id) ON DELETE CASCADE,
prerequisite_video_id INTEGER NOT NULL REFERENCES videos(id) ON DELETE CASCADE
```

这意味着：

- 删除课程 A 时，A 自己的前置知识关系会自动删除。
- 如果课程 A 被课程 B 当作前置知识，删除 A 时，B -> A 这条关系也会自动删除。
- 因此前置知识关系表本身不会出现孤儿引用。

### 学生主页课程设置 / 作业备注

当前 `user_assignments.video_id` 是：

```sql
video_id INTEGER REFERENCES videos(id) ON DELETE SET NULL
```

这意味着删除课程后，历史记录里对应的 `video_id` 会变成 `NULL`。如果历史操作记录只依赖 `videos` 表再查标题和封面，就会丢失当时显示过的课程标题。

## 总体原则

1. 教导主任可以编辑和删除所有课程。
2. 老师可以上传课程，但不能编辑或删除课程，避免不同老师互相改动课程库。
3. 删除课程必须让前置知识关系自动清理，不保留坏引用。
4. 学生主页历史操作记录必须保存“当时的课程标题快照”，不依赖课程是否还存在。
5. 历史作业记录只显示标题文本，不显示封面，不提供跳转，避免课程删除后链接失效。
6. 编辑课程默认是“修改旧课程记录”，不是创建新课程；只有用户明确点击“新建课程”才创建新记录。

## 阶段 1：修正历史作业记录的数据模型

### 目标

让学生主页课程设置历史记录在课程删除后仍然稳定展示。

### 后端数据库调整

给 `user_assignments` 增加课程快照字段：

```sql
ALTER TABLE user_assignments
ADD COLUMN IF NOT EXISTS video_title_snapshot TEXT NOT NULL DEFAULT '';
```

可选字段：

```sql
ALTER TABLE user_assignments
ADD COLUMN IF NOT EXISTS video_deleted_snapshot BOOLEAN NOT NULL DEFAULT FALSE;
```

### 写入规则

老师或教导主任保存学生主页置顶课程时：

1. 后端根据 `videoIds` 查询课程标题。
2. 插入 `user_assignments` 时同时写入 `video_title_snapshot`。
3. 历史记录展示时优先使用 `video_title_snapshot`。
4. 如果旧记录没有快照，再兜底使用 `videos.title`。

### 删除课程后的记录规则

删除课程后：

- `user_assignments.video_id` 会自动变成 `NULL`。
- `video_title_snapshot` 保留原课程标题。
- 历史操作记录显示：`课程标题（课程已删除）`。
- 不显示封面。
- 不提供跳转链接。

这样即使课程不存在，历史作业记录也不会报错。

## 阶段 2：调整历史操作页面显示方式

### 目标

老师作业推送历史记录不依赖封面和详情链接。

### 前端调整

在 `/admin/users/[id]/assignments` 的历史操作区域：

当前做法：

- 显示课程封面。
- 标题可点击跳转详情页。
- 课程删除后容易出现空链接或无封面状态。

建议改为：

- 只显示课程标题。
- 标题是纯文本，不跳转。
- 如果课程已删除，显示 `已删除` 标签。
- 不显示封面图片。

示例展示：

```txt
本次设置的课程：
- 函数基础
- 循环练习（课程已删除）
```

### 后端返回数据调整

历史操作接口返回每条视频记录时至少包含：

```json
{
  "assignment_id": 1,
  "video_id": null,
  "title": "函数基础",
  "is_video_deleted": true,
  "is_deleted": false
}
```

其中 `title` 来自：

```sql
COALESCE(NULLIF(ua.video_title_snapshot, ''), v.title, '课程已删除') AS title
```

## 阶段 3：删除课程时处理前置知识关系

### 目标

删除课程后，其他课程的前置知识列表和编辑表单不能出现坏数据。

### 当前表结构是否安全

当前 `video_prerequisites` 的两个外键都是 `ON DELETE CASCADE`，这是正确的。

删除课程 A 时：

- A 的附件会通过 `video_attachments.video_id ON DELETE CASCADE` 删除数据库记录。
- A 作为主课程的前置知识关系会删除。
- A 作为其他课程前置知识的关系也会删除。
- 其他课程仍然存在，只是少了 A 这个前置知识点。

### 后端删除流程建议

删除课程接口需要放在一个事务里：

1. 查询课程本身、附件、封面 key、视频 key。
2. 查询影响范围：
   - 哪些课程把它作为前置知识。
   - 哪些学生主页当前置顶了它。
   - 哪些历史操作记录引用了它。
3. 先删除存储桶对象：视频、封面、附件。
4. 删除 `videos` 记录。
5. 依靠数据库外键自动清理：
   - `video_attachments`
   - `video_prerequisites`
   - `user_assignments.video_id SET NULL`
6. 返回删除结果和影响统计。

### 前端删除确认文案

教导主任点击删除时，不应该只提示“确定删除视频吗”，而应该提示影响范围：

```txt
确定删除《函数基础》吗？

删除后：
- 视频文件、封面和附件会从存储桶删除
- 其他课程中引用它的前置知识关系会自动移除
- 学生主页历史操作记录会保留课程标题，但不再跳转

此操作不可恢复。
```

## 阶段 4：教导主任编辑课程的规则

### 编辑是改旧课程，不是新建课程

默认编辑课程应该更新同一条 `videos.id` 记录。

原因：

1. 学生主页置顶课程仍然指向同一个课程 ID。
2. 其他课程的前置知识仍然指向同一个课程 ID。
3. 不会因为编辑产生重复课程。
4. 历史记录仍能表示“当时设置的是这门课”。

### 哪些字段可以编辑

教导主任可以编辑：

- 标题
- 简介
- 封面
- 视频文件
- 附件
- 前置知识点

### 编辑标题对历史记录的影响

历史操作记录显示的是当时的标题快照，不应该随着课程新标题变化。

例如：

1. 老师把《函数基础》置顶给学生。
2. 后来教导主任把课程标题改为《函数入门》。
3. 历史操作记录仍显示《函数基础》。
4. 当前学生主页置顶课程显示新标题《函数入门》。

这样历史记录和当前状态都清楚。

### 编辑边界校验

教导主任编辑课程必须经过和上传课程一样的边界校验检查。

需要复用或抽取当前上传校验逻辑，保证新增和编辑规则一致：

- 标题必填，最多 120 个字。
- 标题不能是 `null`、`undefined`、`NaN` 这类无意义内容。
- 简介可选，最多 1000 个字。
- 简介不能是 `null`、`undefined`、`NaN` 这类无意义内容。
- 如果编辑时替换视频文件，新视频必须满足上传页同样的大小和格式限制。
- 如果编辑时替换封面，新封面必须满足上传页同样的大小和格式限制。
- 如果编辑时替换或新增附件，附件数量、大小、文件名和格式必须与上传页规则一致。
- 前置知识点必须是存在的课程，不能包含当前课程自己，不能形成循环引用。
- 前端校验只负责体验，后端 `PATCH /api/videos/:id` 必须再次完整校验。

### 编辑视频文件如何处理存储桶

推荐方案：编辑旧课程记录，但新文件上传到新的对象 key，成功后再删除旧对象。

不要直接覆盖旧 key。

原因：

1. 覆盖旧 key 时，如果上传中断，旧课程可能损坏。
2. 浏览器或 CDN 可能缓存旧视频。
3. 新 key 更容易回滚和排查问题。

推荐流程：

1. 教导主任进入课程编辑页。
2. 后端读取旧课程数据，前端展示旧标题、简介、封面、附件、前置知识点。
3. 如果只改标题/简介/前置知识点，不上传新文件，只更新数据库。
4. 如果替换封面/视频/附件：
   - 先按现有上传流程上传新文件到新 key。
   - 后端确认新对象存在。
   - 数据库事务中更新 `videos.video_url` / `cover_url` 和附件表。
   - 数据库更新成功后删除旧对象。
5. 如果删除旧对象失败，记录日志，后续用孤儿文件清理脚本处理。

## 阶段 5：新增课程编辑接口

### 后端接口建议

教导主任专用：

```txt
PATCH /api/videos/:id
```

权限：`requireSuperAdmin`。

支持更新：

```json
{
  "title": "新标题",
  "description": "新简介",
  "coverKey": "covers/new-cover.webp",
  "videoKey": "videos/new-video.mp4",
  "attachments": {
    "keepIds": [1, 2],
    "deleteIds": [3],
    "replace": [
      { "oldAttachmentId": 4, "key": "attachments/new-file.pdf", "fileName": "新资料.pdf", "fileType": "application/pdf", "fileSize": 1024 }
    ],
    "add": [
      { "key": "attachments/extra.pdf", "fileName": "补充资料.pdf", "fileType": "application/pdf", "fileSize": 2048 }
    ]
  },
  "prerequisiteVideoIds": [1, 2, 3]
}
```

规则：

- `title` 必填。
- `description` 可空。
- `coverKey` 可选；不传表示保留旧封面。
- `videoKey` 可选；不传表示保留旧视频。
- `attachments` 使用附件编辑清单，不再用“不传表示保留旧附件”的粗粒度规则。
- 编辑页打开后必须展示当前课程所有已有资料。
- 每个已有资料都可以单独保留、删除或替换。
- 页面可以继续新增资料。
- 后端根据附件编辑清单精确处理：保留哪些旧附件、删除哪些旧附件、替换哪些旧附件、新增哪些附件。
- `prerequisiteVideoIds` 可选；不传表示保留旧前置知识点，传空数组表示清空。
- 不允许把课程自己设为自己的前置知识。
- 建议增加简单循环检测，避免 A 前置 B、B 前置 A。

### 附件编辑清单处理规则

编辑课程时，附件必须按“当前已有资料列表 + 用户操作结果”提交，后端不能简单认为不传就是全部保留。

推荐提交结构：

```txt
attachments.keepIds       要保留的旧附件 id
attachments.deleteIds     要删除的旧附件 id
attachments.replace       要替换的旧附件 id + 新附件对象 key/文件名/类型/大小
attachments.add           要新增的新附件对象 key/文件名/类型/大小
```

后端处理顺序：

1. 查询当前课程已有附件，确认所有 `keepIds/deleteIds/replace.oldAttachmentId` 都属于当前课程。
2. 校验最终附件数量不能超过上限：`keepIds + replace + add`。
3. 校验新增和替换的新附件文件名、格式、大小。
4. 确认新增和替换的新附件对象已经在存储桶中存在。
5. 数据库事务内：
   - 删除 `deleteIds` 对应附件记录。
   - 删除 `replace.oldAttachmentId` 对应旧附件记录。
   - 插入替换后的新附件记录。
   - 插入新增附件记录。
   - 保留 `keepIds` 对应附件记录不动。
6. 数据库提交成功后，再删除被删除/被替换的旧附件对象。
7. 如果旧对象删除失败，只记录日志，后续交给孤儿文件清理脚本处理。

这样可以支持“删掉几个旧资料、替换几个旧资料、再新增一点资料”的编辑场景。

### 循环前置知识检测

因为“前置的也会有前置”，所以需要避免循环。

不允许：

```txt
A 的前置是 B
B 的前置是 A
```

也不允许更长链路：

```txt
A -> B -> C -> A
```

实现方式：

- 当给课程 A 设置前置知识点时，从每个候选前置课程开始，递归查询它的前置链。
- 如果链路里出现 A，拒绝保存。
- 提示：`前置知识不能形成循环引用`。

## 阶段 6：新增课程编辑页面与入口

### 页面建议

新增页面：

```txt
/admin/videos/[id]/edit
```

页面内容复用上传页表单，但进入编辑模式：

- 标题显示：`编辑课程视频`
- 表单预填旧课程数据
- 视频文件可选，不选表示保留旧视频
- 如果选择了新视频，页面必须提供“移除当前选择的视频”按钮，点击后清空文件选择并恢复为保留旧视频
- 封面可选，不选表示保留旧封面
- 如果选择了新封面，页面必须提供“移除当前选择的封面”按钮，点击后清空文件选择并恢复为保留旧封面
- 附件可保留、删除、替换、新增
- 编辑页打开后展示所有已有资料，每个资料旁边提供：`保留`、`删除资料`、`替换资料`
- 新增资料区继续支持多选上传，每个新选择但未提交的附件旁边提供“移除”按钮，避免选中文件后不能撤销
- 前置知识点可搜索、选择、移除
- 右侧继续显示预览效果

### 后台首页入口

在 `/admin` 的“视频管理”板块顶部写清楚：

```txt
教导主任可以编辑或删除所有课程。点击课程卡片上的“编辑课程”或“删除视频”进行操作。
```

### 操作方式建议

不建议依赖右键。

原因：

1. 右键操作不明显，用户不一定知道。
2. 手机或触屏设备没有稳定右键体验。
3. 浏览器右键菜单容易和自定义菜单冲突。

推荐方式：

- 每个课程卡片上为教导主任显示两个按钮：
  - `编辑课程`
  - `删除视频`
- 老师只显示查看入口，不显示编辑/删除。
- 如果以后想补右键菜单，可以作为增强功能，但不能作为唯一入口。

## 阶段 7：前端组件调整

### VideoList 组件

给 `VideoList` 增加编辑能力：

```txt
canEdit
onEdit
editText
```

教导主任在 `/admin` 视频管理里：

- `canEdit={true}`
- `onEdit={(video) => router.push(`/admin/videos/${video.id}/edit`)}`
- `canDelete={true}`

老师在 `/admin` 视频管理里：

- `canEdit={false}`
- `canDelete={false}`

### 上传/编辑表单文件撤销能力

上传页和编辑页都需要支持撤销已选择的本地文件。

规则：

- 视频文件选择后，显示文件名、大小和“移除视频”按钮。
- 封面文件选择后，显示封面预览和“移除封面”按钮。
- 资料附件列表中，每个未提交附件都显示“移除”按钮。
- 点击移除后，需要同时清空 React state 和对应 `<input type="file">` 的值。
- 上传页中视频和封面仍是必填；如果用户移除了已选视频或封面，提交时按未选择处理并提示。
- 编辑页中视频和封面不是必填；移除新选择的文件后表示保留旧文件，不删除旧文件。

### 历史操作视频列表

把历史操作里的 `<a>` 改成纯文本结构：

```txt
<div className="operation-video-item">
  <span className="operation-video-title">课程标题</span>
  <span>课程已删除</span>
</div>
```

不再渲染封面图。

## 阶段 8：推荐实施顺序

### 第一阶段：先保证删除不出 bug

1. 给 `user_assignments` 增加 `video_title_snapshot`。
2. 保存学生主页置顶课程时写标题快照。
3. 历史操作接口改为使用标题快照。
4. 前端历史记录只显示标题，不显示封面，不跳转。
5. 删除课程前确认 `video_prerequisites` 级联清理正常。

这一阶段完成后，删除课程不会影响作业历史记录和前置知识列表。

### 第二阶段：再做教导主任编辑课程

1. 新增 `PATCH /api/videos/:id`。
2. 复用上传边界校验，保证编辑课程和上传课程的标题、简介、文件、附件、前置知识点校验一致。
3. 支持只改文字和前置知识点。
4. 支持替换封面、视频和附件。
5. 新增 `/admin/videos/[id]/edit` 页面。
6. 在课程卡片上给教导主任显示“编辑课程”。
7. 上传页和编辑页都补充“移除视频 / 移除封面 / 移除资料”按钮，避免选中文件后不能撤销。

### 第三阶段：优化提示和体验

1. 删除前显示影响范围。
2. 后台视频管理顶部增加说明文字。
3. 前置知识点选择加入循环检测提示。
4. README 同步更新。

## 最终结论

- 教导主任应该可以编辑和删除所有课程。
- 删除课程时，前置知识关系用数据库 `ON DELETE CASCADE` 自动清理，这是正确方向。
- 作业历史记录不能继续依赖视频封面和跳转，应该保存标题快照，只显示纯文本标题。
- 编辑课程应该默认更新旧课程记录，不创建新课程。
- 替换视频/封面/附件时，不覆盖旧对象 key，而是上传新对象，数据库更新成功后删除旧对象。
- 编辑和删除入口不建议做成右键唯一操作，应该在课程卡片上直接显示按钮，并在后台视频管理板块顶部写清楚。
