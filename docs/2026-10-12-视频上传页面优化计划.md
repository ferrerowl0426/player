# 视频上传页面功能优化计划

## 背景

当前后台曲目 / 知识点的视频 P 分段需要逐个点击「添加分段」、填写 P 标题、选择视频文件，再保存上传。封面上传目前是选择图片后直接上传，页面文案写有「自动裁切 1:1」，但实际没有给用户提供可拖动、缩放、确认的裁切过程。

本次优化目标：

1. 新增批量导入视频能力：一次选择多个视频后自动生成多个 P 分段，标题默认取视频文件名去掉扩展名。
2. 新增封面正方形裁切能力：选择图片后弹出 1:1 裁切框，用户可拖动、缩放，确认后再上传，取消则保留原封面。

参考库：

- https://valentinh.github.io/react-easy-crop/
- https://github.com/ValentinH/react-easy-crop

---

## 一、现状梳理

### 1. 曲目 P 视频上传页面

主要文件：

```txt
frontend/app/admin/tracks/page.js
frontend/components/uploadVideo.js
frontend/lib/api.js
```

当前流程：

1. 点击「添加分段」新增一个空 P。
2. 手动填写 P 标题。
3. 单独选择该 P 的视频文件。
4. 保存时逐个执行：
   - `createTrackPartUpload`
   - `uploadVideoByMultipart`
   - `completeTrackPartUpload`
   - `saveTrackPart`

当前 P 数据结构：

```js
{
  id: null,
  part_no: partNo,
  title: '',
  duration: '',
  video: null,
  video_url: ''
}
```

### 2. 知识点 P 视频上传页面

主要文件：

```txt
frontend/app/admin/knowledge/page.js
frontend/components/uploadVideo.js
frontend/lib/api.js
```

结构与曲目页面基本一致，只是接口换成知识点接口：

- `createKnowledgePartUpload`
- `completeKnowledgePartUpload`
- `saveKnowledgePart`

### 3. 封面上传页面

当前有多处封面上传入口：

```txt
frontend/app/admin/tracks/page.js              曲目封面，目标比例 1:1
frontend/app/admin/knowledge/page.js           知识点封面，目标比例 1:1
frontend/app/admin/knowledge/page.js           知识点集封面，目标比例 1:1
frontend/app/admin/library/page.js             图书馆 PDF 封面，当前目标比例 A4 210:297
```

曲目 / 知识点页面当前上传方式：

1. 选择图片文件。
2. 直接调用 `createLibraryUploadUrl(file, 'cover')`。
3. 调用 `uploadLibraryFileToBucket` 上传原图。
4. 将返回的 `publicUrl` 写入 `cover`。

图书馆页面当前是 A4 竖版封面规则，不属于本次“正方形封面”的主范围，除非后续确认也要改成 1:1。

## 二、需求拆分

## 功能 A：批量导入视频 P 分段

### 目标体验

在 P 分段管理区新增一个按钮：

```txt
＋ 批量导入视频
```

支持一种选择方式：

1. 一次多选视频文件，例如选择 10 个视频。

第一版取消“选择文件夹导入”，只做批量选择视频文件导入。

导入后系统自动生成 P：

```txt
文件：01-右手分解.mp4 → P 标题：01-右手分解
文件：02-左手换和弦.mov → P 标题：02-左手换和弦
```

用户导入后可以检查：

- P 顺序
- P 标题
- 视频文件是否正确

点击保存后再按当前流程依次上传。

### 文件类型规则

建议默认支持：

```txt
video/*
.mp4
.mov
.m4v
.webm
.avi
.mkv
```

前端筛选逻辑：

- `file.type.startsWith('video/')` 优先；
- 对部分浏览器识别不到 MIME 的文件，兜底检查扩展名。

### 数量规则

建议第一版限制：

```txt
单次最多导入 10 个视频
```

原因：

- 用户需求明确“一次选中 10 个视频”；
- 大视频同时进入列表没问题，但保存时仍按当前串行上传，避免并发导致 COS / 网络压力过大；
- 后续如需要可放宽到 20 或 50。

### 排序规则

第一版建议：

1. 按浏览器返回的文件顺序保留。
2. 同时提供导入后列表里的 ↑ / ↓ 调整。
3. 如果多选文件顺序在不同浏览器表现不稳定，可按文件名自然排序兜底。

自然排序建议用：

```js
new Intl.Collator('zh-CN', { numeric: true, sensitivity: 'base' })
```

这样：

```txt
P2.mp4 会排在 P10.mp4 前面
```

### 标题规则

默认标题 = 文件名去掉最后一个扩展名：

```txt
大手拉小.mp4       → 大手拉小
01.音阶练习.mov    → 01.音阶练习
foo.bar.baz.mp4    → foo.bar.baz
```

### 与已有 P 的合并规则

如果当前已经有 3 个 P，再批量导入 10 个视频：

```txt
新导入 P 的 part_no 从 4 开始
```

也就是追加到列表尾部，不覆盖现有 P。

### UI 调整点

曲目页面：

```txt
frontend/app/admin/tracks/page.js
```

知识点页面：

```txt
frontend/app/admin/knowledge/page.js
```

P 分段管理头部建议改成：

```txt
[＋ 添加分段] [批量导入视频]
```

实现上只需要一个 hidden input：

```jsx
<input type="file" accept="video/*" multiple hidden />
```

注意：

- 不做 `webkitdirectory` 文件夹导入，避免非标准属性带来的兼容性和排序不确定性；
- 用户如需导入某个文件夹下的视频，可在系统文件选择器内全选该文件夹中的视频文件。

### 保存流程

保存流程可以复用现有逻辑，不改后端：

1. 批量导入只是在前端一次性生成多个 `part`。
2. 保存时仍由已有 `submit()` 遍历 `parts`。
3. 每个新 P 仍走现有分片上传流程。

优点：

- 改动集中在前端；
- 不新增后端接口；
- 失败处理沿用现有上传失败 / abort 机制。

## 功能 B：封面正方形裁切

### 目标体验

用户选择封面图片后：

1. 不立即上传。
2. 弹出裁切弹窗。
3. 弹窗中显示一个固定正方形裁切框。
4. 用户拖动、缩放图片，把想保留的部分放进框内。
5. 点击「确认裁切」后，前端生成裁切后的正方形图片文件，再上传。
6. 点击「取消」则关闭弹窗，保留原封面不变。

### 使用库

新增依赖：

```bash
npm install react-easy-crop --save
```

当前 `frontend/package.json` 只有：

```json
"next": "^15.1.4",
"react": "^19.0.0",
"react-dom": "^19.0.0"
```

需要新增：

```json
"react-easy-crop": "latest"
```

建议实际安装锁定到安装时解析的稳定版本，避免未来构建漂移。

### 组件方案

新增通用组件：

```txt
frontend/components/CoverCropperModal.js
```

职责：

- 接收原始图片 `File`；
- 使用 `URL.createObjectURL(file)` 生成预览地址；
- 渲染 `Cropper`；
- `aspect={1}`；
- 维护：
  - `crop`
  - `zoom`
  - `croppedAreaPixels`
- 点击确认时用 Canvas 输出正方形 Blob / File。

建议 props：

```js
<CoverCropperModal
  file={pendingCoverFile}
  title="裁切封面"
  aspect={1}
  outputSize={1200}
  onCancel={closeCropper}
  onConfirm={handleCroppedCover}
/>
```

### Canvas 输出规则

第一版统一输出：

```txt
1200 x 1200
image/jpeg
quality: 0.92
```

原因：

- 统一正方形封面尺寸，显示稳定；
- JPG 体积较小；
- `1200x1200` 足够网页和小程序封面使用。

如果源图有透明通道，例如 PNG / WEBP，第一版也可以输出 JPG；如后续需要透明背景，再改为保留 PNG。

### 取消行为

取消时必须满足：

```txt
不上传新文件
不清空旧 cover
不改当前表单 cover 字段
```

如果当前已有封面，取消后仍显示原封面。

### 接入范围

第一版建议覆盖这几个 1:1 封面入口：

```txt
frontend/app/admin/tracks/page.js
frontend/app/admin/knowledge/page.js 的知识点封面
frontend/app/admin/knowledge/page.js 的知识点集封面
```

暂不改图书馆 PDF 封面，因为图书馆当前明确是：

```txt
A4 竖版 210 : 297
```

如果要改图书馆，应另开需求：A4 裁切框，而不是正方形裁切框。

## 六、风险点与处理

### 1. 批量选择顺序差异

风险：不同浏览器对多选文件返回顺序可能略有差异。

处理：

- 导入后保留 P 列表的 ↑ / ↓ 调整能力；
- 必要时按文件名自然排序作为兜底；
- 保存前由用户检查顺序和标题。

### 2. 大视频上传时间长

风险：一次导入多个大视频，保存上传耗时明显。

处理：

- 第一版继续串行上传，稳定优先；
- 状态栏显示当前 P 上传进度；
- 后续可再做上传队列和失败重试。

### 3. 取消裁切不能影响旧封面

风险：选择图片后如果提前清空 cover，取消时会丢失原封面。

处理：

- 选择图片只写入 `pendingCoverFile`；
- 确认裁切并上传成功后才 `patchTrack({ cover })` 或 `patchPoint({ cover })`。

### 4. Canvas 跨域问题

风险：Canvas 裁切跨域图片会污染画布。

处理：

- 本次裁切对象来自本地 `File`，用 `objectURL`，不会跨域。

### 5. 图片过大导致内存占用

风险：超大图片 Canvas 处理慢。

处理：

- 输出固定 1200x1200；
- 可继续沿用现有封面大小限制；
- 如果源图过大，后续可加入最大源图尺寸限制。
