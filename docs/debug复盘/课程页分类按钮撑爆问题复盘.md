# 课程页分类按钮撑爆问题复盘

## 复盘对象

小程序学生端课程页顶部分类切换区域：

```txt
知识点集 / 曲目集 / 知识点 / 曲目
```

相关页面：

```txt
C:\Users\user\Desktop\播放器\miniprogram\pages\courses\index.wxml
C:\Users\user\Desktop\播放器\miniprogram\pages\courses\index.wxss
```

## 问题现象

微信开发者工具中，课程页顶部四个分类项没有按照设计稿四等分排列，而是出现：

- 分类按钮互相挤压；
- 文字撑开按钮；
- 四个分类没有稳定落在一行；
- 页面视觉与设计稿明显不一致。

用户截图反馈后，第一次只通过 CSS 调整原生 `button` 宽度、字号、间距，但重新编译后问题仍然存在。

## 设计稿要求

课程页顶部分类不是表单提交按钮，而是一个分段筛选控件。

设计稿语义是：

```txt
固定四项
一行四等分
当前选中项深色底
其他项浅色描边
点击后切换当前课程类型
```

本项目已确认：后续不需要兼容更长名字，因此不需要横向滚动，也不需要做超长文本适配。

## 原始错误实现

原先使用了小程序原生 `button`：

```xml
<button class="type-btn" data-section="knowledge-set" bindtap="changeSection">知识点集</button>
<button class="type-btn" data-section="track-set" bindtap="changeSection">曲目集</button>
<button class="type-btn" data-section="knowledge" bindtap="changeSection">知识点</button>
<button class="type-btn" data-section="track" bindtap="changeSection">曲目</button>
```

虽然外层使用了：

```css
.type-switch {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
}
```

但实际显示仍然异常。

## 根因分析

### 1. 小程序原生 button 有默认渲染行为

微信小程序原生 `button` 不是普通容器，它自带：

- 默认 padding；
- 默认 line-height；
- 默认 margin / min-width 行为；
- 默认伪元素边框；
- 特殊的内部布局规则。

这些默认行为会干扰四等分布局。

### 2. 语义选择错误

这个位置本质是“课程类型筛选器”，不是提交按钮。

把设计稿里的 HTML button 机械映射成小程序原生 `button` 是错误的。小程序端应该根据组件语义选择实现方式，而不是照搬标签名。

### 3. CSS 修补无法彻底规避默认行为

曾尝试给 `.type-btn` 添加：

```css
width: 100%;
min-width: 0;
padding: 0;
margin: 0;
line-height: 1;
```

并清理：

```css
.type-btn::after {
  border: 0;
}
```

但在微信开发者工具中仍然没有完全恢复设计稿效果，说明继续围绕原生 `button` 修补不是可靠方案。

## 最终修改方案

将课程页顶部分类从原生 `button` 改为 `view + bindtap` 自绘分段控件。

### WXML 修改

改为：

```xml
<view class="type-switch">
  <view class="type-option {{section === 'knowledge-set' ? 'active' : ''}}" data-section="knowledge-set" bindtap="changeSection">知识点集</view>
  <view class="type-option {{section === 'track-set' ? 'active' : ''}}" data-section="track-set" bindtap="changeSection">曲目集</view>
  <view class="type-option {{section === 'knowledge' ? 'active' : ''}}" data-section="knowledge" bindtap="changeSection">知识点</view>
  <view class="type-option {{section === 'track' ? 'active' : ''}}" data-section="track" bindtap="changeSection">曲目</view>
</view>
```

### WXSS 修改

使用固定四等分布局：

```css
.type-switch {
  width: 100%;
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 10rpx;
  margin-bottom: 20rpx;
}

.type-option {
  height: 72rpx;
  border: 2rpx solid #c9b795;
  border-radius: 16rpx;
  background: #ffffff;
  color: #5d4326;
  font-size: 21rpx;
  line-height: 72rpx;
  font-weight: 900;
  text-align: center;
  box-sizing: border-box;
  white-space: nowrap;
  overflow: hidden;
}

.type-option.active {
  background: #5d4326;
  border-color: #5d4326;
  color: #ffffff;
  box-shadow: 0 10rpx 28rpx rgba(93, 67, 38, 0.18);
}
```

## 本次教训

### 1. 不能机械照搬设计稿标签

设计稿里的按钮、卡片、筛选器在小程序里需要按语义重新选择组件。

课程类型切换器应优先使用自绘 `view`，而不是原生 `button`。

### 2. 截图反馈后不要只做表层 CSS 修补

第一次用户反馈后，只做了按钮宽度、字号、间距修补，但没有解决根因，导致问题复现。

正确方式应该是：

```txt
先判断组件语义是否选错
再决定是修样式还是换实现
```

### 3. 小程序原生组件要谨慎使用

小程序原生组件适合表单和系统能力场景，例如：

- 表单提交；
- 获取手机号；
- 开放能力；
- 用户授权；
- 分享等。

普通 UI 控件、筛选项、分段控件，优先使用 `view` 自绘，避免默认样式污染。

## 后续类似问题处理原则

遇到设计稿中的筛选按钮、Tab、Segment、Chip、标签切换时，优先判断：

```txt
它是否真的需要原生 button 能力？
```

如果只是视觉控件，应直接使用：

```txt
view + bindtap + 自定义样式
```

不要默认使用小程序 `button`。
