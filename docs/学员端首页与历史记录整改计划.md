# 学员端首页与历史记录页面整改计划

> 依据：`docs/PRD.md` §2.2、§2.3、§2.5、§2.6、§3.1、§4.6、§4.8、§5.9、§5.10、§8；设计稿 `docs/design/guitar-home/student-home.html`、`docs/design/guitar-home/my-homework.html`；当前实现 `frontend/app/page.js`、`frontend/app/home.module.css`、`frontend/app/my-homework/page.js`、`frontend/app/my-homework/my-homework.module.css`、`frontend/lib/api.js`、`frontend/app/login/LoginForm.js`。

## 1. 需求复述

本次要按 PRD 和设计稿重新梳理并整改两个学员端页面：

1. 学员首页 `/`
   - 仅学员可访问；游客、老师、教导主任不能看到学员首页。
   - 页面用于展示老师当前布置给学员的作业内容、练习要求、提交要求。
   - 视觉严格对齐 `student-home.html`。
   - 首页右侧为“今天你需要用到的学习资源”卡片区，最多展示当前有效作业内容；单 P 标题必须为“单课名-P名”。
   - 首页左侧必须是两个独立框：“练习要求”和“提交要求”，不能再出现统一“老师留言板 / 留言区 / 作业细则”口径。
   - 两个要求框独立展示，空框不占位；保留换行；超过 3 行时仅框内滚动。
   - 停用学员仍可进入首页并浏览资源，页首显示停用提示文案：`资源免费开放半年用于自学，如需恢复课程请联系老师。`

2. 我的历史作业 `/my-homework`
   - 仅学员可访问。
   - 按 `operation_id` 聚合展示历次作业，时间倒序。
   - 与老师 / 教导主任学生管理页中的历史作业复用同一数据口径：作业内容、练习要求、提交要求、布置时间、老师姓名、删除信息。
   - 学员端对仍存活内容可点击跳转；管理端历史记录不可点击。
   - 视觉严格对齐 `my-homework.html`：工具行、停用提示、直列记录列表、回到顶部按钮。
   - 停用学员页首显示停用提示文案：`老师之前带你学到了这里，如需恢复课程请联系老师。`

3. 登录后进入访客页面的问题
   - PRD 要求：学员登录成功后跳转 `/`。
   - 当前现象：学员登录后进入或表现为访客页面。
   - 必须查明是“登录跳转错了”、“会话识别错了”、“首页鉴权失败后错误跳 `/tracks`”、“cookie/session 未正确写入或读取”，还是“前端访客模式状态未被清除”。

## 2. 当前代码现状与已发现问题

### 2.1 学员首页现状

当前 `frontend/app/page.js` 已经是学员首页路由，但实现与最新 PRD / 设计稿仍有偏差：

- 左侧仍使用信纸式 `letter`，标题为“作业细则”，把练习要求和提交要求合并为一组列表，不符合 PRD v1.1.4。
- PRD 明确要求原“老师留言板 / 留言区 / 作业细则”删除，替换为两个独立上下框：“练习要求”和“提交要求”。
- 当前 `requirements = assignments.flatMap([...])` 会把练习要求和提交要求混在一起，无法保持两个栏目独立。
- 当前空状态和默认文案中仍有“按老师布置的顺序练习”等兜底内容，可能导致没有要求时仍显示非真实内容。
- 当前样式 `home.module.css` 与 `student-home.html` 前半部分不完全一致：设计稿左侧是 `.req-stack` + `.req-card` + `.req-text`，当前实现是 `.letter` 明信片结构。

### 2.2 历史记录页现状

当前 `frontend/app/my-homework/page.js` 已经有历史作业页面，但与设计稿和 PRD 仍有偏差：

- 当前使用时间线 `.tl / .op` 结构；设计稿 `my-homework.html` 是更接近管理端历史记录的 `.rec-list / .hw-item` 直列结构。
- 当前按日期额外插入 `tl-date` 分组；设计稿说明“按作业记录展示，不按日期合并”，日期只作为每条记录左侧标签显示。
- 当前练习要求与提交要求放在同一个 `.op-msg` 容器内，PRD 要求三栏独立展示、空栏不占位、换行保留。
- 当前作业 item 是纯 `<span>`，未处理“仍存活内容可点击跳转”的学员端差异。
- 当前样式 `my-homework.module.css` 与 `my-homework.html` 差异较大，需按设计稿重构为直列记录。

### 2.3 登录后进入访客页面的初步根因判断

已看到的相关代码：

- `frontend/app/login/LoginForm.js`
  - 登录成功后 `redirectByRole('user')` 会跳 `/`，表面看跳转规则符合 PRD。
  - 登录前检查已有会话时调用 `fetchCurrentViewer()`。
  - 游客入口会 `setGuestMode(true)` 后跳 `/tracks`。
  - 登录成功会 `clearGuestMode()`，理论上会清理游客模式。

- `frontend/lib/api.js`
  - `fetchCurrentViewer()` 当前顺序是先查 `/user/me`，失败后查 `/admin/me`，再兜底 guest。
  - 这部分表面上也符合“学员优先”。

- `frontend/app/page.js`
  - 首页初始化只查 `/user/me`，如果失败直接 `router.replace('/tracks')`。
  - 如果 `/user/me` 因 cookie 未带上、cookie 名错误、后端 session 未写入、代理路径不一致而失败，页面会直接跳到 `/tracks`，用户就会看到访客可访问页面。

因此，优先排查方向：

1. 登录接口 `/api/auth/login` 对学员登录后是否写入了 `/user/me` 能识别的 cookie。
2. `loginByAccount()` 返回 role 为 `user` 后，浏览器是否真正保存了学员 cookie。
3. 登录成功后是否仍保留游客模式本地状态，导致导航或页面表现为 guest。
4. `/` 页面 catch 后直接跳 `/tracks` 是否掩盖了真实鉴权错误，需要改成更明确的登录态错误处理或重试当前 viewer。
5. AppNav 的 role 是否被传成 `guest`，或 `/tracks` 页通过 `fetchCurrentViewer()` 得到 guest。

## 3. 目标方案

### 3.1 首页 `/` 整改方案

#### 页面结构

按 `student-home.html` 重建为：

```txt
AppNav（role=user）
main.home
  stop-banner（仅 disabled 学员显示）
  .cols
    左：section.requirement-sec
      .sec-head h2 作业要求
      .req-stack
        article.req-card 练习要求
        article.req-card 提交要求
    右：section.assignment-sec
      .sec-head h2 今天你需要用到的学习资源 + meta
      .grid 学习资源卡片
```

#### 数据口径

- 从 `GET /api/user/assignments/today` 读取当前有效作业。
- 作业内容：过滤 `object_type` 存在、不是 `message`、且有 `navigation_url` 的内容项。
- 练习要求：从最新有效作业记录中取 `practice_requirement`，多个记录时需要保持后端返回顺序，不混成“留言”。
- 提交要求：从最新有效作业记录中取 `submit_requirement`，与练习要求分开。
- 如果某一项为空，则对应卡片不显示或显示空态需按设计稿/PRD决定；PRD写“空框不显示内容，不影响另一个框”，实现上应优先：有内容显示卡片，无内容不占位；两个都空时左侧显示轻量空态。

#### 交互与视觉

- 卡片 hover 出“开始学习”。
- 合集显示“合集”标签；单 P 显示 `P` 标签并使用父单课封面。
- 空作业显示设计稿文案：`今天还没有作业` / `去曲目库和图书馆逛逛，或查看历史作业复习`。
- 停用 banner 文案逐字按 PRD §8。
- 移除明信片 / 作业细则 / 老师留言板样式。

### 3.2 我的历史作业 `/my-homework` 整改方案

#### 页面结构

按 `my-homework.html` 重建为：

```txt
AppNav（role=user）
main.home
  .toolrow
    h1 我的历史作业
    .hint 共 N 条记录 · 按时间倒序
  stop-banner（仅 disabled 学员显示）
  section.zone
    .rec-list
      .hw-item * N
    .rec-empty
  button.to-top
```

#### 单条记录结构

每个 operation 渲染为一条 `.hw-item`：

```txt
.hw-tm
  .tm HH:mm
  .lb 今天 / 9月6日
.hw-main
  .hw-from <老师昵称>老师 · 布置
  .hw-items 作业内容列表
  .hw-msg-pair
    .hw-msg-line 练习要求
    .hw-msg-line 提交要求
  .hw-delnote（如后端返回删除信息）
```

#### 数据与点击规则

- 数据源：`GET /api/user/assignments/history`。
- 排序：按 operation 创建时间倒序，依赖后端返回；前端不二次按日期合并。
- 每条 operation 内的 items：
  - 有 `navigation_url` 且内容仍存活：渲染为可点击链接。
  - 无 `navigation_url`：渲染为纯文本快照。
- 保留练习要求和提交要求原始换行。
- 空栏目不占位。
- 删除记录如果后端提供删除信息，整条变灰并显示删除说明；如果后端当前不返回，计划先保留样式和兼容字段，不强造数据。

### 3.3 登录后进入访客页面修复方案

#### 排查步骤

1. 用接口脚本验证 `/api/auth/login` 学员账号登录后：
   - 返回 role 是否为 `user`；
   - `set-cookie` 是否包含学员 cookie；
   - 携带该 cookie 调 `/api/user/me` 是否 200；
   - 调 `/api/admin/me` 是否不会误判为 admin。

2. 用浏览器行为验证：
   - 登录页提交学员账号后是否跳 `/`；
   - `/` 是否成功渲染 `AppNav role=user`；
   - localStorage/sessionStorage 中游客模式是否被清理。

3. 检查后端 `/api/auth/login` 是否同时兼容 users/admins，且学员登录写入的是 user cookie，不是 admin cookie。

#### 可能修改点

- 如果 `/api/auth/login` 没有正确写 user cookie：修后端登录路由。
- 如果前端登录后未清理游客模式：补充 `clearGuestMode()` 和必要的状态刷新。
- 如果 `/` 页面鉴权失败直接跳 `/tracks` 导致误入访客页：改为更明确的处理：
  - 先调用 `fetchCurrentViewer()` 判断真实角色；
  - user 留在 `/`；
  - teacher 跳 `/admin/users`；
  - super_admin 跳 `/tracks`；
  - guest 才跳 `/tracks` 或 `/login`，避免把学员 cookie 短暂读取失败误判为访客。
- 如果 AppNav 在内容页未使用真实 viewer：统一以 `fetchCurrentViewer()` 结果设置 role。

## 4. 实施顺序

### P0：登录态与访客页问题

1. 接口验证 `/api/auth/login` → `/api/user/me` 的 cookie/session 链路。
2. 修复导致学员被识别为 guest 的根因。
3. 确保学员登录后进入 `/`，页头显示学员导航：`首页 / 曲目区 / 知识点区 / 图书馆 / 我的历史作业`。
4. 确保游客入口仍进入 `/tracks`，且没有首页/历史作业入口。

### P1：首页视觉与字段重构

1. 重构 `frontend/app/page.js`：拆分作业内容、练习要求、提交要求。
2. 重构 `frontend/app/home.module.css`：按设计稿使用 `.req-stack / .req-card / .req-text`。
3. 移除 `letter / 作业细则 / lt-* / pc-*` 旧结构。
4. 处理空态、停用态、加载态。

### P2：历史记录页视觉与字段重构

1. 重构 `frontend/app/my-homework/page.js`：从 timeline 改为 `.rec-list / .hw-item`。
2. 重构 `frontend/app/my-homework/my-homework.module.css`：按设计稿直列记录样式。
3. 历史 items 支持“有链接可点击 / 无链接纯文本”。
4. 练习要求、提交要求分行独立展示。
5. 保留回到顶部按钮。

### P3：验证与回归

1. 后端语法检查。
2. 前端构建。
3. Docker 重启 frontend/backend。
4. 验证：

   - 游客入口落 `/tracks`。
   - `/` 学员首页 200，数据和布局正确。
   - `/my-homework` 历史作业 200，记录按 operation 倒序。
   - 停用学员首页和历史页文案逐字正确。
   - 老师/教导主任访问 `/`、`/my-homework` 不渲染学员页面。

## 6. 风险与注意事项

1. 不要把学员首页做成游客也能看的页面；游客没有首页。
2. 不要把练习要求和提交要求再次合并成“留言 / 作业细则”。
3. 不要在历史页按日期合并 operation；同一天多次推送必须逐条展示。
4. 不要破坏老师 / 教导主任学生管理页的历史记录数据口径。
5. 不要改动作业推送重复逻辑：同一作业允许在不同教学阶段重复布置，只需本次选择内去重。
6. 不要将前端隐藏入口作为权限控制；后端鉴权仍是最终安全边界。
