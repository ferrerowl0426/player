## 一、目标与结论

将学生播放视频、读取图片及下载资料的访问，从 COS 源站直链切换到腾讯云 CDN 自定义加速域名；上传和转码内部读写仍直接访问对象存储，不经过 CDN，也不经过业务服务器中转大文件。

建议加速域名：`media.nxhguitar.com`（拟定，需确认可用并完成配置），业务 API 仍为 `api.nxhguitar.com`，Web 域名不变。Web 与小程序共享同一套媒体地址生成和访问鉴权逻辑。

访问链路：

```text
Web / 小程序 → 业务 API：登录、课程授权、请求播放地址
Web / 小程序 → media.nxhguitar.com：视频播放、图片、资料下载
                      ↓ CDN 缓存未命中
                   腾讯云 COS 源站

管理员上传 → 后端申请预签名 URL → 浏览器直接 PUT/分片上传 COS
转码服务   → 直接读取/写入 COS → API 返回 CDN 播放 URL
```

**重要：CDN 不会让观看流量消失。** 用户仍消耗 CDN 下行流量，未命中缓存还会产生 COS CDN 回源流量、请求费用等。只有最终媒体请求真正访问 CDN 域名，才能从 COS 直链外网下行切到 CDN 分发。只开通 CDN、买流量包或配置 CNAME，不改播放地址，都不能实现目标。

## 三、费用模型与预期

### 3.1 计费区别

- 现状：COS → 学生，通常计 COS 外网下行流量。
- 接入后：CDN → 学生计 CDN 下行流量；COS → CDN 缓存节点计 COS CDN 回源流量。
- 仍可能产生 COS 存储、GET 请求、数据处理/转码、低频取回等费用。
- COS 外网下行流量包、COS CDN 回源流量包、CDN 下行流量包不是同一种资源包，不能假定通用。选购前核实产品、地域、有效期和抵扣范围。
- 本方案采用腾讯云 CDN + COS；若账号实际接入 EdgeOne，应重新按 EdgeOne 套餐/计费及鉴权能力核对，不混用配置和资源包。

### 3.2 估算方法

设月实际媒体交付量为 D GB，回源字节比例为 R：

```text
直链费用 ≈ D × COS外网下行单价 + 请求等费用
CDN费用  ≈ D × CDN下行单价 + D × R × COS回源单价 + 请求等费用
```

R 必须取实际字节统计，不使用“请求命中率”直接代替。预热、多节点重复缓存、拖动、缓存淘汰会影响实际回源量。不能承诺固定节省比例。

观看量粗估：码率为 b Mbps，观看 h 小时，流量约 `b × 3600 × h / 8 / 1024` GiB（十进制 Mbps 换算），再加音轨、协议及重试开销。例如 2 Mbps、1 小时约 0.84 GiB，100 名学生各看 10 小时约 838 GiB；只作量级示例，不代表当前编码码率或报价。

## 四、云端控制台配置计划

### 4.1 域名、源站、HTTPS

1. 确认账号已有 CDN 开通资格及可用产品；加速区域初期按实际学生地区选择中国境内，避免无必要的全球开销。
2. 确认 `nxhguitar.com` 备案状态及域名使用权；准备 `media.nxhguitar.com` 的有效 HTTPS 证书。
3. 在 COS 的域名与传输管理或 CDN 域名管理中添加自定义加速域名，业务类型选择适合音视频点播/大文件分发的类型，以当前控制台名称为准。
4. 源站类型明确选择腾讯云 COS，并选择真实桶与地域；源站不是 Web 服务器，不是 CDN 自己，也不应指向无关的静态网站 endpoint。
5. 根据私有桶配置 CDN 服务授权与回源鉴权，使用最小权限；回源 Host 等按官方 COS 接入向导设置，不臆造参数。
6. 部署 HTTPS 证书，启用 HTTP→HTTPS，配置安全的回源协议。
7. 将 `media` 的 CNAME 指向控制台分配的值。不要另加同名 A 记录，也不要把 CNAME 目标本身发给客户端作为访问地址。
8. 测试 DNS 和 TLS、对象存在性及 200/206 响应后，才切换 API 地址。

### 4.2 缓存与大文件配置

| 对象类型 | 建议初始规则 | 说明 |
|---|---|---|
| UUID命名 MP4、转码 MP4 | CDN缓存30天起，观察后调整 | 替换资源生成新 key，不覆盖同路径 |
| UUID封面、静态图片 | CDN缓存7～30天 | 覆盖旧路径时主动刷新 |
| 附件/PDF | CDN缓存7天起 | 下载响应头与鉴权必须同时正确 |
| 401/403 | 不缓存或零 TTL | 防止授权失败污染缓存 |
| 404 | 短 TTL，如30秒，验证控制台支持 | 上传发布后避免长时间负缓存 |
| 业务 API、登录接口 | 不接入此媒体CDN缓存 | 用户数据和课程授权不得缓存共享 |

- 开启并验收 **Range 回源**，COS 需正确返回 `Accept-Ranges`、`Content-Range` 和 206，避免拖动少量片段却回源完整大视频。
- 缓存键忽略 CDN 时间戳签名等纯鉴权参数，但鉴权仍必须在每次边缘请求时执行；不能用“忽略参数”绕过访问控制。
- 图片处理、版本、响应头变体等会影响内容的参数不可无脑丢弃；分类制定允许参数规则。未经验证不启用“所有参数全忽略”。
- CDN 缓存 TTL 与客户端浏览器缓存期限分开管理；受保护视频不要盲目对客户端下发一年 immutable。
- 热门课程仅按需预热，不预热全部历史视频；频繁刷新/预热可能增加回源量。
- 初期沿用 MP4 与当前播放器，不以接 CDN 为由同时改造 HLS。后续若采用 HLS，清单、分片、密钥都要覆盖鉴权与域名配置。

### 4.3 跨域和响应头

- Web 媒体 CDN 放行实际 Web Origin：`https://nxhguitar.com`、`https://www.nxhguitar.com`；开发环境单独配置，不把测试来源混进生产规则。
- 按实际请求支持 GET/HEAD/OPTIONS、Range；需要脚本读取时暴露 Content-Length、Content-Range、Accept-Ranges、ETag、Content-Disposition。
- 回显 Origin 时正确处理 Vary/缓存变体，避免把某个来源的 CORS 响应错误共享给另一个来源；不同时配置通配 Origin 和凭据。
- 媒体签名 URL 优先不依赖跨域 Cookie，API 自身的 Cookie/CORS 行为保持独立。
- 上传 COS 的 CORS 单独保留 PUT、分片签名所需头和 ETag 暴露；不要用媒体 CDN 的只读规则覆盖上传规则。

## 五、访问安全：必须区分两种鉴权

1. **CDN 回源鉴权**：证明 CDN 有权从私有 COS 取文件，保护源站。
2. **CDN URL 鉴权**：证明学生持有尚未过期的分发 URL，保护边缘缓存。

只开回源鉴权、不加 CDN URL 鉴权，缓存仍可能被任意人访问。只加 CDN 鉴权、桶仍公有读，别人仍可绕过 CDN 使用 COS 链接。

推荐目标：私有 COS + CDN 回源授权/鉴权 + CDN URL 鉴权 + 后端课程权限校验。

- 服务端统一生成 CDN 签名 URL，签名算法与参数严格匹配最终选定的腾讯云 CDN 鉴权类型，不自创签名格式。
- 申请 URL 时验证登录、账号状态、班级/课程/资料权限；不要只验证“已登录”。
- 密钥仅存在后端环境配置，不进入 NEXT_PUBLIC_*、小程序包、数据库公开字段或日志。
- URL 不永久存入数据库；数据库保存稳定 object key/资源ID，签名 URL 在返回时生成，并返回 expiresAt。
- 时效以最长课程及暂停/拖动行为测算，初始可评估2～4小时；它不是最终固定值。支持过期前续签、恢复播放进度、403后最多一次刷新重试，防无限重试。
- 视频原生组件可能不能可靠区分403，需要结合到期时间及播放错误做续签。IP绑定初期不启用，避免移动网络切换导致中断。
- URL仍可能在有效期内被转发；CDN鉴权不等于 DRM，也不能阻止所有录屏或已下载内容传播。
- Referer只能作为辅助规则；微信端 Referer/空 Referer 行为需真机验证，不直接照搬Web白名单封掉小程序。
- 私有化前盘点所有对象消费者：Web、小程序、转码/数据万象任务、回调、缩略图、旧版客户端、管理员下载及第三方处理。不能先关闭公有读再修客户端。
- 若图片需公开、视频需私有，可采用分桶或最小权限对象策略；不要为了课程视频把必要公共封面一并意外封禁。

## 六、后端改造计划（两端共用）

### 6.1 配置隔离

保留：`S3_ENDPOINT`、`S3_PUBLIC_ENDPOINT`、桶名、地域及SDK凭证用于源站操作。现有 `PUBLIC_BUCKET_BASE_URL` 与 CDN 切换有关，但不能直接全局替换后就上线。

建议新增集中配置（拟定名称，当前未实现）：

```dotenv
MEDIA_CDN_ENABLED=false
MEDIA_CDN_BASE_URL=https://media.nxhguitar.com
MEDIA_CDN_AUTH_ENABLED=false
MEDIA_CDN_SIGN_KEY=<仅服务端安全注入>
MEDIA_CDN_URL_TTL_SECONDS=14400
```

签名类型按控制台定稿后增加对应配置；示例不含真实密钥。开发 MinIO 保持关闭 CDN。

服务器配置以 `/root/player/.env` 为准；后端 `backend/.env` 不作为 Docker 生产配置源。修改配置后重新创建后端容器，不仅 restart；若引入前端构建变量则须另行重建前端。本方案优先让客户端消费 API URL，避免两端硬编码媒体域名。

### 6.2 稳定 key、旧链接兼容

- 审计 `normalizePublicUrl()` 的所有调用点和API序列化路径，统一“object key → 可访问地址”的服务层。
- 对历史完整 URL，只匹配明确允许的本项目 COS 域名/旧域名，并验证桶名及路径前缀，提取 key 后生成 CDN 地址。
- 保留对象路径大小写、正确处理中文、空格和编码，不重复 encode；去除旧 COS 签名，再按 CDN 规则签名。禁止对任意外部 URL 全局 replace。
- 有稳定 file_key/video key 的记录优先使用 key；缺失时可从确认可信的历史 URL 提取。外部资料链接保持独立策略。
- 清点并覆盖：tracks、knowledge、library、attachments、covers、videos旧模块、transcoded/720p和1080p，以及集合/前置资料接口。
- 重点修改 `transcode.js` 对“当前publicUrl精确匹配数据库”的依赖，改为稳定 key/任务ID/记录ID定位并补测试，防止切换域名后任务找不到视频。
- 优先运行时兼容，不批量覆盖历史URL。确需回填 key，先只读统计、备份数据库、幂等迁移并保留回滚字段。
- Web API 与小程序 API 均由同一媒体地址服务处理，避免一端走 CDN、一端仍是 COS。

### 6.3 下载不再预览的补齐

现有Web移除预览按钮，但HTML `download` 对跨域 URL 不保证生效，且 `finalizePdfInlineMetadata()` 当前设置 inline。

实施时为附件/图书馆下载提供明确 `Content-Disposition: attachment`，正确编码中文 filename/filename*；可使用独立下载域名/路径和固定响应头策略，或经验证且纳入正确缓存键的响应参数方案。视频仍保持 video/mp4，不全桶改 attachment。

下载接口只返回/重定向到经授权的 CDN URL，不由 Express/CVM 中转整个 PDF 或视频。旧对象元数据或缓存头变更后按对象刷新 CDN，验收旧文件也触发下载。禁止依赖将COS预签名URL的域名换成CDN来实现下载。

## 七、Web端实施计划

## 八、微信小程序实施计划

1. 保留 `miniprogram/utils/constants.js` 的业务API地址；后端小程序接口返回CDN资源URL。

- [ ] 切换用户、未登录、停用账号和无课程权限不能申请新播放链接。
- [ ] 长暂停、链接过期后可以续签并恢复进度，无无限刷新。

- [ ] 小程序体验版和正式环境合法域名校验、iOS/Android播放与下载通过。
- [ ] 直接COS匿名访问在安全收口后失败；SDK上传/分片/转码仍可用。
- [ ] CDN日志/统计有真实请求与流量，重复请求在相同缓存节点可命中；不把浏览器自身缓存当成CDN命中。
- [ ] COS直链下行下降；仍有流量时定位旧版本、外部链接、转码或漏网媒体字段。
- [ ] 记录CDN下行字节、回源字节、字节命中率、4xx/5xx、首帧时间、卡顿率和成本，而不只看域名访问成功。

可由实施人员执行的诊断样例（签名URL从授权API取得，不把真实签名写日志或提交仓库）：

```bash

```

安全阶段无签名返回403是预期；命中判定以控制台日志及实际产品返回的缓存头为准，不假设所有环境都有同一个X-Cache字段。

## 十一、告警、风险与回滚

- 设置预算、日流量、峰值带宽和异常4xx/5xx告警；阈值按基线设定。并发限速需考虑学校同一出口共享IP，避免误伤整班。
- 若配置用量封顶，确认超限行为是阻断还是回源；不允许超限后静默回COS直链继续烧钱。告警不等于硬停机，停止域名也可能有延迟和已产生费用。
- 不建议播放失败自动回退COS公开直链：会绕过权限、破坏流量目标且隐藏CDN故障。
- 保持运行时切换开关与灰度白名单；回滚时回到受控的COS签名访问模式，不重新公开整桶。私有化后的回滚须保证源站签名API可用。
- 回滚不删除对象、不更换key、不批量改写数据库；上传endpoint全程不动。
- 中国境内加速需要满足域名备案等要求，证书到期、DNS错误、CORS、鉴权时钟偏差、旧客户端是重点风险。
