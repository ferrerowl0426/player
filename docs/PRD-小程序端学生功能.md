> 版本：v0.4（UI 冻结收尾；面向程序员的分阶段开发计划 + 交接文档）  
> 日期：2026-10-03  
> 范围：仅新增微信小程序端；网页端仍作为老师和教导主任办公端。  
> 关联文档：`README-miniprogram.md`（小程序交接文档）、`docs/PRD.md`、`README.md`、`test-data/README.md`、`docs/design/guitar-home/miniprogram-student.html`

## 1. 背景与问题

当前网页端已经覆盖曲目区、知识点区、图书馆、学生首页、历史作业等功能，但网页端主要是桌面优先设计。学生实际使用场景更偏手机端：在微信里查看老师布置的作业、播放课程视频、下载资料、回看历史记录。

本期目标是新增一个**只面向学生的小程序端**，把网页端学生能力移动化。老师和教导主任仍然使用电脑网页端办公，小程序端不提供老师后台、内容管理、班级管理、作业布置等功能。

---

## 2. 产品定位

小程序定位为：

> 面向固定学生的学习记录与课程查看工具。

核心原则：

1. **只做学生端**：学生查看课程、作业、资料、历史记录。
2. **不做公众注册**：学生账号由网页端老师 / 教导主任维护，不开放公众自助注册。
3. **不做老师办公**：老师布置作业、查看学生、上传资料仍在电脑网页端完成。
4. **不做交易和广告**：不展示广告，不做课程售卖，不做支付，不做会员充值。
5. **复用现有数据**：小程序读取现有网页端同一套内容、作业、图书馆和学生账号数据。

---

## 3. 用户与角色

| 角色 | 是否使用小程序 | 说明 |
|---|---:|---|
| 学生 | 是 | 查看课程、今日作业、历史作业、下载资料 |
| 老师 | 否 | 使用电脑网页端办公，负责布置作业和管理本班学生 |
| 教导主任 | 否 | 使用电脑网页端管理内容、资料、班级和账号 |
| 游客 | 可选，默认不开放 | 如需过审展示，可提供只读演示页；正式业务不面向公众开放 |

### 3.1 登录口径

用户说法是“不需要用户注册登录”，本 PRD 按以下口径处理：

- **不提供公众注册入口**。
- **不提供学生自行创建账号**。
- **不做微信 openid 绑定**。
- **不做绑定码 / 邀请码 / 解绑流程**。
- 学生账号仍由网页端老师 / 教导主任提前创建。
- 学生在小程序端使用已有的**手机号 / 账号 + 密码**进入。
- 小程序可在本机安全保存会话状态，减少重复输入；但这只是“保持登录”，不是微信身份绑定。

登录表单字段：

| 字段 | 说明 |
|---|---|
| 手机号 / 账号 | 对应 `users.account`，纯数字账号 |
| 密码 | 对应学生账号密码 |

登录成功后进入学生首页；退出登录后回到登录页。

## 4. 目标

### 4.1 用户目标

1. 学生打开小程序后，能快速看到老师最新布置的作业。
2. 学生点击作业内容后，能自动跳转到对应课程、合集或分 P 视频。
3. 学生能浏览曲目区、知识点区、图书馆资料。
4. 学生能下载或打开附件资料，包括 PDF、JPG、MP3 等。
5. 学生能查看历史作业记录，理解老师过去布置过什么、练习要求是什么、提交要求是什么。

### 4.2 业务目标

1. 降低学生访问门槛，让学生主要通过微信使用学习功能。
2. 保持老师和教导主任办公流程不变，避免移动端后台增加复杂度。
3. 复用已有内容和作业数据，减少重复建设。
4. 为后续正式上线和小程序审核建立清晰的功能边界。

---

## 5. 非目标

本期明确不做：

1. **不做老师端小程序后台**：不在小程序里布置作业、管理学生、上传课程。
2. **不做教导主任端小程序后台**：不在小程序里新建曲目、知识点、图书馆资料或班级。
3. **不做公众注册**：学生不能自己注册账号。
4. **不做线上交易**：不做支付、会员、课程购买、价格展示。
5. **不做广告和推广**：不接广告，不做营销弹窗，不诱导分享。
6. **不做社交社区**：不做评论区、论坛、动态、点赞、排行榜。
7. **不做作业上传提交**：若后续需要学生上传练习视频，另起版本评估；本期只查看作业要求和课程资料。

## 6. 信息架构

小程序底部 Tab 按 UI 设计稿采用 5 个入口：

| Tab | 页面 | 说明 |
|---|---|---|
| 首页 | 最新作业 / 学习首页 | 显示学生信息、最新一次作业、练习要求、提交要求，支持一键跳转 |
| 课程 | 曲目区 + 知识点区 | 浏览单科、合集，搜索并进入课程详情 |
| 资料 | 图书馆 | 查看资料列表、进入资料详情、打开或下载资料 |
| 历史 | 历史作业 | 按时间倒序查看过往作业记录 |
| 我的 | 账号状态 / 使用说明 | 显示学生昵称、班级、停用提示、退出登录 |

非 Tab 页面：

| 页面 | 入口 | 说明 |
|---|---|---|
| 学生登录页 | 未登录 / 退出登录后 | 使用手机号 / 账号 + 密码进入小程序 |
| 单曲目详情页 | 作业、课程列表、合集详情 | 播放视频、切换分 P、查看附件和关联资料 |
| 单知识点详情页 | 作业、课程列表、合集详情 | 与单曲目详情同构 |
| 曲谱集详情页 | 作业、课程列表 | 查看收录曲目和合集资料 |
| 知识点集详情页 | 作业、课程列表 | 与曲谱集详情同构 |
| 资料详情页 | 资料列表、课程详情附件 | 获取短时链接并打开资料 |
| 音频播放页 | MP3 附件 / MP3 资料 | 播放、暂停、拖动进度、倍速和下载音频 |

## 7. 页面级功能需求（按小程序 UI 设计稿重写）

> 本节以 `docs/design/guitar-home/miniprogram-student.html` 为页面依据。设计稿中“学生绑定”页在本 PRD 中按已确认口径改为“学生登录页”：不做微信 openid 绑定、不做绑定码、不做邀请码，学生使用已有手机号 / 账号 + 密码登录。

### 7.1 学生登录页

#### 页面目标

让固定学生使用网页端已创建的账号进入小程序；不提供公众注册、微信绑定、找回密码或邀请码入口。

#### 页面结构

- 顶部标题：`学生登录`。
- 主卡片标题：`进入学习记录`。
- 说明文案：本小程序仅供已创建账号的固定学生使用；没有账号或忘记密码请联系老师。
- 表单字段：
  - 手机号 / 学生账号：对应 `users.account`。
  - 密码：对应学生账号密码。
- 主按钮：`登录并进入`。
- 辅助说明：不开放公众注册；账号由老师或教导主任在网页端创建。

#### 交互规则

- 登录成功：进入首页。
- 已保持会话：再次打开小程序直接进入首页，不展示登录页。
- 退出登录：清除小程序本机会话，回到登录页。
- 登录失败：在表单下方提示“账号或密码错误，请联系老师确认账号”。
- 账号不存在：提示“无法识别该学生，请联系老师确认账号”。
- 账号停用：允许进入，但首页和我的页展示停用提示。

#### 禁止事项

- 不展示“注册”“立即报名”“购买课程”“微信一键登录”“绑定微信”“绑定码”“邀请码”“解绑”等入口。
- 不调用微信手机号授权接口。
- 不新增 `openid`、`unionid`、`bind_code`、`invite_code` 等字段。

#### 验收标准

- [ ] 学生可用手机号 / 账号 + 密码登录。
- [ ] 没有注册、绑定、邀请码相关入口。
- [ ] 登录失败提示清晰，不泄露数据库或系统错误。
- [ ] 已登录学生再次进入可保持会话。
- [ ] 退出登录后回到登录页。

---

### 7.2 首页 / 最新作业页

#### 页面目标

学生打开小程序后，第一眼看到自己的班级、最新一次作业、练习要求和提交要求，并能快速跳转到课程、历史作业或课程列表。

#### 页面结构

- 顶部标题：`首页`。
- 学生欢迎卡：
  - 学生昵称。
  - 班级名称。
  - 作业状态文案，例如“今日作业已更新”。
- 快捷入口：
  - `历史作业`：跳转历史页。
  - `去课程页`：跳转课程 Tab。
- 停用提示条：仅停用学生展示，文案为“账号已停用，如需继续学习请联系老师。停用期间仍可浏览课程、资料和历史记录。”
- 最新作业卡：
  - 标题：`最新作业`。
  - 右侧显示布置时间。
  - 作业内容列表，按一次推送的 `operation_id` 聚合展示 1~5 个内容。
- 练习要求卡：展示 `practice_requirement`。
- 提交要求卡：展示 `submit_requirement`。

#### 作业内容卡规则

每个作业内容卡展示：

- 封面。
- 类型标签：单曲 / 合集 / P / 知识点 / 知识点集。
- 标题：最多两行，超出省略。
- 副文案：提示点击后的行为，例如“点击自动定位并播放 P2”。
- 分 P 内容需展示 P 标识，例如 `P2`。

#### 自动跳转规则

| 作业类型 | 点击后跳转 |
|---|---|
| `track_collection` | 曲谱集详情页 |
| `track_point` | 单曲目详情页，默认播放第一个 P |
| `track_part` | 单曲目详情页，并自动定位 / 播放对应 P |
| `knowledge_collection` | 知识点集详情页 |
| `knowledge_point` | 单知识点详情页，默认播放第一个 P |
| `knowledge_part` | 单知识点详情页，并自动定位 / 播放对应 P |

#### 长文本规则

- 练习要求和提交要求默认最多展示三行高度。
- 超出时显示 `展开全文`。
- 展开后显示全文，并可 `收起`。
- 如果采用内部滚动，滚动区域不能影响整页滚动体验。

#### 空态与异常态

- 无最新作业：显示“还没有收到作业，等老师布置后会显示在这里。”
- 最新作业中部分源内容删除：今日作业不展示该内容，避免死链。
- 一次推送全部内容都已删除：显示空态，不展示不可点击死链。
- 作业接口失败：显示“作业加载失败，请稍后重试”。

#### 验收标准

- [ ] 首页学生卡、快捷入口、最新作业、练习要求、提交要求均按设计稿展示。
- [ ] 一次推送多个内容时聚合展示，不拆成多次作业。
- [ ] 点击合集、单科、分 P 跳转正确。
- [ ] 长练习要求 / 提交要求不会撑坏页面。
- [ ] 停用学生能看到停用提示，仍可浏览课程、资料和历史。

### 7.3 课程列表页

#### 页面目标

学生能在移动端浏览曲目区和知识点区内容，快速搜索课程，并进入单科或合集详情。

#### 页面结构

- 顶部标题：`课程`。
- 搜索框：placeholder 建议为 `搜索课程名称`。
- 分段切换：
  - `曲目区`
  - `知识点区`
- 曲目区展示两组：
  - `单曲目`
  - `曲谱集`
- 知识点区展示两组：
  - `单知识点`
  - `知识点集`
- 列表采用双列卡片布局。
- 底部 Tab：首页 / 课程 / 资料 / 历史 / 我的，当前高亮课程。

#### 卡片展示规则

单科卡片展示：

- 封面图。
- 类型标签：单曲 / 知识。
- 标题：最多两行。
- 副信息：`N 个 P · N 个附件`，没有附件时只显示 P 数。

合集卡片展示：

- 封面图。
- 类型标签：合集 / 知识点集。
- 标题：最多两行。
- 副信息：`收录 N 首` 或 `收录 N 个知识点`。

#### 搜索规则

- 支持按单科、合集、分 P 名称搜索。
- 搜索结果仍按当前分段展示，不能把曲目和知识点混在一个无分类列表里。
- 无结果显示“没有找到相关课程”。
- 清空搜索词后恢复默认列表。

#### 加载规则

- 默认按更新时间倒序。
- 支持下拉刷新。
- 支持触底加载更多。
- 加载中使用轻量 loading，不遮挡已加载内容。

#### 验收标准

- [ ] 曲目区 / 知识点区可切换。
- [ ] 单曲目、曲谱集、单知识点、知识点集均可展示。
- [ ] 搜索可命中单科、合集和分 P。
- [ ] 点击卡片进入对应详情。
- [ ] 列表在手机端无横向滚动。

### 7.4 单曲目 / 单知识点详情页

#### 页面目标

学生能播放单曲目或单知识点视频，切换分 P，查看附件资料、关联图书馆资料和前置学习内容。

#### 页面结构

- 顶部标题：`课程详情`。
- 返回按钮。
- 视频播放器区域。
- 课程信息卡：
  - 标题。
  - 当前清晰度，例如 `720p`。
  - 简介 / 作业跳转说明。
- P 列表卡：
  - 标题：`P 列表`。
  - 右侧显示当前 P，例如 `当前 P2`。
  - 每个 P 展示 P 序号、标题、时长。
- 附件资料卡：PDF / JPG / MP3 等附件。
- 关联图书馆资料卡：展示直接关联资料 + 所属合集继承资料的并集。
- 前置学习卡：展示前置知识点 / 前置曲目。

#### 分 P 定位规则

- 从作业中的分 P 点击进入时：
  - 自动进入父单科详情页。
  - 自动选中对应 P。
  - 页面滚动到视频区域。
  - 默认播放该 P，或至少把该 P 标记为当前 P。
- 从单科卡片进入时：默认选中 P1。
- 切换 P 时：更新视频、当前 P 标记和标题状态。

#### 视频播放规则

- 默认播放可用清晰度，首版可默认 720p。
- 如后端返回 720p / 1080p，可在后续版本加清晰度切换；本期不强制。
- 支持全屏播放。
- 视频加载失败提示“视频加载失败，请检查网络后重试”。
- 不要求记录播放进度。

#### 附件与资料规则

- 附件列表展示文件类型标签、文件名、动作按钮：打开 / 预览 / 播放。
- PDF：调用微信文件预览。
- JPG / PNG：调用图片预览。
- MP3：进入音频播放页或调用音频播放能力。
- 关联图书馆资料必须去重：同一本资料如果既直接关联单科，又继承自合集，只展示一次。

#### 验收标准

- [ ] 视频可播放，P 列表可切换。
- [ ] 作业分 P 跳转能自动定位到对应 P。
- [ ] 附件资料可打开或有明确失败提示。
- [ ] 关联图书馆资料展示直接关联与合集继承的并集，且不重复。
- [ ] 前置学习内容可点击进入对应详情。

### 7.5 合集详情页

#### 页面目标

学生能查看曲谱集 / 知识点集的信息、收录内容和合集资料，并进入具体单科继续学习。

#### 页面结构

- 顶部标题：`合集详情`。
- 返回按钮。
- 合集信息卡：
  - 封面。
  - 类型标签：合集 / 知识点集。
  - 合集名称。
  - 合集简介。
- 收录内容卡：
  - 标题：`收录内容`。
  - 右侧显示数量，例如 `30 首` / `12 个知识点`。
  - 内容行展示类型、标题、进入按钮。
- 合集资料卡：
  - 展示 PDF / JPG / MP3 等资料。
  - 来源为合集直接关联的图书馆资料或附件。

#### 交互规则

- 点击收录内容进入对应单曲目 / 单知识点详情。
- 如果收录内容已删除，不展示在当前合集详情中。
- 合集资料打开规则同资料页和附件资料规则。
- 合集简介过长时最多展示若干行，可展开查看全文。

#### 验收标准

- [ ] 曲谱集和知识点集都可复用该页面结构。
- [ ] 合集封面、名称、简介、收录数量展示正确。
- [ ] 收录内容可进入单科详情。
- [ ] 合集资料可打开或预览。

---

### 7.6 资料列表页

#### 页面目标

学生能浏览图书馆资料，搜索资料名称，并根据文件类型进行预览、播放或下载。

#### 页面结构

- 顶部标题：`资料`。
- 搜索框：placeholder 为 `搜索资料名称`。
- 资料列表：单列资料卡。
- 每张资料卡展示：
  - 文件类型图标：PDF / JPG / MP3 / 其他。
  - 资料标题。
  - 文件类型、大小、打开方式说明。
- 异常态卡：用于展示文件打开失败或暂不支持预览。
- 底部 Tab 当前高亮资料。

#### 资料卡交互

- 点击资料卡进入资料详情页。
- 也可在列表直接触发打开，但首版建议统一进详情，便于展示权限说明和关联课程。

#### 搜索与空态

## 8. 数据与接口设计建议

小程序应尽量复用现有后端能力，但建议为小程序新增 BFF 风格接口，减少小程序端拼装复杂度。

### 8.1 登录与当前学生接口

```txt
POST /api/miniprogram/login
GET  /api/miniprogram/me
POST /api/miniprogram/logout
```

登录规则：

- `login` 使用 `account + password`，对应现有 `users.account` 和 `users.password_hash`。
- 不新增 `openid` 字段。
- 不新增 `wechat_openid`、`unionid`、`bind_code`、`invite_code` 等绑定字段。
- 不新增解绑接口。
- 登录成功后由后端签发小程序学生会话；后续接口通过会话识别当前学生。
- `me` 只返回当前学生本人信息，不允许通过参数查询其他学生。

### 8.2 首页作业

```txt
GET /api/miniprogram/homework/today
```

返回：

- 学生信息
- 最新作业组
- 每组 1~5 个作业内容
- 练习要求
- 提交要求
- 可跳转目标

### 8.3 历史作业

```txt
GET /api/miniprogram/homework/history?page=1&pageSize=20
```

后端负责按 `operation_id` 聚合，返回小程序可直接渲染的数据结构。

### 8.4 课程浏览

```txt
GET /api/miniprogram/tracks
GET /api/miniprogram/tracks/:id
GET /api/miniprogram/tracks/collections/:id
GET /api/miniprogram/knowledge
GET /api/miniprogram/knowledge/:id
GET /api/miniprogram/knowledge/collections/:id
```

### 8.5 资料列表与资料详情

```txt
GET  /api/miniprogram/library
GET  /api/miniprogram/library/:id
POST /api/miniprogram/files/sts
GET  /api/miniprogram/files/:fileId/signed-url
```

`library` 返回资料列表，`library/:id` 返回资料详情、文件信息和关联课程。

文件访问有两个接口，职责区分见 8.8：

| 接口 | 用途 | 是否需要登录 |
|---|---|---|
| `POST /api/miniprogram/files/sts` | 主方案：签发 COS 临时密钥（STS），小程序直连 COS 拉取文件 | 必须 |
| `GET /api/miniprogram/files/:fileId/signed-url` | 降级方案：签发单个文件的对象级预签名 URL | 必须 |

### 8.6 音频播放

MP3 播放、视频播放、PDF 预览、资料下载统一走 8.8 描述的 COS 文件访问方案，不单独设计接口。小程序端负责播放器交互，后端只负责权限校验和凭证签发。

### 8.7 安全要求

- 所有个性化接口必须校验当前学生身份。
- 不允许小程序传 `user_id` 后直接查别人的作业。
- 下载资料时由后端签发短时有效凭证，不返回永久密钥。
- 不在小程序端保存长期敏感凭证。

### 8.8 COS 文件访问与临时密钥（STS）签名方案

本节是文件访问的**唯一权威口径**。小程序端所有视频、音频、PDF、图片、附件的播放与下载，都必须按本节实现，不允许各页面自行拼 COS 地址。

#### 8.8.1 基本原则

```txt
小程序前端
    ↓ ① 请求后端业务接口（必须已登录）
后端
    ↓ ② 用永久密钥（子账号）调用 STS，带最小权限 policy + 有效期
    ↓ ③ 返回临时密钥三元组
小程序前端
    ↓ ④ 带着临时密钥，直接发起请求拉取 COS 文件
COS
```

三条红线：

1. **永久密钥只存在于后端环境变量**，绝不进入小程序代码、接口响应或日志。
2. **临时密钥必须是「最小权限 + 短有效期」**，不是永久密钥的等价物。
3. **签发接口必须绑定登录态**，未登录不允许拿到任何凭证。

#### 8.8.2 接口设计

```txt
POST /api/miniprogram/files/sts
```

请求头：

```txt
Authorization: Bearer <小程序学生会话 token>
```

请求体：

```json
{
  "scene": "library",
  "fileIds": ["12", "34"],
  "ttlSeconds": 900
}
```

字段规则：

| 字段 | 必填 | 说明 |
|---|---|---|
| `scene` | 是 | 只允许白名单值：`library` / `track` / `knowledge` / `attachment` / `video` |
| `fileIds` | 建议必填 | 用于把 policy 的 Resource 收窄到具体对象；为空时按 `scene` 收窄到对应前缀 |
| `ttlSeconds` | 否 | 前端只能传更小的值；后端有上限，不接受前端放大有效期 |

响应：

```json
{
  "credentials": {
    "tmpSecretId": "AKIDxxxxxxxx",
    "tmpSecretKey": "xxxxxxxx",
    "sessionToken": "xxxxxxxx"
  },
  "startTime": 1759999000,
  "expiredTime": 1760000000,
  "bucket": "examplebucket-1250000000",
  "region": "ap-guangzhou",
  "allowPrefixes": ["library/", "attachments/12/"]
}
```

小程序端使用 COS 小程序 SDK（`cos-wx-sdk-v5`）承载临时密钥：

```js
const cos = new COS({
  getAuthorization: (options, callback) => {
    callback({
      TmpSecretId: cred.tmpSecretId,
      TmpSecretKey: cred.tmpSecretKey,
      SecurityToken: cred.sessionToken,
      StartTime: cred.startTime,
      ExpiredTime: cred.expiredTime
    });
  }
});
```

#### 8.8.3 最小权限 policy

后端签发临时密钥时必须附带 policy，只放开「读」能力，并把 Resource 收窄到具体 bucket + 前缀：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "name/cos:GetObject",
        "name/cos:HeadObject"
      ],
      "resource": [
        "qcs::cos:ap-guangzhou:uid/1250000000:examplebucket-1250000000/library/*",
        "qcs::cos:ap-guangzhou:uid/1250000000:examplebucket-1250000000/attachments/*"
      ]
    }
  ]
}
```

明确禁止：

| 禁止项 | 原因 |
|---|---|
| `name/cos:*` | 等于放开全部操作，失去最小权限意义 |
| `PutObject` / `PostObject` / `PutObjectACL` | 学生端只读，不需要写能力 |
| `DeleteObject` | 学生端绝不能删文件 |
| `ListBucket` / `GetBucket` | 防止被枚举全桶文件 |
| Resource 写成 `*` | 会被其他 bucket 或路径复用 |

#### 8.8.4 有效期

| 项 | 建议值 |
|---|---|
| 默认有效期 | 900 秒（15 分钟） |
| 允许区间 | 600 ~ 1800 秒 |
| 腾讯云上限 | 主账号最长 7200 秒（2 小时） |
| 缓存策略 | 后端可短缓存签发结果，但缓存时长不得超过剩余有效期的 1/2 |

有效期要和服务端会话有效期解耦：临时密钥过期只影响文件拉取，不导致学生掉登录。

#### 8.8.5 小程序端如何使用（关键实现约束）

微信小程序的 `wx.downloadFile`、`<video>`、`wx.openDocument` **不能自定义请求头**，因此不能直接把临时密钥塞进这些调用。落地方式是：

| 方式 | 说明 | 建议 |
|---|---|---|
| A. SDK 本地签名 | 小程序引入 `cos-wx-sdk-v5`，用临时密钥在本地生成带签名的对象 URL，再交给下载 / 播放 / 预览 | 主方案 |
| B. SDK 直接取文件 | 用 SDK 的 `getObject` 下载到小程序临时文件，再本地打开 | 大文件或需要缓存的场景 |
| C. 预签名 URL 降级 | 直接调用 `GET /api/miniprogram/files/:fileId/signed-url` 拿现成 URL | SDK 不可用或被审核限制时的兜底 |

另外必须注意：小程序直连 COS，要求把 COS 访问域名加入微信后台的 **downloadFile 合法域名**（视频播放还需要配置对应的媒体域名），否则真机会直接失败，开发者工具里不一定报错。

#### 8.8.6 防盗链配置

COS 控制台 → 存储桶 → 安全管理 → 防盗链设置：

| 配置项 | 建议 |
|---|---|
| 状态 | 开启 |
| 名单类型 | 白名单 |
| 白名单 | 业务网页端域名、`servicewechat.com`、`*.servicewechat.com`、CDN 域名（如果启用） |
| 空 referer | 默认拒绝，但需实测确认 PDF 预览、微信内置浏览器、直接下载等场景 |

必须知道的两点：

1. 小程序发起的网络请求，referer 固定为 `https://servicewechat.com/{appid}/{version}/page-frame.html`，所以白名单必须包含 `servicewechat.com`，否则小程序会被自己的防盗链拦截。
2. 腾讯云官方说明：**带签名的访问不校验防盗链**。也就是说防盗链拦的是「无签名的裸链 / 外站盗用」，它不能替代 STS 最小权限与登录鉴权，第一道防线仍然是「私有桶 + 临时密钥 + 短有效期 + 接口鉴权」。

#### 8.8.7 登录鉴权要求

`POST /api/miniprogram/files/sts` 必须：

1. 走 `miniprogram.auth.js` 校验小程序学生会话，未登录返回 `401`，**不允许匿名签发**。
2. 从会话中取学生身份，**不接受请求体传 `user_id`**。
3. 校验被请求的 `fileId` 确实存在，并尽可能校验其属于该学生的可见范围。
4. 读取学生 `status`；停用学生当前沿用网页端规则（仍可浏览与下载），若产品后续改为禁止，则在此接口拦截。
5. 做频率限制：同一学生 / 同一 IP 每分钟签发次数设上限，防止被当作免费签名服务。
6. 记录签发日志（学生 ID、scene、前缀、有效期、时间），便于排查盗刷。

#### 8.8.8 错误码与降级

| HTTP | 场景 | 小程序处理 |
|---|---|---|
| 401 | 未登录 / 会话过期 | 清除本地会话，跳登录页 |
| 403 | 无权访问该文件 | 提示「当前账号无权查看该内容，请联系老师」 |
| 404 | 文件不存在或已删除 | 提示文件已失效，回到上一页 |
| 429 | 签发过于频繁 | 退避重试；若已有未过期凭证则复用 |
| 500 | STS 签发失败 | 提示稍后重试；**禁止前端自行兜底拼接 COS 地址** |

降级顺序：STS 失败 → 尝试对象级预签名 URL → 仍失败则展示失败态。

#### 8.8.9 方案对比与推荐结论

| 维度 | 方案 A：STS 临时密钥（主方案） | 方案 B：对象级预签名 URL（降级） |
|---|---|---|
| 小程序是否直连 COS | 是 | 是 |
| 需要引入 COS SDK | 需要 | 不需要 |
| 单次可访问文件数 | 多个（policy 范围内） | 一次一个 |
| 后端请求次数 | 少，可复用 | 每次打开文件一次 |
| 密钥暴露面 | 临时密钥在端上（短时 + 最小权限） | 密钥不出后端 |
| 实现复杂度 | 中 | 低 |
| 适合场景 | 课程视频、多附件、批量资料 | 单个 PDF / 图片 / MP3 下载 |

推荐结论：

- 主方案采用 **A（STS 临时密钥）**，并统一收口在 `POST /api/miniprogram/files/sts`。
- 同时保留 **B（对象级预签名 URL）** 作为降级能力，代码继续复用 `storage.js` 现有签名能力。
- 两个接口都必须登录后调用，都不允许返回永久密钥。

#### 8.8.10 安全红线（写入开发约束）

1. 永久密钥只存在后端环境变量，不得出现在小程序、前端代码、接口响应和日志中。
2. 调用 STS 使用**子账号密钥**，不使用主账号密钥，子账号只授予 `sts:AssumeRole` 等最小必需权限。
3. 临时密钥 policy 只允许 `GetObject` / `HeadObject`，Resource 收窄到具体 bucket + 前缀。
4. 有效期默认 900 秒，不得超过 1800 秒。
5. 签发接口必须登录后调用，未登录一律 401。
6. 不允许为了省事把存储桶改成公有读。
7. 不允许在小程序端长期缓存临时密钥；过期必须重新向业务接口申请。
8. 不允许新增任何绕过登录的文件直链、公开地址或分享链接。

### 10.5 前后端关系

小程序端只负责展示和交互：

```txt
miniprogram 页面
    ↓ 调用 HTTPS API
backend 小程序接口
    ↓ 查询 / 校验
PostgreSQL + COS
```

文件访问按 8.8 单独规划：

```txt

    ↓ ① 请求 POST /api/miniprogram/files/sts（必须已登录）

miniprogram 页面
    ↓ ④ 带临时密钥直连 COS 拉取文件
COS
```

不要让小程序直接访问数据库，也不要把 COS 永久密钥写进小程序代码。

## 12. 过审流程与合规准备

> 以下为微信小程序常规上线审核流程，具体以微信公众平台当时规则为准。

### 12.1 上线前准备

1. 注册微信小程序账号。
2. 完成主体认证（个人 / 个体工商户 / 企业按实际选择）。
3. 完成小程序备案。
4. 准备小程序名称、头像、简介。
5. 配置服务类目。
6. 准备 HTTPS 域名。
7. 配置 request 合法域名、downloadFile 合法域名、媒体播放域名。
8. 把 COS 访问域名（或 CDN 域名）加入 downloadFile / 媒体合法域名。
9. 在腾讯云配置 STS 子账号密钥、最小权限策略和临时密钥有效期。
10. 在 COS 开启防盗链白名单，并加入 `servicewechat.com`。
11. 配置用户隐私保护指引。
12. 准备测试账号给审核员。

### 12.2 建议备案 / 审核表述

小程序用途建议写：

> 本小程序为个人教学辅助性质的学习记录工具，仅供老师已知的固定学生查看课程内容、作业要求、资料和历史学习记录。不开放公众注册，不提供广告服务，不涉及线上交易、支付、会员充值、课程售卖、论坛社区或新闻资讯。

小程序简介可写：

> 面向固定学生使用的学习记录工具，用于查看课程、作业要求、学习资料和历史记录。

### 12.3 类目建议

需在微信公众平台类目库中选择最贴近实际功能的类目。建议优先考虑偏“工具 / 教育辅助 / 学习记录”方向，避免写成“在线教育平台”“课程售卖平台”。

注意：

- 如果类目选择“教育培训”相关，可能涉及主体和资质要求。
- 如果只是固定学生的学习记录工具，描述要强调“学习记录、教学辅助、不售课、不交易”。
- 最终类目以小程序后台可选类目和主体资质为准。

### 12.4 隐私与个人信息

小程序可能涉及的信息：

| 信息 | 用途 | 是否必须 |
|---|---|---:|
| 手机号 / 账号 | 学生登录身份识别 | 必须 |
| 登录会话 token / session | 保持学生登录状态 | 必须 |
| 学生昵称 | 展示当前学生 | 必须 |
| 班级信息 | 展示学习归属 | 必须 |
| 作业记录 | 展示老师布置内容 | 必须 |

建议：

- 不调用微信手机号授权接口，除非确实需要。
- 不采集位置、通讯录、相册等无关权限。
- 不做用户画像和广告跟踪。
- 隐私保护指引中明确说明数据仅用于学习记录展示。

### 12.5 审核账号准备

- [ ] 小程序首页能体现核心功能，不能是空白页。

| 风险 | 规避方式 |
|---|---|

| 临时密钥被滥用 | 上线前验证未登录无法签发、policy 无法写删、限流生效 |

## 14. 风险与待确认问题

### 14.1 需要尽快确认

1. 小程序主体：个人、个体工商户还是企业？
2. 是否已有微信小程序账号？
3. 是否已经完成小程序备案？
4. 小程序学生会话采用短期 JWT、session token 还是服务端会话表？
5. 历史作业是否放独立 Tab？
6. 是否允许停用学生继续看课程和资料？当前 PRD 沿用网页端“可看但提示停用”。
7. 小程序名称准备用什么？建议避免“在线教育平台”“培训平台”等商业化表述。
8. STS 调用使用哪个子账号密钥？子账号只授予调用 STS 的最小权限。
9. 临时密钥有效期定多少？推荐 900 秒。
10. 防盗链白名单是否已加入 `servicewechat.com`，空 referer 是否拒绝？

### 14.2 技术风险

1. COS 私有文件在小程序中播放 / 下载需要签名，需验证有效期和微信播放器兼容性。
2. MP3 在小程序中的播放体验需要真机验证。
3. 视频大文件可能带来流量成本，需要上线前配置用量告警。
4. 如果后端当前接口依赖 cookie，小程序端可能需要单独 token / session 适配。
5. 小程序审核需要可用测试账号和稳定服务器，不能只跑本地环境。
6. `wx.downloadFile` / `<video>` / `wx.openDocument` 不能自定义请求头，临时密钥必须通过 COS SDK 在端上本地签名，这块是真机联调的重点风险。
7. 小程序直连 COS 需要把 COS 域名加入 downloadFile / 媒体合法域名，开发者工具不校验时容易漏配，真机才暴露。
8. 防盗链对带签名的访问不生效，不能把防盗链当作唯一防护；真正的防线是私有桶 + 最小权限 + 短有效期 + 接口鉴权。
9. 临时密钥即使短时泄露，也必须保证无法写 / 删 / 列举；上线前必须做一次越权验证。
10. STS 签发接口若无频率限制，可能被当作免费签名机，需配置限流和用量告警。
