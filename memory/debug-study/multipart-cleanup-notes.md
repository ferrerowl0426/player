# 上传资源清理学习记录：未完成 Multipart 分片

## 1. 这个问题属于什么类型

这个问题不算狭义的“表单边界校验”。

更准确地说，它属于：

```txt
上传流程可靠性
对象存储资源清理
异常中断兜底
成本控制
```

它和边界校验有关系，但重点不是判断用户输入是否合法，而是处理上传过程中断后残留资源的问题。

## 2. 问题背景

当前上传视频组件在 [uploadVideo.js](file:///c:/Users/user/Desktop/播放器/frontend/components/uploadVideo.js) 中负责浏览器分片直传。

流程大致是：

```txt
1. 后端创建 Multipart Upload，返回 uploadId 和 videoKey
2. 前端把视频切成多个分片
3. 前端逐个申请分片预签名 URL
4. 浏览器直接 PUT 分片到腾讯云 COS / MinIO
5. 全部分片上传完成后，后端调用 CompleteMultipartUpload 合并对象
```

正常情况下，如果上传失败或用户主动取消，前端可以调用后端的 abort 接口，让后端执行 `AbortMultipartUpload`，避免对象存储里残留未完成分片。

## 3. 为什么不能只依赖前端 abort

前端清理是不可靠的。

用户可能会：

```txt
关闭浏览器
刷新页面
断网
电脑休眠
进程被杀掉
上传到一半直接离开页面
```

这些情况下，前端不一定有机会成功调用 abort 接口。

如果没有额外兜底，腾讯云 COS 里会残留大量未完成的 Multipart Upload 分片。它们虽然还没有合并成最终对象，但仍然可能占用存储空间并产生费用。

所以前端 abort 只能算：

```txt
best effort
尽力清理
提升正常流程下的资源回收效果
```

不能作为唯一清理机制。

## 4. 腾讯云 COS 应配置生命周期规则

更可靠的做法是在腾讯云 COS 存储桶配置生命周期规则，自动清理未完成的 Multipart Upload。

建议配置：

```txt
清理未完成的分片上传任务
AbortIncompleteMultipartUpload
保留 1 天或 3 天后自动终止
```

这样即使用户关闭浏览器，COS 也会在生命周期规则生效后自动清理残留分片。

## 5. 后续优化方向

后续可以同时做三层清理：

```txt
1. 前端：上传失败或取消时主动调用 abort
2. 后端：提供可靠的 multipart abort 接口
3. COS：配置生命周期，自动清理过期未完成分片
```

如果要进一步优化，还可以在后端记录上传任务：

```txt
uploadId
videoKey
创建时间
上传状态
管理员用户
```

然后由后端定时扫描超时未完成任务，主动调用 `AbortMultipartUpload`。

但对于当前项目，优先级最高的是在腾讯云 COS 控制台配置生命周期自动清理未完成分片。

## 6. 学到的原则

直传对象存储时，资源清理不能只靠浏览器。

记住：

```txt
前端清理是不可靠的。
服务端清理更可靠。
对象存储生命周期规则是最终兜底。
```
