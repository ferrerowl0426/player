# 2026-10-04 数据万象工作流回调与清晰度不显示复盘

## 1. 背景

本项目为曲目 P 视频和知识点 P 视频接入腾讯云数据万象（CI）自动转码，目标是：

- 源视频上传到 `tracks/<曲目id>/<uuid>.mp4` 或 `knowledge/<知识点id>/<uuid>.mp4`。
- 数据万象自动生成同目录转码文件：
  - `tracks/<曲目id>/<uuid>-720p.mp4`
  - `tracks/<曲目id>/<uuid>-1080p.mp4`
  - `knowledge/<知识点id>/<uuid>-720p.mp4`
  - `knowledge/<知识点id>/<uuid>-1080p.mp4`
- 工作流完成后回调后端：
  - `POST https://api.nxhguitar.com/api/videos/transcode/callback?token=<CI_CALLBACK_SECRET>`
- 后端把转码结果写入 `video_renditions`，前端播放器通过 `renditions` 显示 `原画 / 720P / 1080P`。

## 2. 最终确认的控制台配置

两个工作流分别对应两个输入路径：

| 工作流 | 输入路径 | 上传触发执行 |
|---|---|---|
| tracks 工作流 | `tracks/` | 开启 |
| knowledge 工作流 | `knowledge/` | 开启 |

每个工作流包含两个转码节点：

| 节点 | 输出路径 | 输出文件名 | 模板 |
|---|---|---|---|
| 720p | `${InputPath}` | `${InputName}-720p.${ext}` | H264-MP4-高清（1280px） |
| 1080p | `${InputPath}` | `${InputName}-1080p.${ext}` | H264-MP4-全高清（1920px） |

关键结论：

- `${InputPath}` 已经包含完整源目录，例如 `tracks/25/`。
- 不要写 `tracks/${InputPath}`，否则会输出成 `tracks/tracks/25/...`。
- 不要写 `knowledge/${InputPath}`，否则会输出成 `knowledge/knowledge/...`。
- 文件名使用连字符：`-720p` / `-1080p`，不要再使用 `_720p` / `_1080p`。
- 回调类型使用“工作流完成回调”，格式 JSON。
- 上传触发执行必须开启，否则新上传源视频不会自动触发转码。

## 3. 问题现象

### 3.1 转码文件已经生成，但前端只显示“原画”

现象：

- COS 桶里已经能看到转码文件：
  - `tracks/25/xxx-720p.mp4`
  - `tracks/25/xxx-1080p.mp4`
- 前端播放器画质菜单仍然只显示：
  - `原画`

判断：

- 前端播放器不是直接扫描 COS 文件。
- 前端画质菜单来自接口返回的 `activePart.renditions`。
- 只有 `video_renditions` 中存在 `status='ready'` 且 `video_url` 非空的 `720p/1080p`，前端才会显示多个清晰度。
- 因此根因在“回调没有成功登记到数据库”，不是播放器 UI。

### 3.2 后端日志第一次报：未识别 JobsDetail

服务器日志：

```text
[ci-callback] 工作流完成回调未识别出 JobsDetail
```

原因：

- 后端最初按 `JobsDetail` 结构解析。
- 真实工作流完成回调不是 `JobsDetail`，而是：

```text
WorkflowExecution.Tasks[].ResultInfo...
```

修复：

- `backend/src/transcode.js` 的 `parseCiWorkflowCallbackPayload` 增加 `WorkflowExecution.Tasks` 解析。
- 从 `WorkflowExecution.Object` 获取源文件 key。
- 从每个任务的结果中提取转码产物 key。

对应提交：

```text
d02fa57 修复工作流完成回调任务解析
```

### 3.3 后端日志第二次报：outputKey 为空

部署上一次修复后，日志变为：

```text
[ci-callback] {"jobCount":2,...}
[ci-callback-job] {"state":"Success","inputKey":"tracks/25/...mp4","outputKey":"","quality":"",...}
[ci-callback] 无法判断转码档位：videoId=34 outputKey=
```

判断：

- `jobCount=2` 说明 `Tasks` 已经识别成功。
- `outputKey=""` 说明产物对象还藏在更深一层。
- 真实结构为：

```text
WorkflowExecution.Tasks[].ResultInfo.ObjectInfo[].ObjectName
```

修复：

- 增加 `getWorkflowTaskOutputs(task)`。
- 支持展开：

```text
Task.ResultInfo.ObjectInfo[]
```

- 从 `ObjectInfo[].ObjectName` 取转码产物 key。

对应提交：

```text
ba28d9b 修复工作流产物 ObjectInfo 解析
```

## 4. 后端最终规则

### 4.1 允许的输出 key

新规则：

```text
tracks/<曲目id>/<源文件名>-720p.mp4
tracks/<曲目id>/<源文件名>-1080p.mp4
knowledge/<知识点id>/<源文件名>-720p.mp4
knowledge/<知识点id>/<源文件名>-1080p.mp4
```

兼容旧规则：

```text
transcoded/...
```

### 4.2 拒绝的输出 key

后端会拒绝以下情况：

```text
tracks/tracks/25/xxx-720p.mp4
knowledge/knowledge/25/xxx-720p.mp4
tracks/25/xxx_720p.mp4
knowledge/25/xxx_1080p.mp4
tracks/999/xxx-720p.mp4   # 与源文件不同目录
knowledge/25/xxx-720p.mp4 # 源文件是 tracks 时跨前缀
```

目的：

- 防止错误配置产生的产物被入库。
- 防止伪造回调把任意文件写入 `video_renditions`。
- 保证转码产物必须与源视频同目录、同文件名前缀，只允许追加 `-720p` / `-1080p`。

## 6. 前端为什么之前只显示原画

前端播放器逻辑在：

```text
frontend/components/VideoPlayer.js
```

它会过滤：

```js
status === 'ready' && video_url
```

因此：

- COS 有转码文件，但数据库没登记：只显示原画。
- 数据库有 `720p/1080p`，但状态还是 `processing`：只显示原画。
- 数据库有 `ready`，但 `video_url` 为空：只显示原画。
- 数据库正常后，刷新课程详情页即可出现 `720P / 1080P`。

## 7. 本次经验

1. 数据万象控制台文案和真实回调结构不一定一致，必须以后端日志中的原始报文为准。
2. “工作流执行成功”只代表 CI 产物生成成功，不代表后端已入库。
3. 前端清晰度菜单以数据库 `video_renditions` 为准，不以 COS 文件列表为准。
4. 输出到源目录是可行的，但后端必须严格校验同目录、同源文件名前缀和 `-720p/-1080p` 后缀。
5. 以后遇到“桶里有文件但前端不显示清晰度”，优先检查：
   - backend `ci-callback` 日志；
   - `video_renditions` 状态；
   - 回调 URL token；
   - 后端是否部署到最新提交。
