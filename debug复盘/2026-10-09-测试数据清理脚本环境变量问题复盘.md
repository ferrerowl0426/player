# 2026-10-09 测试数据清理脚本环境变量问题复盘

## 背景

线上服务器需要清除由 `test-data/seed.mjs` 注入的测试数据。README 中记录的清理入口是：

```bash
cd /root/player/test-data
node clean.mjs
```

实际执行时，脚本未能一次性成功连接数据库，导致清理过程被中断。

## 现象

### 现象 1：数据库密码类型错误

执行 `node clean.mjs` 报错：

```txt
SASL: SCRAM-SERVER-FIRST-MESSAGE: client password must be a string
```

这说明 `pg` 客户端拿到的数据库密码不是字符串，常见原因是 `DATABASE_URL` 或密码字段没有被脚本正确读取。

### 现象 2：容器内找不到测试脚本

进入后端容器后尝试执行：

```bash
cd /app/test-data
node clean.mjs
```

报错：

```txt
sh: cd: can't cd to /app/test-data: No such file or directory
Error: Cannot find module '/app/clean.mjs'
```

说明后端镜像并未包含 `test-data/` 目录，测试数据脚本只能在服务器宿主机 `/root/player/test-data` 执行。

### 现象 3：数据库名存在，但宿主机端口用错

后端容器环境中存在：

```txt
DATABASE_URL=postgresql://postgres:postgres@postgres:5432/video_player
```

但在宿主机使用 `127.0.0.1:5432` 连接时报：

```txt
database "video_player" does not exist
```

随后通过 compose 查看发现 PostgreSQL 映射端口是：

```txt
0.0.0.0:15432->5432/tcp
```

因此宿主机应使用 `127.0.0.1:15432`，而不是 `127.0.0.1:5432`。

## 根因

1. `test-data/seed.mjs` 和 `test-data/clean.mjs` 直接复用 `backend/src/config.js`。
2. `backend/src/config.js` 固定读取 `backend/.env`，而服务器 Docker Compose 实际主要使用项目根目录 `.env`。
3. 后端容器中有正确的 `DATABASE_URL`，但容器镜像没有 `test-data/` 目录，不能在容器里直接执行清理脚本。
4. 在宿主机执行脚本时，如果根目录 `.env` 没被加载，脚本拿不到正确 `DATABASE_URL`。
5. 即使手动拼接数据库连接，宿主机要使用 compose 暴露端口 `15432`，不能照搬容器内服务端口 `5432`。

## 临时解决命令

本次线上成功清理使用了显式环境变量：

```bash
cd /root/player/test-data

DATABASE_URL='postgresql://postgres:postgres@127.0.0.1:15432/video_player' \
PGHOST=127.0.0.1 \
PGPORT=15432 \
PGUSER=postgres \
PGPASSWORD=postgres \
PGDATABASE=video_player \
DB_HOST=127.0.0.1 \
DB_PORT=15432 \
DB_USER=postgres \
DB_PASSWORD=postgres \
DB_NAME=video_player \
node clean.mjs
```

清理完成后输出：

```txt
测试数据清除完成 ✔（manifest.json 已删除）
```

并确认：

```bash
ls -l manifest.json
# No such file or directory
```

## 已做修复

新增 `test-data/runtime-config.mjs`，作为 test-data 脚本专用配置入口：

- 额外读取项目根目录 `.env`。
- 保留读取 `backend/.env` 的兼容能力。
- 支持以下数据库配置来源：
  - `DATABASE_URL`
  - `DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_NAME`
  - `PGHOST / PGPORT / PGUSER / PGPASSWORD / PGDATABASE`
- 将 `postgres://` 规范化为 `postgresql://`。
- 缺少数据库配置时给出明确错误提示，提醒服务器宿主机 PostgreSQL 端口通常是 `15432`。

同时更新：

- `test-data/seed.mjs`
- `test-data/clean.mjs`

两者均改为通过 `getRuntimeConfig()` 读取运行时配置。

## 后续标准操作

### 本地

```bash
cd test-data
node generate-assets.mjs
node seed.mjs
node clean.mjs
```

### 服务器宿主机

优先直接执行：

```bash
cd /root/player/test-data
node clean.mjs
```

如果服务器根目录 `.env` 没有适配宿主机端口，可显式指定：

```bash
cd /root/player/test-data
DATABASE_URL='postgresql://postgres:postgres@127.0.0.1:15432/video_player' node clean.mjs
```

### 注意事项

- 不要进入 backend 容器执行 `test-data/clean.mjs`，容器内没有该目录。
- 容器内连接 PostgreSQL 用 `postgres:5432`。
- 服务器宿主机连接 PostgreSQL 用 compose 映射端口，本项目当前是 `127.0.0.1:15432`。
- `clean.mjs` 只按 `manifest.json` 清除 seed 注入的数据和 `test-data/` 前缀对象，不清理后台手工上传的数据。
