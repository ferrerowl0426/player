# 2026-09-20 服务器部署问题复盘

## 背景

本次是在服务器 `/root/player` 目录部署播放器项目，使用 Docker Compose + 腾讯云 COS：

- 前端：Next.js，容器服务端口后续确认监听 `3001`
- 后端：Node/Express，容器服务端口 `3000`
- 数据库：PostgreSQL，宿主机映射 `15432`
- 对象存储：腾讯云 COS，不使用本地 MinIO
- 域名：
  - 主站：`nxhguitar.com`
  - www：`www.nxhguitar.com`，最终配置为 301 跳转主站
  - API：`api.nxhguitar.com`
- 服务器公网 IP：`150.158.122.193`

部署目标是从停止旧容器、清数据库、清 COS、释放端口开始，重新建表、导入数据并通过域名访问。

## 最终推荐架构

### DNS

三条 A 记录都指向服务器公网 IP：

| 主机记录 | 类型 | 记录值 |
|---|---|---|
| `@` | A | `150.158.122.193` |
| `www` | A | `150.158.122.193` |
| `api` | A | `150.158.122.193` |

### Nginx 反向代理

推荐统一主域名，避免 `www` 和非 `www` 同时承载业务导致 CORS、登录态、localStorage 混乱：

```nginx
server {
    listen 80;
    server_name www.nxhguitar.com;
    return 301 http://nxhguitar.com$request_uri;
}

server {
    listen 80;
    server_name nxhguitar.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

server {
    listen 80;
    server_name api.nxhguitar.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### `.env` 域名配置

```env
FRONTEND_URL=http://nxhguitar.com
NEXT_PUBLIC_API_BASE_URL=http://api.nxhguitar.com/api
```

注意：`NEXT_PUBLIC_API_BASE_URL` 是前端构建时写入的，修改后必须重建 frontend。

## 问题 1：`seed.mjs` 缺少 `PUBLIC_BUCKET_BASE_URL`

### 现象

执行：

```bash
cd /root/player/test-data
node seed.mjs
```

报错提示缺少：

```txt
PUBLIC_BUCKET_BASE_URL
```

### 原因

`test-data/seed.mjs` 并不是读取 `/root/player/test-data/.env`，而是通过：

```js
import { config } from '../backend/src/config.js';
```

间接读取后端配置。后端 `config.js` 固定读取的是：

```txt
/root/player/backend/.env
```

所以只把根目录 `.env` 复制到 `test-data/.env` 不生效。

### 处理方式

把根目录配置同步到后端目录：

```bash
cp /root/player/.env /root/player/backend/.env
```

确认：

```bash
grep -i PUBLIC_BUCKET_BASE_URL /root/player/backend/.env
```

并确保宿主机运行 seed 时数据库地址为：

```env
DATABASE_URL=postgresql://postgres:postgres@localhost:15432/video_player
```

不要写成容器网络地址：

```env
DATABASE_URL=postgresql://postgres:postgres@postgres:5432/video_player
```

## 问题 2：`manifest.json` 残留导致 seed 拒绝执行

### 现象

`node seed.mjs` 报：

```txt
检测到 manifest.json，请先执行 node clean.mjs
```

但执行：

```bash
node clean.mjs
```

又报：

```txt
relation "user_assignments" does not exist
```

### 原因

数据库已经通过 `docker compose down -v` 清空过，表不存在；但 `test-data/manifest.json` 是上一次未完成 seed 留下的本地残留文件。

### 处理方式

先确认后端已启动并建表：

```bash
curl http://localhost:3000/api/health
docker exec -it video_player_postgres psql -U postgres -d video_player -c "\dt"
```

如果表已存在，删除残留清单并重跑：

```bash
rm -f /root/player/test-data/manifest.json
cd /root/player/test-data
node seed.mjs
```

## 问题 3：后端健康检查打到 Next.js 前端 404

### 现象

执行：

```bash
curl http://localhost:3000/api/health
```

返回 Next.js 404 HTML，页面里有 `__next_static__`。

### 原因

Docker 端口映射写反/写错，前端占用了宿主机 3000，后端没有暴露到 3000。

错误配置曾类似：

```yaml
backend:
  ports:
    - "3001:3001"

frontend:
  ports:
    - "3000:3000"
```

### 处理方式

后端应映射：

```yaml
backend:
  ports:
    - "3000:3000"
```

前端端口需要结合容器实际监听端口，最终发现当前前端容器监听 `3001`，所以应映射：

```yaml
frontend:
  ports:
    - "3001:3001"
```

修改后重建：

```bash
cd /root/player
docker compose -p video_player -f docker-compose.yml up -d --build --force-recreate backend frontend
```

## 问题 4：3000 / 3001 端口反复占用

### 现象

启动容器时报：

```txt
failed to bind host port 0.0.0.0:3000/tcp: address already in use
```

或：

```txt
Bind for 0.0.0.0:3001 failed: port is already allocated
```

### 排查命令

查 Docker 端口占用：

```bash
docker ps --filter publish=3000 --format "table {{.ID}}\t{{.Names}}\t{{.Ports}}"
docker ps --filter publish=3001 --format "table {{.ID}}\t{{.Names}}\t{{.Ports}}"
```

查系统监听：

```bash
sudo lsof -i :3000
sudo lsof -i :3001
sudo ss -tnlp | grep ':3000'
sudo ss -tnlp | grep ':3001'
```

### 具体原因

1. 旧的 `video_player_backend` 曾以旧映射占用 `3001->3000`。
2. 宿主机上有一个 `next-server` 进程占用 3000，且被进程管理器反复拉起。
3. Docker 可能存在 `docker-proxy` 残留。

### 处理方式

删除旧容器：

```bash
docker rm -f video_player_backend video_player_frontend
```

如果是 Docker 网络/代理残留，先不要删数据库卷，执行：

```bash
cd /root/player
docker compose -p video_player -f docker-compose.yml down --remove-orphans
docker network prune -f
```

如果是宿主机 `next-server` 占用 3000，先找到 PID：

```bash
sudo ss -tnlp | grep ':3000'
```

再停止背后的守护方式，优先查：

```bash
pm2 list
systemctl list-units --type=service --state=running | grep -Ei "node|next|player|frontend"
ps -fp <PID>
```

不要只反复 kill 子进程，否则会被自动拉起。

## 问题 5：前端容器显示 Up，但 `localhost:3001` 连接被重置

### 现象

```bash
curl -I http://localhost:3001
```

返回：

```txt
Recv failure: Connection reset by peer
```

### 原因

前端容器日志显示 Next 监听：

```txt
next start -H 0.0.0.0 -p 3001
```

但 Docker 曾配置为：

```yaml
frontend:
  ports:
    - "3001:3000"
```

宿主机 3001 被映射到容器 3000，而容器内服务实际监听 3001，所以连接被重置。

### 处理方式

修改为：

```yaml
frontend:
  ports:
    - "3001:3001"
```

然后：

```bash
docker compose -p video_player -f docker-compose.yml up -d --build --force-recreate frontend
```

验证：

```bash
docker ps --format "table {{.Names}}\t{{.Ports}}"
curl -I http://localhost:3001
```

## 问题 6：域名解析后仍不能无端口访问

### 现象

DNS 已经解析到服务器 IP，但直接访问 `http://nxhguitar.com` 还不能进入项目。

### 原因

DNS 只负责把域名解析到 IP，不能指定端口。项目实际运行在：

- 前端：`3001`
- 后端：`3000`

要无端口访问，需要 Nginx 反代 80 到对应端口。

### 处理方式

创建 Nginx 配置：

```bash
sudo nano /etc/nginx/sites-available/nxhguitar.com
```

启用：

```bash
sudo ln -s /etc/nginx/sites-available/nxhguitar.com /etc/nginx/sites-enabled/nxhguitar.com
sudo nginx -t
sudo systemctl reload nginx
```

如果 Nginx 未启动：

```bash
sudo systemctl start nginx
sudo systemctl enable nginx
```

## 问题 7：Nginx 配置正确但无法启动，80 被占用

### 现象

```bash
sudo systemctl start nginx
```

失败，日志：

```txt
bind() to 0.0.0.0:80 failed (98: Address already in use)
```

### 原因

80 端口已有 nginx 进程占用，但不受当前 systemd nginx.service 正常管理，导致 reload/start 失败。

### 排查

```bash
sudo ss -tnlp | grep ':80'
```

看到已有：

```txt
users:(("nginx",pid=...))
```

### 处理方式

`nginx -s quit` 因缺少 `/run/nginx.pid` 失败后，用端口方式杀掉旧 nginx：

```bash
sudo fuser -k 80/tcp
sudo ss -tnlp | grep ':80'
sudo systemctl start nginx
sudo systemctl status nginx --no-pager
```

确认：

```txt
Active: active (running)
```

## 问题 8：`www` 加上后后端访问失败

### 现象

`nxhguitar.com` 正常，`www.nxhguitar.com` 访问业务时后端失败。

### 原因

`nxhguitar.com` 和 `www.nxhguitar.com` 是两个不同 Origin。后端 CORS / 前端环境变量通常只配置了：

```txt
http://nxhguitar.com
```

如果 `www` 也直接承载业务，会导致：

- CORS 来源不一致
- 登录态 / localStorage 分裂
- API 回跳地址混乱

### 处理方式

不要让 `www` 直接跑业务，统一跳转到主域名：

```nginx
server {
    listen 80;
    server_name www.nxhguitar.com;
    return 301 http://nxhguitar.com$request_uri;
}
```

验证：

```bash
curl -I http://www.nxhguitar.com
```

应返回：

```txt
HTTP/1.1 301 Moved Permanently
Location: http://nxhguitar.com/
```

## 问题 10：上传 COS 失败，浏览器报 CORS

### 现象

上传封面/图书馆资料时报：

```txt
上传图书馆资料到存储桶失败
```

浏览器控制台报：

```txt
Access to XMLHttpRequest at 'https://gy-nodejs-study-1423556188.cos.ap-nanjing.myqcloud.com/...'
from origin 'http://nxhguitar.com' has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

### 原因

代理到域名后，浏览器 Origin 从原来的 IP/端口变成：

```txt
http://nxhguitar.com
```

COS 存储桶 CORS 没有放行这个新 Origin。

### 处理方式

腾讯云 COS 控制台进入对应桶：

```txt
对象存储 COS -> 存储桶 gy-nodejs-study-1423556188 -> 安全管理 / 跨域访问 CORS
```

添加或修改 CORS：

#### 来源 Origin

```txt
http://nxhguitar.com
http://www.nxhguitar.com
http://api.nxhguitar.com
http://150.158.122.193:3001
```

如果后续启用 HTTPS，再补：

```txt
https://nxhguitar.com
https://www.nxhguitar.com
https://api.nxhguitar.com
```

#### 允许 Methods

```txt
GET
PUT
POST
DELETE
HEAD
OPTIONS
```

#### 允许 Headers

```txt
*
```

#### 暴露 Headers

```txt
ETag
x-cos-request-id
x-cos-hash-crc64ecma
```

#### Max-Age

```txt
600
```

保存后浏览器强刷，再重新上传。

## 复盘结论

1. 部署前必须先明确容器内部监听端口，不要只凭常规 Next.js 默认端口判断。
2. DNS 只解析 IP，不处理端口；正式域名访问必须配反向代理。
3. `NEXT_PUBLIC_API_BASE_URL` 是构建时变量，改 `.env` 后必须重建前端。
4. `www` 和非 `www` 是不同 Origin，建议统一主域名，`www` 只做 301 跳转。
5. COS CORS 需要随着前端 Origin 变化同步更新；从 IP/端口切到域名后必须放行新域名。
6. seed 脚本读取后端配置，排查 `.env` 时不能只看根目录，还要关注 `/root/player/backend/.env`。
7. 端口冲突要区分 Docker 容器、docker-proxy 残留、宿主机 Node/Next 进程、systemd/pm2 自动拉起。
8. Nginx 启动失败时先看 `nginx -t` 和 `systemctl status`，语法正确但启动失败通常是 80 端口被占。
