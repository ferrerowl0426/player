# 班级管理页 · 设计稿 vs 当前实现 差异清单

> 对比基准：
> - 设计稿：`docs/design/guitar-home/class-manage.html`
> - 当前实现：`frontend/app/admin/classes/page.js` + `frontend/app/admin/classes/page.module.css`
> - 涉及共享层：`frontend/components/ui/AppNav.js`、`frontend/app/design-system.css`、`frontend/lib/api.js`
> - 生成时间：2026-09-17

---

## 0. 总览

布局骨架（上排「教导主任 / 老师」两框 + 下排「班级 / 学员」联合框、35% 左右分栏、zone 橙色角标、弹层骨架、响应式断点、全局格纹底饰）已基本对齐。差距集中在四类：

1. **入口位置错位**：设计稿的新建入口在各 zone 头部，当前全部堆在顶部工具行；
2. **核心交互缺失**：设计稿的「编辑资料」弹层（改昵称 + 密码两态重置 + 班级归属）完全没有实现，行内「编辑」按钮缺失；
3. **多出设计稿没有的功能**：搜索框 ×3、「添加学员」批量弹层、「设置班级 / 转班」弹层、班级停用按钮等；
4. **行结构与状态表达不一致**：设计稿是横向单行（左信息右操作、无状态 chip），当前是上下两行且每行挂「正常/停用」chip。

## 1. 布局与结构差异

### 1.1 顶部工具行（当前多出，设计稿没有）
- 设计稿正文直接是 `.grid4`，**没有 toolrow**（CSS 里保留了 toolrow 样式但页面未使用）。
- 当前实现加了一整行 toolrow：hint 文案 + `新建教导主任` / `新建老师` / `新建学员`（3 个深色实心 `zbtn main`）+ `创建班级`（`zbtn mini`）。
- 设计稿的入口位置与样式：

  | 入口 | 设计稿位置 | 设计稿样式 |
  |---|---|---|
  | ＋ 新建教导主任 | 教导主任 zone-head 右侧 zone-ops | mini 描边按钮 |
  | ＋ 新建老师 | 老师 zone-head 右侧 zone-ops | mini 描边按钮 |
  | ＋ 新建班级 | 班级/学员 zone-head 右侧 | mini 描边按钮 |
  | ＋ 新建学员 | 班级/学员 zone-head 右侧 | mini 描边按钮 |

- 当前各 zone-head（教导主任/老师）右侧只有搜索框，没有任何新建入口。
- **建议**：删除 toolrow 整行，把 4 个入口按设计稿放回各 zone-head，统一 mini 描边样式。

### 1.2 zone 标题文案
- 设计稿：`教导主任`、`老师`、`班级 / 学员`。
- 当前：`教导主任列表`、`老师列表`、`班级 / 学员`。前两个多了「列表」二字。

### 1.3 班级/学员 zone-head
- 设计稿：标题旁**无 meta**，右侧 ops = `＋ 新建班级` + `＋ 新建学员`。
- 当前：标题旁有 meta「N 个班级 · N 名学员」，右侧 = 搜索本班学员 + `＋ 新建班级` + `＋ 添加学员`。

### 1.4 split 两侧 sub-head
- 左侧：设计稿 `班级` + meta `共 N 个`；当前 `班级列表` + meta `点击切换右侧学员`。
- 右侧：设计稿 `学员` + meta `未选择班级` 或 `班级名 · N 人 · 已停用`；当前 `学员列表` + meta 只显示班级名（无人数、无停用标记）。

## 2. 缺失功能（设计稿有、实现没有）

### 2.1 「编辑资料」弹层 —— 最大的缺失
设计稿三个列表每行都有「编辑」按钮，打开统一的「编辑资料」弹层：
- 账号只读（灰底，注明不可更改）；
- 昵称可改（≤10 字，仅中文/字母/数字/下划线，带校验与 tip）；
- 密码两态重置：默认 `••••••••` + 「重置密码」按钮；点击后才出现新密码输入 + 「随机生成」，并带「取消重置」链接；
- 老师：显示所带班级只读 chips（空则 `未带班`），tip 引导去班级列表编辑；
- 学员：所在班级单选下拉（含「未分班学员」选项）。

当前实现：
- 行内没有「编辑」按钮；**昵称在任何地方都无法修改**；
- `lib/api.js` 中也不存在更新用户/管理员资料（昵称）的接口封装；
- 密码重置被拆成独立弹层（见 3.4），交互路径与设计稿不同。

### 2.2 「＋ 新建学员」入口
- 设计稿在班级/学员 zone-head 有 `＋ 新建学员`，复用新建账号表单的学员固定模式（隐藏角色行、标题变「新 建 学 员」、按钮变「创建学员」）。
- 当前该位置是 `＋ 添加学员`（批量把已有学员转入班级，设计稿没有此功能）。

### 2.3 排序规则
- 教导主任/老师列表：设计稿停用置底（`offLast`）；当前未排序，直接用接口顺序。
- 学员列表：设计稿停用置底 + 昵称中文典序（`localeCompare('zh-Hans-CN')`）；当前只做停用置底，无字典序。

### 2.4 删除保护
- 设计稿：初始超级管理员（root）「删除」按钮 disabled 并带 title「初始超级管理员不可删除」，编辑也被阻止；教导主任删除前校验「至少保留 1 位教导主任」。
- 当前：只禁用「当前登录者自己」的停用/删除，保护对象与规则都和设计稿不同；无「至少保留一位教导主任」逻辑。

### 2.5 列表滚动边线处理（has-scroll）
- 设计稿：列表**实际发生滚动**时才去掉最后一行下边线（`.rows.has-scroll`，render 后检测 `scrollHeight > clientHeight`）。
- 当前：无 `.has-scroll`，CSS 固定 `.row:last-child { border-bottom: none }`，不滚动时也去掉了边线。

### 2.6 新建老师时的初始班级
- 设计稿：新建老师也显示「初始班级」下拉（tip：老师可带多个班级，此处先选一个），创建后把该班负责老师设为新老师。
- 当前：老师创建无班级选择，需另走「设置班级」弹层。

### 2.7 学员初始班级选填
- 设计稿：可选「先不分班（进入「未分班学员」）」。
- 当前：初始班级必选，留空报「请选择初始班级」，与设计稿的未分班语义冲突。

### 2.8 其他小缺失
- 班级行键盘操作：设计稿支持 Enter + Space 选中；当前只有 Enter。
- 未选班级空态：设计稿有「请在左侧「班级」列表中选择一个班级…」引导文案；当前因默认选中第一个班级而不可达（见 4.1）。

## 3. 多出功能（实现有、设计稿没有）

按此前「不要设计稿没有的功能」的整改原则，以下需用户决定保留还是收敛：

1. **顶部 toolrow 整行**（hint 文案 + 4 个入口按钮）。
2. **3 个搜索框**：搜索教导主任 / 搜索老师 / 搜索本班学员（设计稿定义了 minisearch 样式但此页未使用）。
3. **`＋ 添加学员` 批量弹层**（勾选其他班/未分班学员批量转入）。
4. **行内「设置班级」（老师多选弹层）与「转班」（学员弹层）**：设计稿通过「编辑资料 → 所在班级」和「编辑班级 → 负责老师」完成，无独立弹层。
5. **班级行「停用/恢复」按钮**：设计稿班级行只有「编辑 / 删除」（JS 保留了 coff 分支但 UI 无入口，属预留未启用能力）。
6. **行内 cls-chips**：教导主任行「权限：内容与账号管理」、学员行「学员账号」、老师行带班 chips。设计稿明确隐藏账号列表 chips，账号行不放。
7. **每行常显「正常/停用」状态 chip**：设计稿账号行完全不渲染状态 chip（停用靠整行灰底 + 文字变灰表达）；仅停用班级显示灰色「已停用」chip。
8. **班级/学员 zone-head 的 meta 统计**。
9. **导航右侧 role-tag「教导主任 · 名字」**（设计稿右侧只有头像）。

## 4. 行为与逻辑差异

1. **默认选中班级**：当前加载后自动选中第一个班级；设计稿初始为「未选择班级」，右侧显示引导空态，由用户主动点击。
2. **新建账号弹层**：
   - 标题：设计稿按入口变化（新 建 学 员 / 新 建 老 师 / 新 建 教 导 主 任），固定角色入口会隐藏角色下拉；当前固定「新 建 账 号」且角色下拉常显。
   - 账号校验：设计稿必须是 **11 位手机号**（`maxlength=11` + `^\d{11}$` + 重复校验）；当前仅校验纯数字，无位数限制。
   - 密码：设计稿可手动输入或随机生成；当前 readOnly 只能重新生成（若是有意的安全策略，需确认保留哪版）。
3. **新建班级弹层**：设计稿只填名称（tip：负责老师稍后分配）；当前新建时也带「负责老师」下拉，应只在编辑时出现。
4. **编辑班级弹层**：基本对齐（改名 + 负责老师下拉 + 暂不分配）。差异：设计稿下拉选项格式为「昵称 · 手机号（已停用）」，当前只有昵称；设计稿改名会同步学员归属与当前选中班级，当前依赖后端 `updateClass`（需验证后端是否同步，见第 7 节）。
5. **确认弹层文案**：设计稿按对象给出完整后果说明——
   - 停用学员：「停用后仍可登录自学，首页将显示恢复引导」；停用老师/主任：「停用后仍可登录，界面将显示停用引导文案」；
   - 删除教导主任：「系统至少需保留 1 位教导主任」；
   - 删除学员：「账号、班级关系与学习记录均不可恢复」；
   - 删除班级：「班内 N 名学员将进入「未分班学员」，账号与历史记录保留」；
   - 停用班级：「停用后班级保留全部师生，但不可再加入新学员或作为转班目标」。
   当前文案均为一句话简写。
6. **toast 位置**：设计稿顶部居中（`top:70px`）；当前底部居中（`bottom:28px`）。时长 1.9s vs 2.6s（小差异）。
7. **行内按钮数量**：设计稿每行固定 3 个按钮（编辑/停用/删除）；当前 4~5 个（重置密码/转班或设置班级/停用/删除），在 54px 单行结构里必然换行，这也是行结构被改成上下两行的诱因之一。

## 6. 导航差异（共享组件 AppNav）

- 设计稿链接：首页 / 知识点区 / 曲目库 / 图书馆 / 学生管理 / 班级管理(active)。
- 当前 super_admin：曲目区 / 知识点区 / 图书馆 / 学生管理 / 班级管理 —— 少「首页」，「曲目库」写作「曲目区」。
- 设计稿导航右侧只有头像；当前多 role-tag 徽标。
- nav 视觉（底部 3px 咖啡线、active 橙色高亮）由全局 design-system.css 提供，已对齐。

## 7. 需后端/接口确认的验证项

1. **昵称修改接口**：编辑资料弹层的硬前提，`lib/api.js` 目前没有 `updateManagedUserProfile` 类封装，需确认后端是否支持（用户端与管理端账号）。
2. **「至少保留 1 位教导主任」**：删除最后一位教导主任时后端是否有保护。
3. **初始超管保护**：后端是否对初始 super_admin 账号禁止删除/停用。
4. **删除班级**：后端是否把班内学员自动转入未分班（class_id 置空）。
5. **删除老师**：后端是否清空其所带班级的 `teacher_id`。
6. **班级重命名**：后端 `updateClass` 改名后是否同步学员/作业记录中的班级引用。

## 8. 建议收敛顺序（确认后执行）

**P0（结构级）**
1. 删除 toolrow，4 个新建入口放回各 zone-head（mini 描边）；
2. 行结构改回横向单行（左信息、右 3 按钮），去掉行内 chips 与常显状态 chip；
3. 补「编辑资料」弹层 + 行内「编辑」按钮（依赖第 7.1 条接口确认）；
4. 补「＋ 新建学员」入口，替换「＋ 添加学员」位置。

**P1（规则级）**
5. 排序：停用置底 + 学员昵称字典序；
6. 账号 11 位手机号校验；学员初始班级选填（未分班）；新建老师可选初始班级；
7. 新建班级去掉负责老师下拉；sub-head / meta / 标题文案对齐；
8. `.cls-row.sys` 样式；has-scroll 边线处理；状态 chip 规则（正常不显示、停用灰色「已停用」）。

**P2（细节级）**
9. 确认弹层文案对齐设计稿；toast 移到顶部；Space 键选中；编辑班级下拉格式；停用行底色 `#eeeae3`。

**待用户决策的多出功能**：3 个搜索框、添加学员批量弹层、设置班级/转班弹层、班级停用/恢复按钮、zone-head meta、role-tag —— 保留则设计稿需增补说明，严格按稿则移除。
