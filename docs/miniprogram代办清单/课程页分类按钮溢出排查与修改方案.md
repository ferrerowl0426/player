<view class="type-switch">

  <button class="type-btn {{section === 'track-set' ? 'active' : ''}}" data-section="track-set" bindtap="changeSection">曲目集</button>

## 根因判断

### 1. 不应继续使用原生 `button` 做顶部分段控件

微信小程序原生 `button` 有平台默认能力和内部样式，包括但不限于：

- 默认点击态；
- 默认按钮渲染盒模型；
- 默认 `button::after` 边框；
- 不同基础库 / 模拟器设备下表现不完全一致；
- 部分样式即使设置 `width: 100%`、`min-width: 0`，仍可能因内部按钮渲染影响布局。

课程页这个位置只是一个视觉分段选择器，不是表单提交按钮，因此不应该用 `button`。

### 2. 设计稿中的 `.type-btn` 是 Web 参考，并不等价于小程序原生 button

设计稿文件：

```txt
C:\Users\user\Desktop\播放器\docs\design\guitar-home\miniprogram-student\course.html
```

设计稿里是 HTML：

```html
<button class="type-btn active">知识点集</button>
```

但小程序端不能照搬 HTML button 行为。小程序中应使用 `view` 或自定义组件模拟按钮视觉。

### 3. 当前修改方向只在 CSS 层兜底，仍未消除组件默认行为

虽然已经做过：

- `width: 100%`；
- `min-width: 0`；
- `padding: 0`；
- `button::after { border: 0; }`；
- 缩小 `gap` 和字体；

但截图说明实际渲染仍未符合预期，所以应从结构上改掉原生 `button`。

## 正确修改方案

### 方案 A：推荐方案，改为 `view` 自绘分段控件

把 `button` 全部替换为 `view`：

```xml
<view class="type-switch">
  <view class="type-option {{section === 'knowledge-set' ? 'active' : ''}}" data-section="knowledge-set" bindtap="changeSection">知识点集</view>
  <view class="type-option {{section === 'track-set' ? 'active' : ''}}" data-section="track-set" bindtap="changeSection">曲目集</view>
  <view class="type-option {{section === 'knowledge' ? 'active' : ''}}" data-section="knowledge" bindtap="changeSection">知识点</view>
  <view class="type-option {{section === 'track' ? 'active' : ''}}" data-section="track" bindtap="changeSection">曲目</view>
</view>
```

对应样式：

```css
.type-switch {
  width: 100%;
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 8rpx;
  margin-bottom: 20rpx;
}

.type-option {
  min-width: 0;
  height: 72rpx;
  border: 2rpx solid #c9b795;
  border-radius: 16rpx;
  background: #ffffff;
  color: #5d4326;
  font-size: 21rpx;
  font-weight: 900;
  display: flex;
  align-items: center;
  justify-content: center;
  white-space: nowrap;
  overflow: hidden;
}

.type-option.active {
  background: #5d4326;
  border-color: #5d4326;
  color: #ffffff;
}
```

优点：

- 不受小程序 `button` 默认样式影响；
- 布局更稳定；
- 更适合设计稿中的自定义分段视觉；
- 后续也更容易做选中态、点击态、禁用态。

### 方案 B：使用 `scroll-view` 横向滚动

如果后续要兼容更长的类型名称，可以改成横向滚动：

```xml
<scroll-view scroll-x class="type-scroll" show-scrollbar="false">
  <view class="type-row">
    ...
  </view>
</scroll-view>
```

但当前设计稿明确是四个等分按钮，因此不优先采用。

## 验收标准

### UI 验收

- 顶部四分类按钮一行显示；
- 四列宽度一致；
- 文字居中；
- 当前选中项为咖啡色底白字；
- 非选中项为白底咖啡色字；
- 没有横向溢出；
- 页面不出现横向滚动。

### 功能验收

- 点击 `知识点集`，列表标题和数据变为知识点集；
- 点击 `曲目集`，列表标题和数据变为曲目集；
- 点击 `知识点`，列表标题和数据变为知识点；
- 点击 `曲目`，列表标题和数据变为曲目；
- 搜索仍然只搜索当前类型；
- 底部导航栏图标不受影响。

## 后续注意

小程序端遇到类似“设计稿里是 button，但实际只是切换 Tab / 分段选择 / 筛选 Chip”的场景，不要直接使用原生 `button`。优先使用：

```txt
view + bindtap + 自定义样式
```

只有以下场景再使用原生 `button`：

- 表单提交；
- 获取手机号；
- 获取用户信息；
- 分享；
- 需要小程序 button 原生 open-type 能力。
