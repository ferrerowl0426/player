# 学员管理界面整改方案

> 范围：`/admin/users`  
> 对照来源：`docs/PRD.md` §2.2 / §2.4 / §2.6 / §4.8 / §4.9 / §5.6 / §5.8 / §5.10 / §8、`docs/design/guitar-home/student-manage.html`、当前实现 `frontend/app/admin/users/page.js` 与 `frontend/app/admin/users/page.module.css`。  
> 最新口径：老师与教导主任共用同一页面；老师只管理本人班级学生；教导主任可自由筛选并拥有学生标记能力；作业推送区保持搜索选择流程，但留言区必须拆成「练习要求」与「提交要求」两个独立框。

---

## 1. 总体结论

当前 `/admin/users` 已具备基础三栏布局、班级/学生筛选、历史作业、布置作业、停用/恢复、重置密码等能力，但与 PRD 和 `student-manage.html` 仍存在明显差距：

| 模块 | 当前还原度 | 主要问题 |
| --- | :-: | --- |
| 页面骨架 | 75% | 三栏结构接近设计稿，但班级筛选不是设计稿的下拉多选；区头与标记入口缺失 |
| 权限与跳转 | 80% | 页面可访问，老师/教导主任共用，但异常处理过于粗暴，初始化失败会直接跳登录 |
| 学生标记 | 0% | PRD 新增能力完全未实现：无 `is_marked` 前端渲染、无接口、无清除全部标记 |
| 作业历史 | 55% | 仍按单个 `message` 展示，未拆成「练习要求 / 提交要求」；删除原因仍用 `window.prompt` |
| 布置作业 | 60% | 推送对象选择已基本具备，但只有一个“作业备注/留言”框；缺“上次作业”回填；范围下拉样式不完全对齐设计稿 |
| 账号操作 | 50% | 创建学员、重置密码、删除学员仍使用浏览器原生 prompt/confirm，不符合设计稿弹层 |
| 文案口径 | 60% | 仍出现“留言/备注”等旧口径；PRD 已明确新页面不再显示留言区 |

**整改重点**：先补数据模型与接口，再改页面结构。学生标记和双要求字段属于 P0/P1，因为 PRD 已经定稿，当前页面仍是旧留言模型。

## 2. 与 PRD / 设计稿差异清单

### 2.1 P0：学生标记完全缺失

**设计稿 / PRD 要求**

- 仅教导主任可见可操作。
- 左列学生行内有标记圆点：
  - 未标记：咖啡色空心点，hover 行时出现；
  - 已标记：紫色实心点，常驻显示。
- 中列学生头部有「标记学生 / 取消标记」按钮。
- 左列区头有「清除全部标记 · N」，有标记时才显示，不受筛选影响。
- 清除全部标记走二次确认弹层，确认按钮用紫色，不用危险红。
- 停用学生不可标记；停用已标记学生时立即清除，恢复后不还原。
- 数据字段：`users.is_marked boolean DEFAULT false`，不新建表。

**当前实现**

- `frontend/app/admin/users/page.js` 未渲染任何标记圆点、头部标记按钮、清除全部入口。
- `backend/src/admin.routes.js` 搜索不到 `/users/:id/mark` 和 `/users/marks/clear`。
- `PATCH /api/admin/users/:id/status` 只更新 `is_active/status`，没有停用时清除 `is_marked`。

**整改动作**

1. 后端：
   - `backend/src/db.js`：确保 `users` 表新增 `is_marked boolean DEFAULT false`，并为老数据补默认值。
   - `GET /api/admin/users` 返回 `is_marked`。
   - 新增 `PATCH /api/admin/users/:id/mark`，`requireSuperAdmin`，请求体 `{ isMarked: boolean }` 或开关式均可，但前后端统一。
   - 新增 `POST /api/admin/users/marks/clear`，`requireSuperAdmin`，清除所有 active 学员标记。
   - 修改 `PATCH /api/admin/users/:id/status`：当 `isActive=false` 时同步 `is_marked=false`。
   - 停用学员调用 mark 接口时返回 400/409，文案如「停用学员不可标记」。
2. 前端：
   - 左列 `.stu-item` 内增加 `.mk` 圆点，仅 `isSuperAdmin && user.is_active` 渲染。
   - 选中学生头部增加 `.mk-tag` 按钮，仅 `isSuperAdmin && selectedUser.is_active` 渲染。
   - 左列 `zone-head` 在 meta 后增加 `.mk-clear`，`markedCount > 0` 才渲染。
   - 清除全部走设计稿确认弹层，确认按钮 `.mbtn.mark`。
   - 操作成功 toast：`已标记「XX」` / `已取消标记「XX」` / `已清除全部标记（N 位学生）`。
3. CSS：补齐 `student-manage.html` 中 `.mk`、`.mk-tag`、`.mk-clear`、`.mbtn.mark` 的样式，使用 `--mark #7b5ea7`。

**验收**

- 教导主任能标记/取消标记，刷新后状态保留。
- 老师视角完全看不到三个标记入口，直接调接口被 403。
- 停用已标记学生后，列表圆点消失，数据库 `is_marked=false`。
- 清除全部不受当前班级/搜索筛选影响。

### 2.2 P0：作业要求仍是单一留言字段，未拆成两个独立框

**设计稿 / PRD 要求**

- 布置作业区底部必须有两个独立输入框：
  - `练习要求（选填）…`
  - `视频提交要求（选填）…`
- 历史作业展示时也要分两栏/两行：
  - `练习要求：...`
  - `提交要求：...`
- 作业内容、练习要求、提交要求三个栏目独立保存、独立展示，空栏不占位。
- 学员首页、我的历史作业、管理端历史作业复用同一份数据和组装规则。

**当前实现**

- `page.js` 只有一个 `message` state。
- 提交体为 `{ objects, message }`。
- 历史记录只渲染 `operation.message` 到 `.hw-msg`。
- textarea placeholder 仍是 `作业备注 / 给学生的留言（选填）…`。
- 后端 `user_assignments` 目前只看到 `message`，未看到 `practice_requirement` / `submit_requirement` 或等价字段。

**整改动作**

1. 数据模型：
   - 推荐在 `user_assignments` 增加：
     - `practice_requirement text DEFAULT ''`
     - `submit_requirement text DEFAULT ''`
   - 或如果继续使用 `message` 兼容旧数据，需要明确迁移策略：旧 `message` 只作为历史兼容展示，不再作为新作业输入。
2. 后端：
   - `POST /api/admin/users/:userId/assignments` 接收 `practiceRequirement`、`submitRequirement`。
   - 校验各自 ≤1000 字，沿用 §4.9 文案。
   - 允许三栏任一非空即创建操作：对象、练习要求、提交要求至少有一项。
   - `GET /api/admin/users/:userId/assignments` 的 `operations` 返回两个字段。
   - 学员端今日/历史接口同步返回两个字段，保证三端同构。
3. 前端：
   - `message` 拆为 `practiceRequirement` 与 `submitRequirement`。
   - 布置作业区用 `.msg-pair` 包裹两个 `.msg-box`。
   - `submitAssignment` 校验三栏至少一项非空。
   - 历史作业中按设计稿渲染 `.hw-msg-pair`、`.hw-msg-line`、`.hw-msg-label`、`.hw-msg-text`。
   - 长文本在框内滚动，保留换行：`white-space: pre-wrap; overflow-wrap: anywhere;`。

**验收**

- 只填练习要求可推送；只填提交要求可推送；只选作业内容也可推送。
- 历史作业中两个字段独立展示，空字段不占位。
- 学员首页与学员历史作业看到的字段与管理端一致。
- 旧留言数据不丢失，但新页面不再出现“留言板/留言区”字样。

### 2.3 P1：班级筛选不是设计稿的下拉多选

**设计稿要求**

- 左列班级筛选是一个下拉多选控件 `.cls-dd`：
  - 按钮显示「我的全部班级 / 全部班级（N）/ 已选班级名 / 未选择班级」。
  - 面板内有「全选 / 全不选」。
  - 老师视角只能在本人班级内选择，且不可全不选。
  - 教导主任可全选/全不选全部班级。

**当前实现**

- 使用 `.class-chips` 平铺按钮。
- 老师视角虽然数据由后端限制，但前端视觉与设计稿不一致。
- 没有下拉箭头、展开面板、全选/全不选控制。

**整改动作**

- 将 `selectedClassIds` 的 UI 从 chip 列表改为 `.cls-dd` 结构。
- 增加 `classDropdownOpen` 状态与外部点击关闭、Esc 关闭。
- 老师视角：`classOptions` 只来自 `fetchClasses()` 返回的本人班级；如果只剩 1 个班级，不允许取消。
- 教导主任：允许空选择；空选择时学生列表显示空态「该范围内未找到学生」。
- CSS 复用设计稿 `.cls-dd`、`.cls-dd-btn`、`.cls-dd-panel`、`.cls-opt`。

**验收**

- 老师登录后只能看到本人班级，且不能通过 UI 全不选。
- 教导主任可以选择任意班级组合，也可清空。
- 选择状态、计数与学生列表同步。

### 2.4 P1：账号操作仍使用浏览器原生 prompt / confirm

**设计稿 / PRD 要求**

- 删除历史记录必须使用自定义弹层，填写删除原因。
- 新建学员、重置密码、删除学员都应使用平台统一弹层样式。
- 删除/停用/恢复等操作用 toast 反馈。

**当前实现**

- `handleDeleteOperation` 使用 `window.prompt` 填删除原因。
- `handleCreateUser` 使用两个 `window.prompt` 创建账号。
- `handleResetPassword` 使用 `window.prompt` 输入新密码。
- `handleDeleteUser` 使用 `window.confirm`。

**整改动作**

- 新增并复用弹层组件：
  - `CreateStudentModal`：账号、昵称、初始密码、初始班级。
  - `ResetPasswordModal`：新密码、随机生成、复制。
  - `DeleteUserConfirmModal`：删除学员确认。
  - `DeleteOperationModal`：删除历史记录 + 删除原因 textarea。
- 所有成功/失败提示统一 toast；不再用浏览器原生弹窗。
- 删除历史记录的按钮：最新未删除作业不可直接删时置灰并加 title，符合 §5.8。

**验收**

- 页面里搜索不到 `window.prompt` / `window.confirm`。
- 删除历史作业必须填写原因；空原因不可提交。
- 弹层 Esc、点击遮罩、取消按钮都能关闭。

### 2.5 P1：停用学员仍允许进入布置区交互

**设计稿要求**

- 停用学员仍保留历史记录。
- 布置区顶部显示提示：老师/教导主任文案不同。
- 停用学员不可继续布置新作业，搜索、范围筛选、两个要求框、推送按钮、上次作业按钮均禁用。

**当前实现**

- 仅在 `selectedUser?.is_active` 为 false 时显示提示。
- 推送表单没有系统性禁用：搜索、选择、textarea 仍可编辑；提交按钮只受 `busy/noClass/selectedUserId` 控制。

**整改动作**

- 增加 `isSelectedUserDisabled`。
- 禁用：推送搜索输入、范围下拉、结果点击、两个要求 textarea、上次作业按钮、推送按钮。
- 根据角色显示文案：
  - 教导主任：`该学员账号已停用 · 请先恢复账号后再布置作业`
  - 老师：`该学员账号已停用 · 请联系教导主任启用账号`
- CSS 增加半透明/禁用态。

**验收**

- 停用学员无法提交作业；直接调后端如 PRD 未要求可不拒绝，但建议后端也拒绝新推送。
- 恢复后布置区恢复可用。

### 2.6 P1：缺「上次作业」回填

**设计稿 / PRD 要求**

- 布置作业区提供「上次作业」按钮。
- 优先从该学生首页当前展示的最新有效作业回填；无当前作业时取最近一条未删除历史作业。
- 回填对象、练习要求、提交要求；只是填入表单，重新推送必须新增记录。

**当前实现**

- 没有「上次作业」按钮。
- 没有从 `operations` 或 `activeAssignments` 回填 `selectedObjects` 和要求文本的逻辑。

**整改动作**

- 后端可不新增接口，前端基于当前 `operations` 计算最近未删除记录。
- 需要保证 operation 中返回对象的 `object_type/object_id/part_id/title` 足够重建 `selectedObjects`。
- 按钮放在 `push-foot` 中 `推送作业` 左侧，样式 `.btn-shortcut`。
- 无可回填数据时 toast：`暂无可回填的作业数据`。

**验收**

- 点击后已选作业、练习要求、提交要求同步回填。
- 再点击推送会生成新 operation，不覆盖旧记录。

### 2.7 P2：推送范围下拉缺统一箭头样式

**设计稿要求**

**当前实现**

**整改动作**

- 给 `.hw-scope` 增加设计稿同款 background SVG，或改为与全站 `.order-wrap + .order-chevron` 一致的外包结构。
- 推荐保持搜索框内紧凑形态，用 background SVG，避免改变布局。

**验收**

- 范围下拉右侧可见箭头，hover/focus 边框变咖啡/橙色。

### 2.8 P2：历史作业删除规则未完整呈现

**PRD 要求**

- 当前学生最新的一条未删除作业不可直接删除；必须先布置新作业，旧作业才可填写原因并软删除。
- 删除后整条记录变灰留痕。

**当前实现**

- 所有未删除 operation 都显示删除按钮。
- 软删除后可灰显，但“最新作业不可删”的 UI 约束缺失。

**整改动作**

- 计算 `latestActiveOperationId`。
- 该记录删除按钮显示为 disabled，title：`最新作业不能删除，请先布置一条新的作业`。
- 后端 `PATCH /api/admin/operations/:operationId/delete` 同步校验，不能只靠前端。

**验收**

- 最新未删除作业无法删除；创建新作业后，上一条可删除。

## 4. 后端接口补充建议

### 4.1 学生标记

```http
PATCH /api/admin/users/:id/mark
Content-Type: application/json

{ "isMarked": true }
```

返回：

```json
{ "data": { "id": 1, "is_marked": true } }
```

规则：

- `requireSuperAdmin`
- 用户不存在 → 404
- 用户已停用 → 400/409
- 老师调用 → 403

### 4.2 清除全部标记

```http
POST /api/admin/users/marks/clear
```

返回：

```json
{ "data": { "clearedCount": 3 } }
```

规则：

- `requireSuperAdmin`
- 只清 active 学员即可；停用学员理论上不应有标记。
- 不受班级筛选、搜索筛选影响。

### 4.3 双要求字段

```http
POST /api/admin/users/:userId/assignments
Content-Type: application/json

{
  "objects": [...],
  "practiceRequirement": "...",
  "submitRequirement": "..."
}
```

规则：

- 三栏至少一项非空。
- `practiceRequirement` / `submitRequirement` 各 ≤1000 字。
- 历史接口按 operation 返回两个字段，学员端同步。

## 5. 文案整改

| 场景 | 当前/问题 | 应改为 |
| --- | --- | --- |
| 布置输入框 | 作业备注 / 给学生的留言（选填） | 练习要求（选填） / 视频提交要求（选填） |
| 空推送校验 | 请选择要推送的内容或填写作业备注 | 请至少填写一项作业内容（视频作业、练习要求或提交要求） |
| 作业成功 | 作业已推送 | 作业已推送 |
| 学生标记 | 无 | 已标记「XX」/ 已取消标记「XX」 |
| 清除标记 | 无 | 已清除全部标记（N 位学生） |
| 停用老师 | 已基本正确 | 此账号已停用 / 请联系教导主任获取工作内容。停用期间无法查看学生记录与布置作业。 |
| 暂无带班 | 已基本正确 | 请联系教导主任获取工作内容 |

## 6. 验收清单

- [ ] 老师访问 `/admin/users` 只能看到本人班级学生；后端越权访问他班学生返回 403。
- [ ] 教导主任可自由筛选班级和学生。
- [ ] 教导主任可标记/取消标记学生，紫色实心圆点刷新后仍存在。
- [ ] 老师视角完全不渲染标记入口。
- [ ] 清除全部标记的数量正确，清除不受筛选影响。
- [ ] 停用学生不可标记，停用时清除既有标记，恢复后不还原。
